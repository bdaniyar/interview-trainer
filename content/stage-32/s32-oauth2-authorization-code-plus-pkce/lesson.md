## Теория

### Что это

Тема **OAuth2 Authorization Code + PKCE** описывает отдельный контракт backend-разработки.

### Как работает

Разложи механизм на вход, изменение состояния, наблюдаемый результат и специфичный для темы сценарий ошибки.

**verifier/challenge.** `verifier/challenge` защищается по реализованному flow: проблема, принятое решение, компромисс, режим отказа и test/metric.

**перехваченный код нельзя обменять без проверочного значения.** `intercepted code cannot be exchanged without verifier` защищается по реализованному flow: проблема, принятое решение, компромисс, режим отказа и test/metric.

**проверка параметра state и адреса перенаправления всё ещё обязательна.** `state/redirect validation still needed` защищается по реализованному flow: проблема, принятое решение, компромисс, режим отказа и test/metric.


### Важный нюанс / ограничение

Граница Junior: уверенно объясняй `verifier/challenge` и `intercepted code cannot be exchanged without verifier` на одном проверяемом примере; редкие внутренние детали сначала ищи в официальной документации.

### Где используется в backend

В backend эта тема важна в том месте, где применяется `verifier/challenge`; проверяй именно наблюдаемый contract, а не название инструмента.
