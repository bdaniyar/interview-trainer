# Tool calling и связь вызовов с результатами

У пользователя две задачи: проверить даты конкретной брони и увидеть число активных броней. Модель может запросить оба действия за один ответ. Даты остаются в базе приложения, поэтому для ответа понадобится промежуточный шаг.

## Учебные цели

- Проследить полный обмен между моделью и backend.
- Отличить ID элемента ответа от ID вызова функции.
- Собрать продолжение с несколькими результатами в произвольном порядке.

## Теория

**Tool calling** — протокол, по которому модель предлагает вызвать именованную функцию. Описание инструмента объясняет, когда он пригодится, а JSON Schema задаёт форму аргументов. Приложение отправляет модели определения инструментов. В ответ получает структурированное предложение: имя, аргументы и идентификатор вызова. Приложение разбирает предложение, применяет свою политику и вызывает обычную функцию. Результат возвращается модели, чтобы она могла ответить или предложить следующий шаг.

В Responses API элемент `function_call` имеет `id` элемента, например `fc_91`, и `call_id` вызова, например `call_x`. В `function_call_output` передают `call_x`. Идентификатор всего ответа, например `resp_73`, относится к продолжению на уровне API и не заменяет эти ID. Если клиент передаёт историю сам, он сохраняет исходные output items. Документация отдельно требует сохранить возвращённые reasoning items при передаче результатов поддерживающим их моделям. В примере такой элемент считается непрозрачным элементом протокола.

**Structured Outputs** ограничивает форму результата извлечения. Tool schema ограничивает форму предложения о действии. Правила доступа и исполнение принадлежат приложению в обоих случаях, а успешная проверка формы ничего не говорит о правах клиента. Для Claude Messages связывают `tool_use.id` с `tool_result.tool_use_id`. Для Gemini Interactions связывают ID шага с `function_result.call_id`. Эти поля принадлежат разным wire formats. Внутреннее приложение может использовать свой DTO с явным ID.

## Модель понимания

Пусть `list` завершился раньше `lookup`. Результат `list` нужно сопоставить по его call ID; перестановка по позиции отправит число броней в слот даты. Независимые чтения можно исполнить параллельно после проверки. Зависимые вызовы идут последовательно, если вход второго требует данных первого.

```text
Пользователь → API              Просит даты и список
API → модель                    История и две tool schemas
модель → API                    fc_91/call_x и fc_94/call_y
API → backend                   Проверить права и выполнить два чтения
backend → API                   call_y завершён, затем call_x
API → модель                    Исходные items и outputs по call_x/call_y
модель → API → пользователь     Текст по полученным результатам
```

## Что нужно знать на Junior

Отличай Unicode output от сырого DTO. Пустой, дублирующийся и неизвестный ID — ошибки протокола. Без результата для одного вызова безопаснее явно завершить обработку или вернуть предусмотренную ошибку с тем же ID, чем подставить ответ соседнего вызова.

## Примеры кода

```python
requested = ["trip-9", "trip-4"]
finished = [("trip-4", "лифт"), ("trip-9", "заезд в 18:00")]
outputs = dict(finished)
assert set(requested) == outputs.keys()
for key in requested:
    print(key, outputs[key])
```

Сначала выводится `trip-9 заезд в 18:00`, затем `trip-4 лифт`. В реальном адаптере до построения словаря проверяют дубли, иначе позднее значение может затереть раннее.

## Типичные ошибки

- Сопоставлять вызовы и ответы через `zip`.
- Возвращать ID элемента как `call_id`.
- Выкидывать промежуточные items при ручном продолжении.
- Исполнять произвольную строку вместо разрешённой функции.

## Вопросы с собеседований

1. Как связать ответы, пришедшие в разном порядке?
2. Что сохранить для ручного продолжения Responses?

## Хорошие ответы

**Как связать ответы, пришедшие в разном порядке?**

Связать по `call_id` и сверить множества ID. До построения словаря отклонить дубли, а после него проверить неизвестные и отсутствующие значения.

**Что сохранить для ручного продолжения Responses?**

Сохранить исходные output items с их полями, включая reasoning items, когда их вернула модель. Дополнить результаты отдельными `function_call_output` с идентификаторами первоначальных вызовов. В отдельном SDK-примере проверяется и исходный пользовательский вход следующего запроса.

## Критерии хорошего ответа

Укажи, какие поля принадлежат разным уровням протокола, и проведи два вызова с обратным порядком получения результатов.

## Задача

Реализуй `read_calls(output, allowed)` и `continuation(output, results, allowed)` из starter. `output` — список JSON-совместимых dict. Обрабатывай `function_call`: непустые строки `id`, `call_id` и разрешённое `name`, `arguments` разбирай из строки в JSON-объект. Повтор любого идентификатора среди calls, неизвестный tool и неправильная форма приводят к `ValueError`. Возвращай typed `ToolCall` в порядке предложений. `continuation` требует ровно один строковый `ToolResult.output` на вызов, независимо от порядка поступления, и добавляет `function_call_output` в порядке вызовов к независимой копии всех предыдущих items. Неизвестный, дублированный или отсутствующий результат даёт `ValueError`. Открытая fixture печатает два связанных результата. Check меняет IDs, функции, порядок, форму и обязательные поля; протокол не выполняет функции сам.

Пример входа в Run — два вызова `c-arrival` и `c-list`. Несмотря на обратный порядок ответов, первый добавленный output относится к `c-arrival` и содержит `2027-01-14`.

## Шпаргалка

### Краткий конспект

Tool schema задаёт форму предложения. Вызов идентифицирует `call_id`, а item ID нужен провайдеру. Клиент хранит исходные items и отправляет каждый результат с его call ID. Для независимых чтений порядок завершения может отличаться от порядка предложений. Сопоставление по позиции меняет смысл ответа и может ошибочно связать данные с другим действием.

1. Что делать с дублированным call ID?
2. Какая граница решает, может ли функция читать бронь?
3. Где именно различаются Responses и Claude Messages?

<details>
<summary>Сверить конспект</summary>

Остановить обмен как ошибку протокола. Решение о праве чтения принимает приложение. OpenAI использует `function_call_output.call_id`, Claude — `tool_result.tool_use_id`.
</details>
