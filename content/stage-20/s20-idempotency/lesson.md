# Idempotency

## Суть

Идемпотентный обработчик позволяет безопасно повторить один логический запрос. Повторная доставка сообщения и повтор HTTP после timeout должны ссылаться на тот же business operation, а не создавать новую работу.

## Учебные цели

Определить один логический запрос, сравнить его нормализованный payload и проверить конкурентный повтор через durable unique constraint. Различать fingerprint, ключ запроса и ключ внешнего события.

## Зачем это нужно backend-разработчику

Сравните payload {"a":1,"b":true} и тот же dict в другом порядке: hash должен совпасть. Измените true на 1 или порядок list: hash меняется. В реальном API одновременно отправьте два одинаковых ключа; проверьте один UUID и отдельный conflict при другом n.

## Теория

### Что это

Идемпотентный обработчик позволяет безопасно повторить один логический запрос. Повторная доставка сообщения и повтор HTTP после timeout должны ссылаться на тот же business operation, а не создавать новую работу.

### Как работает

API принимает Idempotency-Key, вычисляет hash нормализованного payload и пытается INSERT с unique key. Если другая транзакция уже сохранила тот же ключ, API читает существующую job: совпавший hash возвращает тот же результат, другой payload даёт conflict. Проверка SELECT перед INSERT без unique constraint проигрывает гонку.

Hash сравнивает смысл согласованного представления, но сам по себе не блокирует две записи. Нужны durable unique constraint и атомарная транзакция. В маленькой задаче ключи dict сортируются, пробелы убираются, Unicode кодируется UTF-8; порядок list остаётся важным, true отличается от 1. Это конкретная Python JSON-конвенция, а не универсальная межъязыковая canonical JSON спецификация.

Уникальный effect на job_id защищает локальный business effect, а inbox receiver защищает внешний повтор по event_id. У этих ключей разные области: ключ создания задания не обязательно совпадает с ключом каждой доставки его события. Продумайте срок хранения дедупликации; удаление ledger может разрешить старый дубль.

### Важный нюанс / ограничение

Повтор с тем же key и другим payload не должен молча вернуть успех первого действия. Fingerprint не хранит результат и не заменяет транзакционный unique constraint. Ключ нельзя генерировать заново при каждой retry.

## Модель понимания

## Что нужно знать на Junior

### Обязательно

Хеш вычисляется по согласованным bytes; порядок полей объекта можно нормализовать, порядок списка менять нельзя. Уникальность обеспечивается БД, а не самим хешем. Ledger должен храниться достаточно долго, чтобы старые повторы ещё распознавались.

## Примеры кода

```python
import hashlib

wire = b'{"action":"notify","order":42}'
digest = hashlib.sha256(wire).hexdigest()
assert len(digest) == 64
```

digest — str из 64 hex-символов. Здесь показан hash уже подготовленных bytes; нормализация вложенных объектов и проверки JSON-типа остаются самостоятельной задачей.

## Типичные ошибки

SELECT перед INSERT без unique constraint проигрывает двум одновременным запросам. Новый случайный ключ на каждом retry создаёт новую операцию. Сортировка списков меняет смысл payload. Удаление ledger без анализа срока повторов разрешает повторный эффект от старого сообщения.

## Задача

Реализуйте `fingerprint_request(payload: dict) -> str` в main.py через обычные Python Run/Check. Верните SHA-256 от UTF-8 JSON с sort_keys=True, separators=(",", ":"), ensure_ascii=False. Корень — dict, все ключи всех вложенных dict — строки; значения — JSON-типы, float только конечные. Неверный вход даёт ValueError. Порядок словаря не важен, порядок списка и различие true/1 важны. Не изменяйте payload. Это учебная Python-канонизация, не обещание межъязыкового универсального стандарта.

Например, используйте входы из практики выше; граничные и неверные входы также проверяются. Starter намеренно не содержит готового алгоритма.

## Шпаргалка

Operation key выбирается один раз. Hash связывает его с payload. Unique constraint разрешает конкурентный дубль; durable state позволяет вернуть прежний UUID или результат. Одинаковый ключ с другим содержимым требует конфликта. Idempotency действует в явно выбранной области и сроке хранения.
