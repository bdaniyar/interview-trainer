# `asyncio.gather`

## Учебные цели

Запустить независимые ожидания вместе, сохранить порядок результатов и объяснить поведение при ошибке.

## Теория

### Что это

`asyncio.gather(a, b)` объединяет несколько awaitable в одно ожидание результатов. Переданные coroutine автоматически планируются как задачи. Теперь, зная Task, можно явно начать независимые операции конкурентно.

### Зачем нужно

Чтобы показать карточку товара, можно независимо получить цену и остаток. Последовательное ожидание суммирует задержки; совместный запуск позволяет перекрыть их.

### Как работает

1. Вызовы функций создают coroutine objects.
2. gather планирует их и возвращает общий awaitable.
3. Каждая задача уступает управление во время I/O; остальные продолжают работу.
4. `await gather(...)` даёт список в порядке переданных аргументов, даже если завершались они иначе.

Для списка входов запись `*(fetch(x) for x in ids)` передаёт отдельный awaitable на каждый элемент. Звёздочка распаковывает элементы в аргументы вызова.

### Важный нюанс / ограничение

По умолчанию первая возникшая ошибка передаётся ожидающему коду, но gather не отменяет автоматически остальных участников. Они могут продолжать выполнение. При `return_exceptions=True` исключения становятся элементами списка и требуют явного разбора. Для группы, где ошибка должна отменять соседей, в Python 3.11+ есть TaskGroup; его не требуется применять в задании. Внешняя отмена самого gather передаёт отмену незавершённым участникам.

## Модель понимания

gather перекрывает независимые ожидания.

## Что нужно знать на Junior

### Обязательно

- gather перекрывает независимые ожидания.
- Результаты расположены в порядке входных аргументов.
- Обычная ошибка участника сама по себе не отменяет соседей.

## Примеры кода

```python
import asyncio

async def read(label, delay):
    await asyncio.sleep(delay)
    print("done", label)
    return label.upper()

async def main():
    result = await asyncio.gather(read("slow", 0.02), read("fast", 0))
    print(result)

asyncio.run(main())
```

### Разбор выполнения

Печатается done fast, затем done slow, затем ['SLOW', 'FAST']. Первый элемент результата соответствует первому аргументу, а не первому завершению. Задержки учебные; реальное время не используется как критерий корректности.

## Типичные ошибки

Неправильно сопоставлять результат с входом через порядок завершения, например считать первый результат ответом самого быстрого сервиса. Исправление: gather сохраняет порядок аргументов; если нужен порядок завершения, выбирают другой API. Другая ошибка — считать, что ошибка одного участника всегда остановила всех остальных.

### Вопрос 1

### Вопрос 2

Замени gather двумя последовательными await. Как изменятся порядок done и общая задержка?

<details><summary>Показать ответ</summary>

Для исходного порядка slow, fast сначала завершится slow, только затем начнётся fast. Задержки складываются вместо перекрытия; при нулевой задержке fast разница времени в данном примере мала.

</details>

### Вопрос 3

Один запрос упал. Можно ли уже делать вывод, что остальные прекратились?

<details><summary>Показать ответ</summary>

Нет. По умолчанию gather передаёт первую ошибку ожидающему коду, но не отменяет остальных участников автоматически. Их завершением нужно управлять явно.

</details>

## Вопросы с собеседований

### Основной вопрос

В каком порядке gather возвращает результаты и что делает при ошибке?

### Дополнительный вопрос

Чем gather отличается от двух последовательных await?

## Хорошие ответы

### Короткий ответ

Gather запускает переданные coroutine конкурентно и возвращает результаты в порядке аргументов.

### Нормальный ответ уровня Junior

Gather запускает переданные coroutine конкурентно и возвращает результаты в порядке аргументов. Порядок завершения может отличаться. По умолчанию первая ошибка передаётся ожидающему коду, а остальные участники автоматически не отменяются. Если выбрать return_exceptions=True, ошибки попадут в список как значения. Это нужно учитывать, когда несколько запросов составляют одну операцию.

### Углубление / дополнительный вопрос

При последовательных await второй вызов начинается только после первого результата. Gather планирует оба ожидания и позволяет перекрыть их задержки, если операции независимы.

## Критерии хорошего ответа

Обязательные понятия:

- gather перекрывает независимые ожидания.
- Результаты расположены в порядке входных аргументов.
- Обычная ошибка участника сама по себе не отменяет соседей.

Ошибочные утверждения кандидата:

- «Gather всегда возвращает результаты в порядке завершения.»
- «При первой ошибке gather автоматически отменяет все остальные задачи.»

Ошибки при написании кода разбираются отдельно в разделе «Типичные ошибки».

## Задача

### Получить несколько значений

Реализуй `async def fetch_many(fetch, ids)`: для каждого id вызови async-функцию fetch, запусти ожидания конкурентно и верни список результатов в порядке ids.

Пример: если fetch(x) возвращает x * 10, то `[3, 1, 2]` даёт `[30, 10, 20]`, независимо от порядка завершения. `[]` даёт `[]`; повторяющиеся id обрабатываются отдельно. Исключения не превращай в None и не подавляй. Отменять остальных участников при первой ошибке контракт не требует.

- Результаты расположены в порядке входных аргументов.
- Обычная ошибка участника сама по себе не отменяет соседей.
