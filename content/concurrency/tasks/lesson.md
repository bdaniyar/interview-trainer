# Tasks and `asyncio.create_task`

## Учебные цели

Запланировать coroutine как Task, сохранить ссылку и дождаться результата либо ошибки.

## Теория

### Что это

Task — объект asyncio, который управляет выполнением coroutine в event loop и хранит её результат, исключение или состояние отмены. `asyncio.create_task(coro)` планирует coroutine на выполнение и сразу возвращает Task.

### Зачем нужно

Можно начать независимую работу, выполнить следующий шаг текущей coroutine, затем дождаться начатой работы. Создание Task отличается от простого создания coroutine object из 8.2.

### Как работает

При стандартной фабрике Task создание не прерывает текущую строку кода: новая задача получит ход, когда loop снова сможет её запустить. `await task` ждёт завершения и возвращает результат. Повторно ждать уже завершённую Task допустимо, в отличие от повторного ожидания использованной coroutine.

Держи сильную ссылку на созданные задачи, например в set, пока работа нужна. `task.add_done_callback(callback)` вызывает callback с этой Task после её завершения. `registry.discard` подходит: удаляет элемент и не падает, если его уже нет.

### Важный нюанс / ограничение

Ссылка и callback не заменяют наблюдение результата. Исключение нужно получить через await или другую явную обработку. Task в памяти процесса не гарантирует выполнение после его перезапуска; важные фоновые задания требуют отдельной системы обработки.

## Модель понимания

Task планирует coroutine и хранит итог.

## Что нужно знать на Junior

### Обязательно

- Task планирует coroutine и хранит итог.
- Ссылки и await результата имеют разные назначения.
- Done callback получает завершённую Task.

## Примеры кода

```python
import asyncio

async def quote():
    print("quote started")
    await asyncio.sleep(0)
    return 120

async def main():
    task = asyncio.create_task(quote())
    print("scheduled")
    price = await task
    print(price)

asyncio.run(main())
```

### Разбор выполнения

При стандартной фабрике задач сначала scheduled. На await task main приостанавливается, quote печатает quote started и уступает на sleep(0). Затем quote возвращает 120; main получает его и печатает 120. Планирование не обещает выполнение на другом ядре.

## Типичные ошибки

Неправильно: вызвать create_task(save()) и забыть задачу. Ошибка save может остаться ненаблюдаемой, а завершение процесса оборвёт работу. Исправление: сохранить Task, дождаться её результата и определить, кто отвечает за ошибку и завершение.

## Практика

1. Пусть quote поднимает ValueError("no quote"). Где его получит main? Ответ: на await task.
2. Объясни, почему callback удаления из registry должен выполняться после завершения, а не сразу после create_task.
3. Если сохранение платежа обязано пережить restart, достаточно ли set с Task?

## Вопросы с собеседований

### Основной вопрос

Чем Task отличается от coroutine object?

### Дополнительный вопрос

Удаление Task из реестра обрабатывает её исключение?

## Хорошие ответы

### Короткий ответ

Coroutine object описывает ещё не выполненную или приостановленную работу.

### Нормальный ответ уровня Junior

Coroutine object описывает ещё не выполненную или приостановленную работу. Task планирует её выполнение в event loop и хранит итог. Create_task возвращает Task сразу, поэтому независимые операции могут продвигаться конкурентно. Нужно сохранять ссылки на задачи и получать результаты или ошибки через await. Это конкурентность в loop, а не отдельный поток для каждой coroutine.

### Углубление / дополнительный вопрос

Нет. Callback registry.discard управляет только ссылкой в set. За результат и исключение отвечает код, который ожидает Task или явно читает её итог.

## Критерии хорошего ответа

Обязательные понятия:

- Task планирует coroutine и хранит итог.
- Ссылки и await результата имеют разные назначения.
- Done callback получает завершённую Task.

Ошибочные утверждения кандидата:

- «Create_task создаёт отдельный OS-поток для coroutine.»

Ошибки при написании кода разбираются отдельно в разделе «Типичные ошибки».

## Задача

### Реестр запущенных задач

Реализуй обычную функцию `start_job(coro, registry)`. Она вызывается внутри работающего loop, создаёт Task из переданной coroutine, добавляет её в переданный set, регистрирует удаление завершённой Task из set и возвращает Task.

Пример: `task = start_job(asyncio.sleep(0, result=42), jobs)`; сразу `task in jobs` истинно, `await task` даёт 42. После обработки callback задача удалена из jobs. При ошибке coroutine ожидающий код получает исходное исключение; удаление из registry всё равно выполняется. Чужие элементы set сохраняются.
