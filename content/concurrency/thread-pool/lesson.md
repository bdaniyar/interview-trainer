# ThreadPoolExecutor

## Учебные цели

Ограничить число рабочих потоков и получить результат либо ошибку через Future.

## Теория

### Что это

ThreadPoolExecutor — пул переиспользуемых рабочих потоков. `submit(function, *args)` ставит синхронную работу в пул и возвращает Future — объект будущего результата.

### Зачем нужно

При работе с синхронным SDK не нужно создавать новый поток на каждый запрос. Пул с max_workers ограничивает количество одновременно выполняемых функций.

### Как работает

`future.result()` блокирует вызывающий поток до завершения и возвращает значение либо повторно поднимает исключение задачи. `executor.map` отдаёт результаты в порядке входа. Выход из with по умолчанию ждёт завершения запланированной работы и освобождает пул.

Заполни пул работой, затем собирай результаты. Если после каждого submit немедленно вызывать result до следующего submit, получится почти последовательное выполнение.

### Важный нюанс / ограничение

Max_workers ограничивает активные потоки, а не весь размер очереди задач. Не отправляй бесконечный поток работ в память без ограничений. `future.result(timeout=...)` ограничивает ожидание результата, но не останавливает уже работающую функцию. У синхронного сетевого клиента должны быть собственные таймауты. Не вызывай блокирующий result в потоке asyncio-loop: для такой интеграции используй изученный to_thread или подходящий executor API.

## Модель понимания

submit возвращает Future.

## Что нужно знать на Junior

### Обязательно

- submit возвращает Future.
- result блокирует вызывающий поток и передаёт ошибку.
- max_workers ограничивает активные вызовы, а не всю очередь.
- Ожидание результата не должно блокировать event loop.

## Примеры кода

```python
from concurrent.futures import ThreadPoolExecutor

def read_size(name):
    sizes = {"avatar": 120, "report": 450}
    return sizes[name]

with ThreadPoolExecutor(max_workers=2) as pool:
    pending = [pool.submit(read_size, name) for name in ("report", "avatar")]
    result = [future.result() for future in pending]
print(result)
```

### Разбор выполнения

Обе работы отправлены до ожидания результатов. Затем results собираются в порядке списка pending: [450, 120]. Порядок фактического выполнения может отличаться. Здесь словарь заменяет внешний I/O, чтобы пример был воспроизводим без сети.

## Типичные ошибки

Неправильно отправить задачу в единственный рабочий поток, а внутри неё ожидать другую задачу того же пула через result: второй работе может не достаться свободный поток, возникнет deadlock. Исправление: зависимости и сбор результатов организовать снаружи рабочих функций, либо пересмотреть разбиение работы.

## Практика

1. Замени "avatar" на "missing". Где возникнет KeyError? Ответ: при result соответствующего Future, а не обязательно в submit.
2. Почему max_workers=2 не ограничивает число элементов pending двумя?
3. Сравни два цикла: сначала все submit, потом все result; и submit/result в одной итерации. Где можно перекрыть I/O?

## Вопросы с собеседований

### Основной вопрос

Как ThreadPoolExecutor передаёт результат и исключение?

### Дополнительный вопрос

Останавливает ли timeout у Future.result рабочий поток?

## Хорошие ответы

### Короткий ответ

Submit ставит функцию в пул и возвращает Future.

### Нормальный ответ уровня Junior

Submit ставит функцию в пул и возвращает Future. Вызов result ждёт её завершения и возвращает значение, а при ошибке поднимает исходное исключение. Max_workers ограничивает активные рабочие потоки, но не все ожидающие задачи. Пул удобен для синхронного I/O; сетевые таймауты и размер очереди нужно контролировать отдельно. Выход из with освобождает пул после ожидания работы.

### Углубление / дополнительный вопрос

Нет. Он ограничивает ожидание вызывающего кода. Уже выполняющаяся функция продолжает работать, поэтому ей нужны собственные ограничения I/O и корректное завершение.

## Критерии хорошего ответа

Обязательные понятия:

- submit возвращает Future.
- result блокирует вызывающий поток и передаёт ошибку.
- max_workers ограничивает активные вызовы, а не всю очередь.
- Ожидание результата не должно блокировать event loop.

Ошибочные утверждения кандидата:

- «Timeout у Future.result принудительно останавливает работающую функцию.»

Ошибки при написании кода разбираются отдельно в разделе «Типичные ошибки».

### Проверить ошибку рабочего вызова

Создай пул с max_workers=2. Отправь два вызова функции `lookup(key)`, которая читает ключ из словаря `{"a": 10}`: один для "a", второй для "missing". Первый result должен дать 10, второй — KeyError. Обработай KeyError вокруг result, сохрани закрытие пула через with.

Дополнительный случай: передай пустой список ключей — получится пустой список результатов без вызовов lookup. Автоматической Monaco-задачи здесь нет.
