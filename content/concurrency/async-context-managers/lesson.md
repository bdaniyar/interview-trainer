# Async context managers

## Учебные цели

Применить async with и реализовать вход и выход асинхронного ресурса без подавления исключений.

## Теория

### Что это

Async context manager — объект, управляющий ресурсом через `async with`. Его методы `__aenter__` и `__aexit__` являются ожидаемыми: открытие или закрытие соединения может требовать I/O.

### Зачем нужно

HTTP-клиент, соединение или поток данных нужно закрыть и при успехе, и при ошибке внутри блока. Ручной close после последней строки легко пропустить при исключении.

### Как работает

`async with manager as resource` сначала ожидает `manager.__aenter__()` и связывает результат с resource. После тела, включая выход по исключению, ожидает `__aexit__(exc_type, exc, traceback)`. При успехе все три аргумента равны None; при ошибке содержат её описание. Истинное возвращаемое значение __aexit__ подавляет ошибку; False или None оставляют её распространяться.

Если сам __aenter__ не завершился успешно, __aexit__ автоматически не вызывается. Частично выделенные во время входа ресурсы нужно очищать в самом __aenter__.

### Важный нюанс / ограничение

Async with не делает произвольный ресурс потокобезопасным и не обеспечивает commit в БД, если менеджер этого явно не реализует. Гарантия выхода предполагает работающий процесс и кооперативное завершение; аварийное убийство процесса может прервать cleanup.

## Модель понимания

Вход и выход async with могут ожидать I/O.

## Что нужно знать на Junior

### Обязательно

- Вход и выход async with могут ожидать I/O.
- __aenter__ возвращает используемый ресурс.
- Истинный результат __aexit__ подавляет ошибку тела.
- Ошибка входа требует очистки на этапе входа.

## Примеры кода

```python
import asyncio
from contextlib import asynccontextmanager

@asynccontextmanager
async def channel(log):
    log.append("open")
    try:
        yield "connection"
    finally:
        log.append("close")

async def main():
    log = []
    try:
        async with channel(log) as connection:
            log.append(connection)
            raise ValueError("broken")
    except ValueError:
        log.append("handled")
    print(log)

asyncio.run(main())
```

### Разбор выполнения

asynccontextmanager превращает async-генератор с одним yield в менеджер. До yield происходит вход, значение yield попадает в connection. При ValueError finally добавляет close, затем ошибка попадает в except. Вывод: ['open', 'connection', 'close', 'handled']. Задание использует явные методы вместо декоратора.

## Типичные ошибки

Неправильно возвращать True из __aexit__ только потому, что close прошёл успешно. Это скрывает ошибку тела. Исправление: если подавление не входит в контракт, вернуть None или False после закрытия.

## Практика

### Вопрос 1

Удали raise из примера. Какие элементы останутся в log?

<details><summary>Показать ответ</summary>

В log останутся open, connection, close. Без ошибки обработчик except не добавит handled; выход из async with всё равно закроет ресурс.

</details>

### Вопрос 2

Что будет, если ошибка возникла до yield при открытии? Почему нельзя рассчитывать только на выход из контекста?

<details><summary>Показать ответ</summary>

Если открытие упало до yield, вход в контекст не завершился. Нельзя рассчитывать на обычный __aexit__: частично созданные ресурсы освобождает код открытия.

</details>

### Вопрос 3

Объясни различие между ресурсом, возвращённым __aenter__, и самим менеджером.

<details><summary>Показать ответ</summary>

Менеджер управляет входом и выходом, а возвращённое __aenter__ значение используется как ресурс после as. Это могут быть разные объекты; например, менеджер возвращает соединение или число 42.

</details>

## Вопросы с собеседований

### Основной вопрос

Как работает async with и когда он подавляет ошибку?

### Дополнительный вопрос

Вызовется ли __aexit__, если __aenter__ выбросил исключение?

## Хорошие ответы

### Короткий ответ

Async with ожидает вход через __aenter__ и использует возвращённый ресурс в теле.

### Нормальный ответ уровня Junior

Async with ожидает вход через __aenter__ и использует возвращённый ресурс в теле. После успешного входа он ожидает __aexit__ и при нормальном завершении, и при исключении тела. Если __aexit__ возвращает истинное значение, ошибка тела подавляется. Для обычного освобождения ресурса возвращают None или False. Ошибка самого входа требует собственной очистки частично созданных ресурсов.

### Углубление / дополнительный вопрос

Нет. Контекст ещё не был успешно открыт. Если вход успел выделить часть ресурсов, очисткой до повторного raise управляет сам __aenter__.

## Критерии хорошего ответа

Обязательные понятия:

- Вход и выход async with могут ожидать I/O.
- __aenter__ возвращает используемый ресурс.
- Истинный результат __aexit__ подавляет ошибку тела.
- Ошибка входа требует очистки на этапе входа.

Ошибочные утверждения кандидата:

- «True из __aexit__ просто сообщает, что ресурс успешно закрыт, и не влияет на исключение.»

Ошибки при написании кода разбираются отдельно в разделе «Типичные ошибки».

## Задача

### Менеджер ресурса

Допиши класс `AsyncResource(opener, closer)` в main.py. `opener` — async-функция без аргументов; результат сохрани в self.resource и верни из __aenter__. В __aexit__ дождись `closer(self.resource)`, не подавляй исключение тела.

Пример: opener возвращает 42; `async with AsyncResource(opener, closer) as value` получает 42, а после блока closer вызывается с 42. При ValueError внутри блока closer тоже вызывается, затем ValueError выходит наружу. Если opener упал, closer не вызывается. Ошибки opener/closer не подменяй.

## Шпаргалка

- __aenter__ возвращает используемый ресурс.
- Истинный результат __aexit__ подавляет ошибку тела.
- Ошибка входа требует очистки на этапе входа.
