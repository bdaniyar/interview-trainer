# Threading

## Учебные цели

Запустить и дождаться потока; защитить составное изменение общего состояния через Lock.

## Теория

### Что это

Thread — поток выполнения внутри процесса. Потоки имеют отдельные стеки вызовов, но видят общие объекты процесса. Поэтому они удобны для синхронного I/O, но совместная запись требует согласования.

### Зачем нужно

Два обработчика могут одновременно менять общий остаток или счётчик. Если каждый прочитал 10 и записал 11, один из двух инкрементов потерян: ожидается 12.

### Как работает

`Thread(target=fn)` создаёт объект потока. `start()` запускает функцию, `join()` ждёт её завершения. Порядок выполнения разных потоков заранее не задаётся.

Race condition — гонка: результат зависит от допустимого чередования шагов. Например: A читает 10; B читает 10; A пишет 11; B пишет 11. Lock — блокировка, которая разрешает одному потоку войти в защищённый участок. `with lock` получает блокировку, выполняет участок и освобождает её даже при исключении. Все участники должны использовать один и тот же lock для одного инварианта.

### Важный нюанс / ограничение

В обычной CPython 3.12 GIL допускает выполнение Python-кода одним потоком за раз, но не превращает составную бизнес-операцию в транзакцию. Во время I/O многие библиотеки освобождают GIL, поэтому потоки помогают перекрыть ожидания. Для чистых Python-вычислений ускорение по ядрам обычно требует процессов; некоторые C-расширения освобождают GIL. Не держи lock во время долгого сетевого запроса, если он не защищает необходимый инвариант.

## Модель понимания

Потоки разделяют память процесса.

## Что нужно знать на Junior

### Обязательно

- Потоки разделяют память процесса.
- Lock защищает весь составной инвариант.
- start запускает, join ожидает завершения.
- GIL не заменяет синхронизацию бизнес-операций.

## Примеры кода

```python
from threading import Lock, Thread

balances = {"total": 0}
lock = Lock()

def add_batch(amount):
    for _ in range(100):
        with lock:
            old = balances["total"]
            balances["total"] = old + amount

threads = [Thread(target=add_batch, args=(1,)), Thread(target=add_batch, args=(2,))]
for thread in threads:
    thread.start()
for thread in threads:
    thread.join()
print(balances["total"])
```

### Разбор выполнения

После обоих join все 200 обновлений закончены. Один поток прибавил 100, второй 200, поэтому результат 300 независимо от порядка входа в lock. Создание обоих объектов ещё не запускает функции; запуск делает start. Удаление lock может проявлять гонку по-разному: отсутствие сбоя в одном запуске не доказывает безопасность.

## Типичные ошибки

Неправильно создавать `Lock()` заново внутри каждого вызова, защищающего один счётчик: потоки получат разные замки. Исправление: один общий lock вокруг всего чтения и записи. Нельзя защищать только последнюю запись, оставляя чтение снаружи.

## Практика

1. Нарисуй гонку двух операций «прочитать 10, прибавить 1, записать» и сравни итог 11 с ожидаемым 12.
2. Измени amount второго потока на 3. Какой итог гарантирован после join? Ответ: 400.
3. Если вызвать start и сразу join для первого потока до запуска второго, будут ли их ожидания перекрываться?

## Вопросы с собеседований

### Основной вопрос

Защищает ли GIL общий счётчик от гонок?

### Дополнительный вопрос

Зачем нужен join и гарантирует ли он порядок работы потоков?

## Хорошие ответы

### Короткий ответ

GIL в обычной CPython ограничивает одновременное выполнение Python-кода, но не гарантирует атомарность составной операции.

### Нормальный ответ уровня Junior

GIL в обычной CPython ограничивает одновременное выполнение Python-кода, но не гарантирует атомарность составной операции. Два потока могут прочитать одно старое значение и перезаписать результат друг друга. Общий Lock должен защищать весь участок чтения, проверки и записи. Потоки полезны для I/O, где ожидания перекрываются, а чистые Python-вычисления обычно не ускоряются на нескольких ядрах.

### Углубление / дополнительный вопрос

Join ждёт завершения конкретного потока, чтобы вызывающий код не использовал незавершённый результат. Он не задаёт порядок шагов уже запущенных потоков и не защищает общую память.

## Критерии хорошего ответа

- start запускает, join ожидает завершения.

## Задача

### Разбор общего состояния

Письменно разложи операцию `if stock > 0: stock -= 1` для двух покупателей и начального stock=1. Покажи чередование, при котором оба проходят проверку. Укажи весь участок, который должен выполнять один владелец lock. Проверка только `stock -= 1` недостаточна: решение о продаже тоже относится к инварианту.

Ожидаемый результат исправленного сценария: ровно одна продажа, остаток 0. Для stock=0 обе продажи отклоняются. Monaco можно использовать как черновик; автоматической coding-задачи у этого урока нет.
