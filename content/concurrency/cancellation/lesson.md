# Cancellation

## Учебные цели

Запросить отмену Task, дождаться очистки и не скрыть постороннюю ошибку.

## Теория

### Что это

Cancellation — кооперативная отмена. `task.cancel()` просит Task завершиться: при следующей возможности в coroutine будет выброшен `asyncio.CancelledError`. Это запрос, а не подтверждение остановки.

### Зачем нужно

Если клиент отключился или результат больше не нужен, незавершённую работу полезно прекратить. При этом нужно освободить открытые ресурсы и не оставить задачу работающей незаметно.

### Как работает

1. Вызывающий код получает Task и вызывает cancel().
2. Ожидающая coroutine получает CancelledError, когда loop может доставить отмену.
3. Её finally освобождает ресурсы, затем исключение обычно распространяется дальше.
4. Вызывающий код делает await task и получает подтверждение завершения отменой.

Внутри самой рабочей coroutine допустимо перехватить CancelledError для очистки, но после этого обычно нужен `raise`. На границе управления задачей можно поймать именно это исключение и вернуть статус отмены.

### Важный нюанс / ограничение

CancelledError наследуется от BaseException, поэтому обычный `except Exception` его не ловит. Перехватывать BaseException ради подавления всех ошибок опасно. Если Task уже завершилась обычным результатом, cancel не изменит этот результат; если она упала с ValueError, await должен показать эту ошибку.

## Модель понимания

cancel запрашивает отмену, await наблюдает завершение.

## Что нужно знать на Junior

### Обязательно

- cancel запрашивает отмену, await наблюдает завершение.
- finally нужен для освобождения ресурса.
- CancelledError нельзя случайно превращать в успех.

## Примеры кода

```python
import asyncio

async def worker(started, log):
    try:
        started.set()
        await asyncio.Event().wait()
    finally:
        log.append("released")

async def main():
    started = asyncio.Event()
    log = []
    task = asyncio.create_task(worker(started, log))
    await started.wait()
    task.cancel()
    try:
        await task
    except asyncio.CancelledError:
        print("cancelled")
    print(log)

asyncio.run(main())
```

### Разбор выполнения

Event — сигнал между coroutine: set отмечает наступление события, wait ждёт его. Сигнал started гарантирует, что worker уже вошёл в try. После cancel выполняется finally и добавляется released. Затем main получает CancelledError и печатает cancelled, потом ['released']. Бесконечное ожидание Event прекращается отменой.

## Типичные ошибки

Неправильно: вызвать cancel и сразу считать ресурс закрытым. Исправление: await task, дождаться finally и обработать именно CancelledError. Внутри worker нельзя незаметно заменить отмену обычным return: вызывающий код тогда не увидит, что работа отменена.

## Вопросы с собеседований

### Основной вопрос

Почему после task.cancel() обычно нужно await task?

### Дополнительный вопрос

Почему except Exception не всегда перехватывает отмену?

## Хорошие ответы

### Короткий ответ

Cancel отправляет запрос отмены, но не означает, что задача уже остановилась.

### Нормальный ответ уровня Junior

Cancel отправляет запрос отмены, но не означает, что задача уже остановилась. CancelledError доставляется кооперативно, и coroutine должна успеть выполнить finally. Await task позволяет дождаться очистки и увидеть итог. На границе управления можно обработать CancelledError; внутри рабочей coroutine после очистки отмену обычно передают дальше через raise.

### Углубление / дополнительный вопрос

Asyncio.CancelledError наследуется от BaseException. Для отмены нужен явный обработчик; широкий перехват BaseException может скрыть также системные сигналы завершения.

## Критерии хорошего ответа

Обязательные понятия:

- cancel запрашивает отмену, await наблюдает завершение.
- finally нужен для освобождения ресурса.
- CancelledError нельзя случайно превращать в успех.

Ошибочные утверждения кандидата:

- «После task.cancel() задача уже точно завершила finally.»

Ошибки при написании кода разбираются отдельно в разделе «Типичные ошибки».

## Задача

### Отменить и дождаться

Реализуй `async def cancel_and_wait(task)`: запроси отмену, дождись Task и верни True, если ожидание закончилось CancelledError. Если Task завершилась обычным результатом, верни False. Другие исключения передай вызывающему коду.

Пример: запущенный worker, ожидающий Event, получает отмену и выполняет finally; функция возвращает True только после очистки. Уже успешно завершённая Task даёт False. Уже упавшая с ValueError Task передаёт ValueError. Функция вызывается управляющим кодом, который сам в этом упражнении не отменяется.

## Шпаргалка

- cancel запрашивает отмену, await наблюдает завершение.
- finally нужен для освобождения ресурса.
- CancelledError нельзя случайно превращать в успех.
