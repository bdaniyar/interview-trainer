# Async iterators and generators

## Учебные цели

Прочитать async-источник по одному значению, завершить его через StopAsyncIteration и объяснить очистку при раннем выходе.

## Теория

### Что это

Async iterator — источник, следующий элемент которого получается через await. `async for` ожидает элементы по одному. Это полезно для чтения страниц API или потока сообщений без загрузки всего ответа в память.

### Зачем нужно

Если данных много, удобно обработать очередную порцию, затем запросить следующую. Начать обработку можно до получения последней страницы; расход памяти зависит от размера порции.

### Как работает

`__aiter__()` — обычный метод, возвращающий async iterator. Его `async __anext__()` возвращает следующий элемент или поднимает `StopAsyncIteration`, когда данных больше нет. `async for` повторяет ожидание __anext__ и завершает цикл на этом исключении.

Async generator — функция async def с yield. Каждый yield передаёт одно значение читателю, а тело сохраняет позицию до следующего запроса. Внутри можно await загрузки следующей страницы. Наличие async for само по себе не запускает обработку элементов конкурентно.

### Важный нюанс / ограничение

Ранний break не означает немедленное гарантированное закрытие любого источника. Для async generator с ресурсами можно использовать `contextlib.aclosing`: он вызывает aclose на выходе, чтобы выполнить finally. Для других async-итераторов способ закрытия определяется их API.

## Модель понимания

async for ожидает очередной __anext__.

## Что нужно знать на Junior

### Обязательно

- async for ожидает очередной __anext__.
- StopAsyncIteration означает конец источника.
- yield сохраняет позицию async generator.
- Потоковое чтение и конкурентная обработка — разные решения.

## Примеры кода

```python
import asyncio
from contextlib import aclosing

async def pages(log):
    try:
        for number in (1, 2, 3):
            await asyncio.sleep(0)
            yield f"page-{number}"
    finally:
        log.append("closed")

async def main():
    log = []
    async with aclosing(pages(log)) as source:
        async for page in source:
            print(page)
            break
    print(log)

asyncio.run(main())
```

### Разбор выполнения

Запрашивается только первый элемент: после sleep(0) генератор выдаёт page-1. break прекращает чтение. На выходе aclosing закрывает генератор, finally записывает closed. Вывод: page-1, затем ['closed']. Страницы 2 и 3 не запрашивались.

## Типичные ошибки

Неправильно поднимать StopIteration из __anext__. Для async-протокола нужен StopAsyncIteration. Другой неверный подход — считать, что async for заранее запрашивает все страницы: без отдельного планирования чтение идёт последовательно.

## Практика

1. Убери break. Сколько страниц напечатается и сколько раз выполнится finally? Ответ: три страницы, один finally.
2. Для диапазона start=3, stop=3 сколько раз должно быть возвращено значение? Ответ: ни разу.
3. Почему список всех результатов может занять много памяти, даже если источник async?

## Вопросы с собеседований

### Основной вопрос

Для чего нужен async for и чем он отличается от обычного for?

### Дополнительный вопрос

Как закрыть async generator при break?

## Хорошие ответы

### Короткий ответ

Async for получает следующий элемент через ожидаемый __anext__, поэтому источник может ждать сеть между элементами.

### Нормальный ответ уровня Junior

Async for получает следующий элемент через ожидаемый __anext__, поэтому источник может ждать сеть между элементами. Обычный for использует синхронный next. Асинхронное завершение обозначается StopAsyncIteration. Async generator позволяет реализовать источник через async def и yield. Сам цикл остаётся последовательным, а закрытие ресурса при раннем выходе нужно организовать явно.

### Углубление / дополнительный вопрос

Можно окружить его contextlib.aclosing и async with. На выходе будет вызван aclose и выполнится finally генератора. Для другого типа источника нужно проверить его контракт закрытия.

## Критерии хорошего ответа

Обязательные понятия:

- async for ожидает очередной __anext__.
- StopAsyncIteration означает конец источника.
- yield сохраняет позицию async generator.
- Потоковое чтение и конкурентная обработка — разные решения.

Ошибочные утверждения кандидата:

- «Async for автоматически запускает все итерации конкурентно.»

Ошибки при написании кода разбираются отдельно в разделе «Типичные ошибки».

## Задача

### Асинхронный диапазон

Допиши `AsyncRange(start, stop)` с шагом 1 и исключённой верхней границей. __aiter__ возвращает self; __anext__ возвращает текущее целое, увеличивает позицию и поднимает StopAsyncIteration при достижении stop.

Пример: `[item async for item in AsyncRange(2, 5)]` даёт `[2, 3, 4]`. Для start >= stop результат пуст. Повторное чтение уже исчерпанного экземпляра остаётся пустым. Реальный I/O и искусственный sleep в этом упражнении не нужны: изучаем сам протокол.
