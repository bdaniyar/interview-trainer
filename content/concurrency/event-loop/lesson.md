# Event loop

## Учебные цели

Объяснить, кто продолжает coroutine после ожидания, и добавить явную уступку управления через sleep(0).

## Теория

### Что это

Event loop — цикл событий. В обычном asyncio-приложении он работает в одном потоке: запускает готовый шаг, принимает события готовности I/O, обрабатывает таймеры и возвращает ожидающие операции к выполнению.

### Зачем нужно

Один сервер обслуживает много соединений. Вместо потока на каждое ожидание loop следит за готовностью сокетов и запускает обработчики, когда есть что читать или писать.

### Как работает

1. `asyncio.run` запускает loop и главную coroutine.
2. Coroutine работает до приостановки на незавершённом awaitable или до конца тела.
3. Loop выполняет другую готовую работу. Таймер sleep делает продолжение готовым после задержки.
4. Когда ожидаемый результат доступен, coroutine продолжает с места await.

`asyncio.sleep(0)` — явная уступка управления без ожидания положительной длительности. Это полезная точка для учебного наблюдения, но не замена выносу тяжёлых вычислений.

### Важный нюанс / ограничение

Loop не прерывает произвольный Python-код посередине цикла. Долгий синхронный вызов удерживает поток и задерживает все остальные операции этого loop. В 8.9 разберём способы работы с такими библиотеками.

## Модель понимания

Loop продолжает готовые операции и обрабатывает таймеры.

## Что нужно знать на Junior

### Обязательно

- Loop продолжает готовые операции и обрабатывает таймеры.
- В одном потоке loop выполняется один шаг Python-кода за раз.
- Долгий синхронный шаг задерживает остальных участников loop.

## Примеры кода

```python
import asyncio

async def main():
    loop = asyncio.get_running_loop()
    loop.call_soon(print, "callback")
    print("before")
    await asyncio.sleep(0)
    print("after")

asyncio.run(main())
```

### Разбор выполнения

call_soon регистрирует обычную функцию для ближайшего прохода loop, не вызывает её прямо сейчас. Сначала before. sleep(0) приостанавливает main, loop запускает зарегистрированный callback. Затем main продолжает и печатает after. Итог: before, callback, after.

## Типичные ошибки

Неправильно ждать, что loop сам прервёт `while not ready: pass`. Этот цикл не уступает управление: событие от другой задачи того же loop может вообще не получить обработки. Исправление для реального ожидания — await события или I/O; для демонстрации уступки — sleep(0).

## Практика

1. Удали await sleep(0) из main. Где окажется callback относительно before и after? Ответ: после обеих строк.
2. Заменит ли sleep(0) ускорение расчёта большого отчёта? Объясни, кто выполняет расчёт.
3. Запиши, какие строки выполняются до и после уступки в checkpoint из задания.

## Вопросы с собеседований

### Основной вопрос

Почему один блокирующий вызов задерживает другие запросы в asyncio?

### Дополнительный вопрос

Что делает asyncio.sleep(0)?

## Хорошие ответы

### Короткий ответ

Event loop выполняет готовую работу в своём потоке.

### Нормальный ответ уровня Junior

Event loop выполняет готовую работу в своём потоке. Coroutine отдаёт ему управление при реальном ожидании, после чего он может обслужить другие соединения. Если синхронная функция долго не возвращает управление, loop не может запустить следующий шаг другой задачи. Поэтому блокирующая библиотека внутри async-функции способна задержать все запросы этого loop.

### Углубление / дополнительный вопрос

Он приостанавливает текущую задачу и позволяет loop выполнить другую готовую работу без положительной задержки. Это уступка управления, а не запуск отдельного потока.

## Критерии хорошего ответа

Обязательные понятия:

- Loop продолжает готовые операции и обрабатывает таймеры.
- В одном потоке loop выполняется один шаг Python-кода за раз.
- Долгий синхронный шаг задерживает остальных участников loop.

Ошибочные утверждения кандидата:

- «Event loop автоматически прерывает любой долгий Python-цикл.»

Ошибки при написании кода разбираются отдельно в разделе «Типичные ошибки».

## Задача

### Точка уступки

Реализуй `async def checkpoint(log)`. Добавь строку `"before"` в переданный список, выполни `await asyncio.sleep(0)`, затем добавь `"after"`. Возвращать значение не требуется.

Пример: после полного ожидания checkpoint([]) список содержит `["before", "after"]`. Для исходного `["existing"]` сохрани этот элемент перед новыми. При приостановке запись before уже видна другой работе в loop, а after ещё отсутствует.
