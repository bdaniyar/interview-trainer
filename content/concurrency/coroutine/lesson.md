# Coroutine function and coroutine object

## Учебные цели

Создать coroutine object, запустить его и получить результат через await; отличать объявление функции от выполнения её тела.

## Теория

### Что это

Coroutine function — функция, объявленная через `async def`. Её вызов создаёт coroutine object: объект с ещё не выполненной работой. Тело не начинает работать от одного вызова.

### Зачем нужно

Сетевую операцию удобно описать как последовательность шагов: запросить пользователя, дождаться ответа, прочитать поле. Пока ответ не готов, исполнение можно приостановить.

### Как работает

`await` внутри coroutine получает результат другой ожидаемой операции. `asyncio.run(main())` создаёт event loop — цикл событий — и выполняет главную coroutine до завершения. В обычном скрипте это вход в async-код; внутри уже работающего loop повторный `asyncio.run()` не нужен.

Возвращаемое через `return` значение становится результатом `await`. Если вложенная операция выбросит исключение, оно возникнет в месте ожидания. Словарь можно читать только после того, как получен результат, а не из самого coroutine object.

### Важный нюанс / ограничение

Слово `async` само по себе не запускает работу в фоне. Одну и ту же уже выполненную coroutine нельзя ожидать повторно: для нового вызова создают новый объект.

## Модель понимания

Вызов async def создаёт coroutine object.

## Что нужно знать на Junior

### Обязательно

- Вызов async def создаёт coroutine object.
- await получает возвращённое значение или исключение.
- asyncio.run запускает главную coroutine в обычном скрипте.

## Примеры кода

```python
import asyncio

async def greeting(name):
    print("inside")
    return f"Привет, {name}"

async def main():
    pending = greeting("Алия")
    print("created")
    text = await pending
    print(text)

asyncio.run(main())
```

### Разбор выполнения

Сначала created: создание pending не вошло в greeting. На await начинается тело, печатается inside. return передаёт строку в text; последняя строка вывода — Привет, Алия.

## Типичные ошибки

Неправильно: `name = client.get_user(7)["name"]`, если get_user объявлен через async def. Индексирование применяется к coroutine, а не к словарю. Исправление: сначала получить `user = await client.get_user(7)`, затем читать поля user.

## Практика

### Вопрос 1

В примере перенеси print("created") после await. Запиши новый порядок трёх строк.

Порядок: inside → created → Привет, Алия. Await выполняет greeting до получения результата, после чего main доходит до print("created") и печати text.

</details>

### Вопрос 2

Вместо return в greeting подними ValueError("bad name"). На какой строке main возникнет ошибка?

<details><summary>Показать ответ</summary>

ValueError возникнет в main на строке await pending. До await тело greeting ещё не выполнялось, поэтому создание pending само эту ошибку не вызывает.

</details>

### Вопрос 3

Почему два отдельных вызова greeting("Алия") создают разные объекты?

<details><summary>Показать ответ</summary>

Каждый вызов coroutine function создаёт новый coroutine object с отдельным состоянием выполнения. Это не повторное использование одного и того же объекта.

</details>

## Хорошие ответы

### Короткий ответ

Вызов async def создаёт coroutine object, но ещё не выполняет тело.

### Нормальный ответ уровня Junior

Вызов async def создаёт coroutine object, но ещё не выполняет тело. Чтобы получить результат, его нужно ожидать через await или запланировать на выполнение. В скрипте главную coroutine можно запустить через asyncio.run. return становится значением await, а исключение передаётся в точку ожидания. Один только вызов не означает фоновую работу.

### Углубление / дополнительный вопрос

До await у нас coroutine object. После await будет возвращённый словарь, и только тогда можно прочитать ключ name.

## Задача

### Получить имя пользователя

Реализуй `async def fetch_name(client, user_id)`. У client есть `async get_user(user_id)`, возвращающий словарь с ключом `name`. Дождись его и верни имя без преобразований.

Пример: ответ `{"id": 7, "name": "Aida"}` даёт `"Aida"`. Пустое имя `""` остаётся пустым. Если клиент выбросил `LookupError`, передай исключение вызывающему коду. `user_id` передаётся клиенту ровно как получен.
