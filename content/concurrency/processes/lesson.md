# Multiprocessing

## Учебные цели

Объяснить изоляцию памяти процессов, передачу сериализуемых данных и защиту точки входа.

## Теория

### Что это

Process — отдельный процесс ОС со своей памятью и интерпретатором. В обычной CPython каждый такой интерпретатор имеет собственный GIL, поэтому процессы могут одновременно считать чистый Python-код на разных ядрах.

### Зачем нужно

Большой расчёт не должен удерживать loop веб-сервера. Независимые части расчёта можно передать процессам, если выигрыш превышает цену запуска и обмена данными.

### Как работает

В примере ProcessPoolExecutor создаёт пул рабочих процессов. map отправляет функцию и входы, затем позволяет получить результаты в порядке входов. При передаче через пул аргументы, функция и результат должны поддерживать сериализацию: преобразование в передаваемое представление. Для обычного pickle надёжный вариант — функция верхнего уровня импортируемого модуля и простые данные.

На платформах со spawn рабочий процесс импортирует главный модуль. Поэтому создание пула помещают под `if __name__ == "__main__":`: импорт определит функции, но не создаст ещё один пул рекурсивно.

### Важный нюанс / ограничение

Глобальный список дочернего процесса не является общим списком родителя. Нужны явный возврат результата, очередь или специальные механизмы общей памяти. Открытое соединение БД, lambda и локальную функцию не стоит передавать как обычную задачу пула. Для маленького вычисления запуск процессов и копирование данных часто дороже самого расчёта.

## Модель понимания

У процессов отдельная память и интерпретатор.

## Что нужно знать на Junior

### Обязательно

- У процессов отдельная память и интерпретатор.
- Аргументы и результаты пула должны сериализоваться.
- Создание пула защищается условием __main__.
- Цена запуска и передачи данных может превысить выигрыш.

## Примеры кода

Сохрани пример как отдельный файл process_demo.py и запусти `python3 process_demo.py`; интерактивная консоль не всегда предоставляет импортируемый главный модуль.

```python
from concurrent.futures import ProcessPoolExecutor

def square(value):
    return value * value

def main():
    with ProcessPoolExecutor(max_workers=2) as pool:
        results = list(pool.map(square, [2, 3, 4]))
    print(results)

if __name__ == "__main__":
    main()
```

### Разбор выполнения

Рабочие процессы считают отдельные элементы. list потребляет результаты map, ожидая их готовности; порядок остаётся [4, 9, 16]. Выход из with закрывает пул и дожидается запланированной работы. Сам пример слишком мал для ускорения: он показывает передачу работы и результата, а не benchmark.

## Типичные ошибки

Неправильно изменить global results в дочерней функции и ждать изменения списка у родителя. Исправление: вернуть результат через API пула. Ещё одна ошибка — создавать пул на уровне модуля при spawn: импорт дочерним процессом снова запустит создание процессов.

## Практика

1. Почему square определена снаружи main? Объясни роль импорта и сериализации.
2. Что вернёт map для [0, -2]? Ответ: [0, 4].
3. Два процесса получают один обычный список аргументом и меняют его. Увидит ли родитель эти изменения как общую память? Ответ: нет, не через обычную передачу аргументов.

## Хорошие ответы

### Короткий ответ

Процессы подходят для независимых тяжёлых Python-вычислений, которые можно распределить по ядрам.

### Нормальный ответ уровня Junior

Процессы подходят для независимых тяжёлых Python-вычислений, которые можно распределить по ядрам. У каждого процесса отдельная память, поэтому аргументы и результаты приходится передавать, обычно через сериализацию. Это добавляет затраты запуска, памяти и копирования. Нужны импортируемые функции и защита точки входа при spawn. Для маленьких задач или передачи огромных объектов выигрыш может исчезнуть.

### Углубление / дополнительный вопрос

Процессы имеют отдельные адресные пространства. Обычная передача аргумента не создаёт общей памяти. Изменения нужно передать обратно через результат или подходящий IPC-механизм.
