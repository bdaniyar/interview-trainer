# `await` and cooperative scheduling

## Учебные цели

Проследить последовательные await и объяснить, почему они не создают конкурентный запуск.

## Теория

### Что это

Awaitable — объект, который разрешено ожидать через `await`. Coroutine — один из таких объектов. Встретив `await`, текущая coroutine передаёт управление ожидаемой операции и продолжает выполнение только после её результата.

### Зачем нужно

Чтобы отправить письмо пользователю, сначала требуется получить адрес. Два последовательных await прямо выражают эту зависимость.

### Как работает

В строках `a = await first()` и `b = await second()` вызов second ещё не произошёл, пока first не закончил работу. Если first ждёт I/O, loop может выполнять другую уже запланированную работу, но эти строки не создают её сами.

`await asyncio.sleep(delay)` моделирует ожидание: просит loop вернуться к coroutine после задержки. В отличие от обычного sleep это даёт loop возможность обслуживать другие операции. Если ожидаемый объект уже готов и не приостанавливается, await может закончиться сразу: каждый await не гарантирует переключение.

### Важный нюанс / ограничение

Нельзя писать `await 42` или ожидать обычный словарь. Await работает с протоколом ожидаемых объектов, а не с любым значением. Явный конкурентный запуск появится в уроках 8.5–8.6.

## Модель понимания

Последовательные await сохраняют зависимость шагов.

## Что нужно знать на Junior

### Обязательно

- Последовательные await сохраняют зависимость шагов.
- await разрешён только для awaitable.
- Готовый awaitable может не приостанавливать выполнение.

## Примеры кода

```python
import asyncio

async def read(label):
    print("start", label)
    await asyncio.sleep(0)
    print("end", label)
    return label.upper()

async def main():
    first = await read("a")
    second = await read("b")
    print(first + second)

asyncio.run(main())
```

### Разбор выполнения

Вывод: start a, end a, start b, end b, AB. Нулевая задержка уступает управление loop, но read("b") вызывается лишь после завершения read("a"). Наличие двух await не делает эти два чтения конкурентными.

## Типичные ошибки

Неправильное рассуждение: «В main два await, значит оба read уже ждут одновременно». Исправление: проследить место вызова каждой функции. Не начатую операцию loop не может продолжить.

## Практика

1. Если оба read ждут по одной секунде, сколько примерно займёт main? Ответ: две секунды плюс накладные расходы.
2. Первый read выбрасывает ValueError до return. Будет ли вызван read("b") без обработчика? Ответ: нет.
3. Предскажи вывод при удалении sleep из read. Изменится ли порядок строк?

## Вопросы с собеседований

### Основной вопрос

Два последовательных await запускают операции конкурентно?

### Дополнительный вопрос

Всегда ли await переключает выполнение на другую задачу?

## Хорошие ответы

### Короткий ответ

Нет.

### Нормальный ответ уровня Junior

Нет. Второй вызов происходит после того, как первый await вернул результат. Во время ожидания loop может выполнять другие уже запланированные задачи, но второй вызов из следующей строки ещё не начат. Await также может сразу получить готовый результат без переключения. Для независимого конкурентного запуска нужно явно запланировать работу, что делает Task.

### Углубление / дополнительный вопрос

Нет. Если ожидаемая операция завершается сразу, текущая coroutine может продолжить работу без приостановки. Поэтому await сам по себе не обеспечивает справедливое распределение CPU.

## Критерии хорошего ответа

Обязательные понятия:

- Последовательные await сохраняют зависимость шагов.
- await разрешён только для awaitable.
- Готовый awaitable может не приостанавливать выполнение.

Ошибочные утверждения кандидата:

- «Любые два await в функции всегда выполняются конкурентно.»

Ошибки при написании кода разбираются отдельно в разделе «Типичные ошибки».

## Задача

### Собрать профиль последовательно

Реализуй `async def load_profile(client, user_id)`: получи словарь через `await client.get_user(user_id)`, затем список ролей через `await client.get_roles(user_id)`. Верни новый словарь с данными пользователя и полем `roles`. Исходный словарь не меняй; его старое поле roles, если есть, заменяется.

Пример: `{"id": 4, "name": "Aida"}` и `["reader"]` дают `{"id": 4, "name": "Aida", "roles": ["reader"]}`. Пустой список ролей допустим. Ошибки клиента не подавляй.

Конкурентные решения прежней версии с той же сигнатурой остаются совместимыми; требовать gather на этом шаге не нужно.

- Готовый awaitable может не приостанавливать выполнение.
