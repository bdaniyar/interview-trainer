# Оценка retrieval и качества ответа RAG

Когда ассистент отвечает неверно, сначала проверь поиск. Затем выясни, что генератор сделал с найденным. Одна средняя оценка не позволяет разделить эти сбои.

## Учебные цели

- Посчитать precision, recall, MRR и отдельные answer metrics.
- Собрать воспроизводимое сравнение по языкам и split.

## Теория

Qrels — размеченные релевантные источники для каждого запроса. У релевантного источника отмечены ID и версия. После удаления повторов берём первые k рангов. Recall — hits/|relevant|. Здесь precision — hits/число реально возвращённых позиций, поэтому короткий список не заполняется пустыми позициями. Reciprocal rank — единица, делённая на позицию первого релевантного документа, или 0 при пропуске. MRR — среднее этих величин по определённым cases. При пустом qrels recall и reciprocal rank получают null. При пустой выборке precision получает null. Отчёт хранит знаменатели.

Оценка ответа учитывает корректность статуса, support каждого утверждения, наличие допустимых citations, abstention и conflict. Stale или forbidden выдача — отдельная ошибка независимо от среднего. Судья модели может предпочитать стиль, порядок или собственные ответы, поэтому нужна проверенная рубрика и ручная калибровка.

Dev используется для выбора конфигурации, holdout открывают после фиксации. Переводы и парафразы одного сценария держатся в одном split. В P5 по 10 вопросов ru, kk, en, из каждого языка 6 dev и 4 holdout. Правила до запуска зафиксированы независимо от ответов scripted generator.

## Модель понимания

При relevant={a,b} и rank [x,b,b,c] после dedup имеем [x,b,c]. При k=2 результат [x,b], recall=1/2, precision=1/2 и RR=1/2. Вредный ID вне top-k всё равно считается нарушением.

## Примеры кода

```python
ranked = list(dict.fromkeys(["noise", "b", "b", "x"]))[:2]
qrels = {"a", "b"}
first = next((i for i, key in enumerate(ranked, 1) if key in qrels), None)
hits = len(qrels.intersection(ranked))
print(hits / len(qrels), hits / len(ranked), 1 / first)
```

Вывод `0.5 0.5 0.5`. Место b равно 2, а повтор отсутствует в расчёте.

## Типичные ошибки

- Делить на k при другой публичной политике знаменателя.
- Переезжать на holdout для выбора настройки.
- Спрятать утечку доступа внутри итоговой средней.

## Вопросы с собеседований

1. Зачем хранить qrels отдельно от модели?
2. Почему два разных знаменателя?
3. Что делать при найденном источнике и неправильном ответе?

## Хорошие ответы

**Зачем хранить qrels отдельно от модели?**

Это заранее согласованная разметка цели. Генератор не получает её из eval.

**Почему два разных знаменателя?**

Recall сравнивает с релевантными, precision — с выданными. Для empty частей применяем документированную null policy.

**Что делать при найденном источнике и неправильном ответе?**

Разобрать generation, citation и поддержку claim отдельно. Ошибка поиска и ошибка ответа требуют разных действий.

## Критерии хорошего ответа

Назови инвариант, покажи конкретный вход, объясни наблюдаемый результат и случай, когда операция должна завершиться отказом.

## Задача

Реализуй `score_case(case,prediction,k)` и `summarize(rows)`. DTO в contracts.py. Строгий int k>0. Удали дубли до top-k, посчитай recall/precision/mrr по правилам выше. При наличии claims citation_valid требует непустые citations, все входят в retrieved top-k и relevant. claim_support — доля уникальных claims из supported_claims. Correct требует ожидаемый статус, при answered — точный набор claims и валидные ссылки, при других — отсутствие claims и citations. Отдельно abstention для expected=abstain. Forbidden — количество уникальных ID во всём ранжировании и ссылках вне allowed. bucket в порядке forbidden, ok, retrieval_miss при непустом relevant и нуле hits, иначе answer_error. summarize для каждой численной или bool метрики возвращает mean/n без None; при n=0 mean=None. Пример Run печатает три значения 0.5. Check сравнивает ошибки и знаменатели.
