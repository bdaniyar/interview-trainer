# RAG на Python: от поиска до ответа

Ассистенту не нужно запоминать расписание в весах модели. Backend может найти текущую выдержку и сформировать запрос с ней. Если доступной выдержки нет, система умеет остановиться.

## Учебные цели

- Развести стадии retrieval, context, generation и validation.
- Проверить реальное чтение, ограничение контекста и безопасный отказ.

## Теория

Retrieval-augmented generation подбирает источники на каждый запрос. Fine-tuning меняет параметры модели и сам по себе не поставляет текущую версию документа. У RAG тоже есть ошибки: источник может не быть найден, отрезок может не поместиться, генератор может добавить факт или вернуть битый контракт.

`question → embedding → authorized retrieval → ranking → context → generator → validation → answer`. Контекст состоит из policy приложения, вопроса и выбранных выдержек. Бюджет резервирует выход. В учебном коде считаем UTF-8 bytes, реально tokenizer может учитывать структуру и special tokens. Каждый evidence блок целостный. Модель видит документы как данные, включая возможную indirect prompt injection. Полномочия и право чтения принадлежат приложению.

## Модель понимания

Пусть описание из чужого tenant ближе всех к вопросу. Оно не должно пройти SQL ACL. После recheck видимый текст может исчезнуть из-за обновления; либо выбери законную выдержку, либо верни insufficient_evidence. Проверка citations смотрит, какие IDs действительно попали в context.

## Что нужно знать на Junior

Проверяй вызов retriever и содержимое context через spy. Совпавшая строка ответа не доказывает retrieval. Отдельные статусы позволяют увидеть, что именно исправлять.

## Примеры кода

```python
chunks = [("hours", "До 18:00"), ("extra", "ы" * 12), ("map", "Север")]
remaining = 29
for key, value in chunks:
    size = len(key.encode()) + len(value.encode())
    if size <= remaining:
        print(key, size)
        remaining -= size
```

Вывод — `hours 15` и `map 13`. У extra 29 байт, он уже не помещается после первого. Бюджет больше не распределяется по частям одной выдержки.

## Типичные ошибки

- Передать провайдеру весь корпус либо строку exception.
- Приравнять наличие ссылки к содержательной поддержке.
- Смешать policy приложения и инструкцию из документа.

## Вопросы с собеседований

1. Как отличить ложный retrieval от рабочего?
2. Прекращает ли RAG prompt injection?
3. Где проверять citations?

## Хорошие ответы

**Как отличить ложный retrieval от рабочего?**

Подменить репозиторий и проверить факт вызова, порядок и контекст. Сравни два разных набора документов.

**Прекращает ли RAG prompt injection?**

Найденный текст остаётся недоверенным. Серверные правила и ACL выполняются отдельно.

**Где проверять citations?**

После generation по IDs и версиям, которые реально были в context. Текущие права и support требуют отдельных проверок.

## Критерии хорошего ответа

Назови инвариант, покажи конкретный вход, объясни наблюдаемый результат и случай, когда операция должна завершиться отказом.

## Задача

Реализуй `rag(question,principal,retrieve,generate,limit=500,reserve=64)`. DTO в contracts.py. До retrieval проверь непустой текст, строгие положительные лимиты и бюджет UTF-8 для POLICY, вопроса и резерва. `retrieve(principal,question)` возвращает список Excerpt. Отфильтруй tenant и owner, сохрани порядок и один результат на ID. Блок стоит bytes(ID)+bytes(text)+len(str(version)); добавляй только целиком, допускается пропуск длинного. Без блока верни insufficient_evidence. `generate(Context)` даёт Draft версии draft-v1 с непустым текстом до reserve bytes и непустым кортежем уникальных supplied IDs. Типизированные статусы: invalid_input, context_budget, retrieval_error, insufficient_evidence, generation_error, invalid_answer, answered. Исключения скрывай. Пример Run возвращает hours. Check подменяет ответ, данные, scope и бюджет.

## Шпаргалка

### Краткий конспект

RAG вызывает retrieval перед генерацией и собирает целые разрешённые блоки. Бюджет 20 после обязательной части вмещает 11-байтовый b и пропускает 40-байтовый a. Нет evidence — осмысленный отказ. ID вне контекста отклоняется.
