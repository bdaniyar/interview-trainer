# Embedding pipeline и версии пространства

При индексации один HTTP-вызов часто получает сразу несколько текстов. Нужно сохранить успешные элементы и не перепутать их, даже если один текст завершился ошибкой.

## Учебные цели

- Зафиксировать embedding space по модели, ревизии, размерности и нормализации.
- Сопоставлять ответы batch по ID и переиспользовать только совместимый cache.

## Теория

Embedding — вектор, который обученная модель строит из входа. Близкие по смыслу тексты могут давать близкие векторы, если это свойство проверено для выбранной задачи. В задаче эмбеддер fake: координаты фиксированы для проверки приложения.

Batch — список входов одного запроса. Адаптер сверяет ID результатов с отправленными ID. Внешний API может использовать индекс входа, его тоже нужно провалидировать и связать с собственным ID. Проверка формы включает размерность, конечность, ненулевую норму и политику нормализации. Пропуск одного результата оставляет остальные пригодными. Дубликат одного ID неоднозначен даже при равных координатах.

Cache key включает embedding space и SHA-256 исходного UTF-8 текста. После замены модели старые и новые координаты живут отдельно. При миграции новый индекс заполняют, проверяют полноту и затем активируют. Провайдер вызывается вне DB-транзакции. Ограниченный retry применяют к временным отказам, с общим deadline, сохраняя успешные результаты.

## Модель понимания

Три текста отправлены как a,b,c. Пришли c,a. Сохрани успех c и a под их ID, b отметь missing. Повтор можно выполнить для b: на новом вызове cache вернёт валидные a и c.

## Что нужно знать на Junior

Заранее выбери единицу результата и формат ошибок. Timeout вызывающего кода и частичный ответ — разные события. Retry после неизвестного исхода может повторить расход средств.

## Примеры кода

```python
from hashlib import sha256

requested = {"a": "мәтін", "b": "рыба", "c": "document"}
returned = {"c": (1, 0), "a": (0, 1)}
for key, text in requested.items():
    print(key, key in returned, len(sha256(text.encode()).hexdigest()))
```

Вывод содержит a True 64, b False 64, c True 64. Порядок выдачи соответствует входу, а результат c выбирается по ключу.

## Типичные ошибки

- Использовать zip без проверки ID и пропусков.
- Хранить cache только по тексту и переиспользовать после смены модели.
- Повторять весь batch и перезаписывать уже принятые результаты.

2. Зачем хранить model revision в ключе?

## Хорошие ответы

**Как восстановить порядок batch?**

Хранить ответы по проверенному ID и обходить вход в исходном порядке. Пропуск сдвигает zip, но не map.

**Зачем хранить model revision в ключе?**

Одинаковые размеры не гарантируют совпадения координат. Новый индекс собирается отдельно.

**Что показывают фиксированные векторы?**

Они проверяют контракт приложения. Качество learned representation требует отдельной оценки.

## Критерии хорошего ответа

Разбери batch [a,b,c] с ответом [c,a]. Назови статус b, ключ cache и причину пересчёта при смене ревизии.

## Задача

Реализуй `embed(items, space, provider, cache)`. DTO в contracts.py. `items` — последовательность уникальных непустых ID с непустыми текстами. Ошибка входа или space даёт ValueError до вызова. Cache ключ (space, SHA-256 текста в UTF-8); записям с несовпадающими метаданными или неверным вектором не доверяй. Provider вызывается один раз для промахов, возвращает список или кортеж Embedding. Возврати кортеж Outcome в исходном порядке. Статусы cached/ok с вектором, duplicate для повторного ID, missing для отсутствия, invalid при невалидном векторе/space или чужом ID в пакете, provider_error при TimeoutError/ConnectionError. Строки без валидного ID не сопоставляй. Проверяй размер, тип, конечность, ненулевую норму и при normalized=True близость нормы к 1. Сохрани только успехи. Пример Run печатает missing, ok. Check меняет порядок, размеры, cache и эффект повторного запроса.

<details>
<summary>Ответы для самопроверки</summary>

**Как обработать timeout?**

Отметить провал текущих misses и повторить только разрешённые ошибки с бюджетом.

**Что делать с NaN?**

Отклонить вектор и не сохранять его.

**Чем content hash отличается от ID документа?**

Он меняется вместе с исходными байтами и переиспользуется для совпадающего текста.
