# Chunking и происхождение фрагмента

Длинный документ занимает много места в context. Его делят на фрагменты, чтобы найти нужное правило и показать, где оно сформулировано.

## Учебные цели

- Нарезать Unicode текст с heading и page metadata.
- Обеспечить воспроизводимые границы, покрытие и ссылку на версию документа.

## Теория

Chunk — фрагмент исходного текста. Overlap — повтор небольшого окончания предыдущего фрагмента в следующем. Он помогает сохранить условие на границе, но увеличивает объём индекса и создаёт похожие результаты. Срез строится в индексации Python str. Это полуоткрытые смещения `[start,end)` в Unicode code points, начиная с нуля. UTF-8 байты, графемы и токены другого формата могут иметь другие границы. Хеш текста считается по UTF-8.

Строка ATX heading (`#`–`######` и пробел) начинает новый section. Вымышленный маркер `<!-- page: N -->` меняет page, при этом section сохраняется. Маркеры включаются в срезы. Правила учебные и не реализуют полный Markdown parser. При поиске section помогает понять назначение совпавшего слова. Версия документа входит в ключ фрагмента: одинаковый абзац новой версии всё равно относится к новому состоянию.

## Модель понимания

Если первый срез [0,5), size=5 и overlap=2, следующий начинается с 3. Когда достигнут конец section, переходи к новому region без перекрытия. При overlap=size начало перестанет двигаться, поэтому условие запрещено.

## Что нужно знать на Junior

Храни исходную версию и границы рядом с embedding. Если меняешь способ нормализации текста, зафиксируй новую ревизию pipeline. Иначе отрезок текста и ссылка разойдутся.

## Примеры кода

```python
text = "Ауа таза😀"
size, overlap = 5, 2
for start in (0, size - overlap):
    value = text[start:start + size]
    print(start, len(value), len(value.encode()), repr(value))
```

Вывод — `0 5 9 'Ауа т'` и `3 5 9 ' таза'`. Один emoji занимает одну позицию Python и четыре UTF-8 байта. Полный алгоритм добавит ещё один срез до конца.

## Типичные ошибки

- Считать offset через len(encoded) и использовать его на Python str.
- Брать только hash текста как ID, скрывая смену версии.
- Терять пустые строки или делать overlap через границу page/section.

## Вопросы с собеседований

1. Как выбрать размер и overlap?
2. Зачем версия внутри chunk ID?
3. Почему offset нужно определить публично?

## Хорошие ответы

**Как выбрать размер и overlap?**

Сравнить retrieval на зафиксированных запросах. Overlap покрывает разорванный смысл ценой повторов и индекса.

**Зачем версия внутри chunk ID?**

Цитата должна указывать на конкретный источник. Тот же текст может встречаться в нескольких версиях.

**Почему offset нужно определить публично?**

Python, UTF-8 и интерфейс могут считать разные единицы. Читающий код должен получить тот же срез.

## Критерии хорошего ответа

Назови единицу смещений, выведи следующий start и объясни, почему совпавший hash текста не даёт права цитировать старую версию.

## Задача

Реализуй `chunk_text(document_id, version, text, size, overlap) -> tuple[Chunk,...]`. ID документа непустой, version от 1, строгие int size/overlap, `0 <= overlap < size`. Начальный page=1, section=None. На whole-line заголовке или маркере начни новую область. Повтори overlap только внутри области, сохраняя всё содержимое, включая маркеры и переводы строк. `digest=SHA-256(text.encode())` в hex; chunk_id — детерминированный идентификатор с документом, версией, границами и digest. Ошибки входа дают ValueError. Пустой текст возвращает пустой кортеж. Пример Run печатает три среза для заголовка Ауа. Check сверяет покрытие каждого символа, Unicode и смену версии.
