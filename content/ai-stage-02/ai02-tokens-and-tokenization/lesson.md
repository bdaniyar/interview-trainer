# Токены и токенизация

В логе один запрос состоит из 300 символов русского текста и кода. Сеть передала байты, но лимит модели измеряется токенами. Чтобы решить, поместится ли запрос, нужно понять, какие единицы считает выбранная модель.

## Учебные цели

- Объяснить различие символа, UTF-8 байта, слова и токена.
- Выполнить encode → IDs → decode на двух версиях.
- Учесть служебные токены в учебном бюджете.

## Теория

**Токен** — единица, которую токенизатор выделяет для модели. Это может быть слово, пробел с частью слова, число, знак кода или последовательность байтов. **Vocabulary**, словарь, связывает единицу с числовым ID. Модель получает последовательность ID. **Encoding** строит эту последовательность из строки, **decoding** преобразует ID обратно в текст. Токенизация модели может нормализовать строку и иметь правила, при которых исходное представление не полностью восстанавливается.

**Subword** — часть слова, встречающаяся в разных словах. Так один словарь может хранить частые корни и окончания, не перечисляя все возможные слова. Модель учат с конкретной схемой ID. Число 57 само по себе не говорит, какая строка ему соответствует. У модели со словарём B этот же ID может означать что-то другое.

В HTTP-запросе кроме текста есть границы сообщений и сведения об инструментах. API может считать их согласно своему формату. В упражнении один токен начала и один токен конца имитируют накладные расходы. Реальный состав запроса зависит от API и модели. Для биллинга используй возвращённый usage, когда он доступен. У правила «четыре символа на токен» нет универсальной применимости.

## Модель понимания

Для Python-разработчика словарь похож на протокол с версией. Подменить словарь после выдачи ID — как применить неверную схему декодирования сообщения. Обсуди, что должно входить в ключ кэша estimate: текст, формат сообщений и идентификатор токенизатора. Иначе одна и та же строка принесёт неправильное число после смены модели.

## Что нужно знать на Junior

Нельзя точно ответить «сколько здесь токенов», если неизвестна модель, её словарь и форма запроса. Для теста можно взять фиксированную версию и синтетические ожидаемые ID. При переходе на провайдера сначала проверь совместимый счётчик, затем сравни оценку с возвращённым usage.

## Примеры кода

Код сравнивает символы и байты с вручную заданным результатом местного словаря для трёх разных строк.
```python
samples = {"я": [7], "я!": [7, 8], "def f": [15, 20]}
for text, ids in samples.items():
    print(len(text), len(text.encode("utf-8")), len(ids))
assert len("я!".encode("utf-8")) == 3
assert len(samples["def f"]) == 2 < len("def f")
assert len("".encode()) == 0
```
Строки вывода — `1 2 1`, `2 3 2`, `5 5 2`. Первая колонка считает Unicode-кодовые точки, вторая — байты UTF-8, третья — учебные ID. Кодовые точки в Python не обязательно совпадают с видимыми символами, например у букв с составным акцентом. Набор ID придуман для сравнения единиц.

## Хорошие ответы

ID определён словарём и его версией. Жадные, подсловные и байтовые разбиения дают иные длины. Вход включает сообщения и метаданные по схеме API. Точное число требует сведений о токенизаторе и оболочке.

## Критерии хорошего ответа

Укажи разницу между байтом, кодовой точкой и ID на русском примере. Объясни, почему менять словарь без проверки нельзя и откуда брать итоговый расход.

## Задача

Напиши `encode(text, version, framed=False)`, `decode(ids, version)` и `fits_budget(text, version, maximum)`. В `fixtures.py` зафиксированы два разных словаря подстрок. Выбирай самое длинное совпадение с текущей позиции. При отсутствии ключа закодируй одну Unicode-точку как `FALLBACK + ord(character)`. Рамка при `framed=True` добавляет ID `0` и `1`; decode принимает либо оба на краях, либо ни одного. Отклони неизвестную версию, несогласованную рамку и неизвестный ID. Допустим пустой неформатированный текст. `fits_budget` включает рамку и отклоняет отрицательный лимит.

Например, `encode("привет!", "A", True)` даёт `[0, 2, 3, 1]`. Проверь также строку с emoji и кодом, две версии и точную границу. Сопоставь учебный механизм с реальным токенизатором из источника. В упражнении нормализация и BPE-модель не используются.
