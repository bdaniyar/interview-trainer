# Предобучение LLM и настройка поведения

Модель уверенно завершает строку «Выезд оплачивается…». Откуда берётся такое поведение и что изменится, если мы дадим ей новый документ, инструкцию или обучающий пример?

## Учебные цели

- Связать обучение продолжению с отрицательным логарифмом вероятности.
- Вычислить target shift и среднее с маской.
- Различить четыре вида изменений системы.

## Теория

**Pretraining** подбирает параметры модели на большом корпусе. У decoder-only модели одна учебная цель — предсказать следующий токен по предыдущим. Если токены [BOS, «я», «еду»], распределение на позиции BOS оценивает «я», а распределение после «я» — «еду». BOS обозначает начало. Это сдвиг целей, target shift. Последняя входная позиция без известного следующего токена не даёт собственного loss. При обучении фактический предыдущий токен обычно известен, при генерации его выбирает сама модель.

Для цели tᵢ берём pᵢ — вероятность именно этой цели среди всех возможных токенов. Отрицательный логарифм, **NLL**, равен −ln(pᵢ). Он растёт при уменьшении pᵢ. Для one-hot разметки, где у правильного токена вес 1, это частный случай кросс-энтропии −Σⱼ yⱼ ln(pⱼ). Среднее делит сумму только на число включённых позиций. Например, для p=0.5 и 0.25 получаем (ln2 + ln4)/2 ≈ 1.04. При p=0 учебное соглашение даёт бесконечный loss. При расчёте на логитах обычно используют устойчивую форму log-softmax.

**Supervised fine-tuning (SFT)** продолжает обучение на выбранных примерах вход → желательное продолжение. **Preference-based post-training** использует предпочтения между результатами либо оценки, чтобы менять поведение. **Alignment** — работа по согласованию поведения с критериями людей и приложения. Конкретные закрытые корпуса и рецепты нельзя выводить из того, что умеет продукт. Типовая последовательность показывает идеи, не полный рецепт любого провайдера.

У **inference** веса фиксированы. Запрос с инструкцией меняет контекст, но не веса. **Retrieval** ищет документы, а RAG добавляет найденные отрывки в контекст генерации. Обновление индекса влияет на то, какие отрывки будут найдены. Проверка доступа или расчёт возврата отдельной функцией меняют код приложения. Fine-tuning меняет веса и требует отдельной оценки, поэтому новая политика бронирования не обязана ждать обучения.

## Модель понимания

Запиши таблицу «артефакт → что меняется». Градиент меняет параметры. Prompt меняет только вход. Загрузка документа меняет индекс поиска, а его найденный фрагмент меняет конкретный вход. SQL ownership check меняет прикладную политику.

## Что нужно знать на Junior

Сохраняй версию модели, промпта и retrieval snapshot. При разборе неожиданного ответа это независимые причины. Низкий next-token loss не заменяет проверку фактов и доступа.

## Примеры кода

```python
from math import log, isclose
tokens = ["<s>", "бронь", "готова"]
rows = [{"бронь": .8, "готова": .2}, {"бронь": .4, "готова": .6}]
picked = [row[t] for row,t in zip(rows,tokens[1:],strict=True)]
assert picked == [.8,.6]
assert isclose(sum(-log(p) for p in picked)/2, -log(.48)/2)
assert -log(rows[1]["готова"]) < -log(rows[1]["бронь"])
print(round(-log(.48)/2, 3))
```

Вывод `0.367`. Массив входных строк короче списка токенов на одну позицию. Сам текст не делится на токены в упражнении.

## Типичные ошибки

- Сравнивать распределение с текущей позицией.
- Оставлять маскированный токен в знаменателе.
- Заявлять, что новый prompt обновил веса.
- Объявлять alignment полной гарантией поведения.

## Практика

Сопоставь четыре изменения с артефактами. Добавь в инструкции фразу «обращайся по имени», обнови каталог документов, дообучи веса на примерах и проверь owner до вызова. Для каждого объясни, какой файл или сервис изменился.

## Вопросы с собеседований

1. Как устроен target shift?
2. Чем SFT отличается от retrieval?

## Хорошие ответы

**Как устроен target shift?**

Строку i сопоставляем токену i+1. Mask исключает отдельные target позиции. У среднего нет знаменателя. Контракт вернёт None.

**Чем SFT отличается от retrieval?**

Retrieval читает индекс и формирует данные для конкретного inference. Обычно индекс, если нужна актуальная ссылка; проверить качество отдельно.

## Критерии хорошего ответа

Покажи пару входа и цели, знаменатель и случай нулевой вероятности. Для каждого изменения системы назови артефакт и его жизненный цикл.

## Задача

Реализуй `sequence_nll(tokens, distributions, masked=())`. Строка i оценивает `tokens[i+1]`; masked содержит индексы целей в tokens, начиная с 1. Каждая немаскированная строка задаёт словарь вероятностей в [0,1] с суммой около 1 (абсолютный допуск 1e−9). Неизвестная цель означает p=0 и loss=inf; проверь все немаскированные строки, даже если раньше встретился ноль. Верни None при отсутствии оцениваемых позиций. Ошибки формы, индекса и вероятности дают ValueError. Например, для [BOS,A,B] и вероятностей истинных целей 0.8 и 0.25 при masked=[1] loss=−ln(0.25). Check оценивает только расчёт. Четыре изменения выше объясни своими словами.
