# Embeddings, длина и смысловая близость

Запрос «вернуть оплату» и статья «как получить деньги обратно» могут быть связаны, хотя слова разные. Сравним две стратегии поиска на таком примере и выясним, что измеряет числовое расстояние.

## Учебные цели

- Отличить token embedding от вектора всего текста.
- Рассчитать cosine и нормализацию.
- Проверить модель и размер векторов перед поиском.

## Теория

**Embedding** — вектор, полученный обучаемым преобразованием. Его координаты полезны вместе. У token embedding внутри LLM одна строка соответствует ID, затем соседние слои добавляют зависимость от контекста. Text embedding строится для строки или документа и обычно возвращает один вектор фиксированной размерности. Отдельная координата редко позволяет назвать однозначное понятие. Модель и версия определяют пространство. Одинаковая длина двух векторов ещё не делает их совместимыми.

Cosine similarity — x·y/(||x||₂ ||y||₂), где числитель — скалярное произведение, знаменатель — произведение длин. Можно сначала **нормализовать**, разделив каждый вектор на его длину. Тогда cosine равен dot единичных векторов. Для x=[3,4,0], y=[0,2,0], dot=8, длины 5 и 2, cosine=0.8. x и 2x дают cosine 1, противоположные направления −1, перпендикулярные 0. У zero vector направление не определено, его отклоняем.

**Лексическое сходство** сравнивает слова или подстроки. Оно помогает искать точный номер, но может пропустить перефразирование. **Семантическое сходство** измеряет близость представлений модели. Способность находить связанные значения проверяется размеченными случаями в конкретном домене. Похожий текст может утверждать противоположное, ошибаться или принадлежать другому пользователю. Сходство не доказывает факт и не даёт права читать документ.

В упражнении векторы заданы вручную, поэтому отражают только придуманный пример. Мы проверяем арифметику и метаданные, не качество обученной модели. При смене версии пространства обычно нужно пересчитать индекс тем же encoder и проверить качество на независимой выборке.

## Модель понимания

Явный ключ сравнения — model ID с ревизией и размерностью. Пересечение типов как при работе с разными системами координат отклоняем до dot. При равных оценках ранжируй стабильно по ID.

## Что нужно знать на Junior

Зафиксируй baseline и размеченные случаи. Например, Jaccard для слов — размер пересечения / размер объединения. Отдельно проверь точные коды, перефразы и смысловые противоречия.

## Примеры кода

```python
from math import hypot, isclose
query=(3,4,0)
target=(0,2,0)
dot=sum(a*b for a,b in zip(query,target,strict=True))
score=dot/(hypot(*query)*hypot(*target))
assert isclose(score, .8)
assert hypot(0,0,0)==0
assert not (set("вернуть оплату".split()) & set("деньги обратно".split()))
print(score)
```

Вывод `0.8`; лексическое пересечение при этом пустое. Связь условна, векторы заданы вручную.

## Типичные ошибки

- Сравнивать разные версии модели при равных размерах.
- Делить на ноль у пустого направления.
- Считать высокий cosine доказательством утверждения.
- Мерить только один удачный перефраз.

## Вопросы с собеседований

1. Почему нужны одинаковые model ID?
2. Чем cosine отличается от длины?

## Хорошие ответы

**Почему нужны одинаковые model ID?**

Номер оси и масштаб имеют смысл внутри выбранной модели и версии. Нет. Возможны разные оси той же длины.

**Чем cosine отличается от длины?**

Нормализация убирает масштаб; zero vector не задаёт направления. Она теряет информацию о длине, если длина сама была полезной для задачи.

## Критерии хорошего ответа

Нормализуй два вектора и объясни совместимость. Сравни лексический и численный порядок и отметь одно ложное совпадение.

## Задача

Реализуй `normalize(embedding)`, `cosine(left,right)` и `rank(query,documents)`. `Embedding(model,dimensions,values)` задан в fixtures. normalize возвращает кортеж чисел единичной длины, отбрасывает ноль, несовпадение заявленного размера, bool, нечисловые и не конечные значения. cosine требует одинаковый model и dimensions, иначе ValueError. rank принимает словарь ID→Embedding и возвращает список (ID,score) по убыванию score, затем по ID. Например, [1,0] против [−2,0] даёт −1. В Run сравни результаты с Jaccard для фразы без общих слов. В Check другие модели, размеры, границы и равные оценки.
