# Sampling и ограничения LLM

Чат сгенерировал уверенное письмо о возврате. Текст гладкий, но сумма не совпадает с бронью. Чтобы объяснить такую ошибку, полезно проследить, как модель выбирает следующее продолжение и что означает её вероятность.

## Учебные цели

- Вычислить распределение из logits и понять эффект temperature.
- Отобрать кандидатов top-p и сделать воспроизводимый локальный выбор.
- Различить вероятность токена, калибровку и достоверность.

## Теория

На каждом шаге языковая модель выдаёт по одному числу **logit** для каждого кандидата продолжения. Вектор из трёх чисел в примере относится к трём возможным очередным токенам. Более высокий logit даёт больший вес. **Softmax** преобразует веса в вероятности. Для позиции `i` берём `exp((z_i - m) / T)`, где `z_i` — её logit, `m` — максимальный logit, `T > 0` — температура. Делим каждый вес на сумму всех весов. Вычитание общего максимума сохраняет отношения и защищает от переполнения экспоненты. Сумма вероятностей близка к 1 с погрешностью чисел с плавающей запятой.

При большей `T` отношения весов становятся ближе к 1 и распределение выравнивается. **Greedy** всегда выбирает максимальный logit. В нашем контракте это отдельное поведение при `T=0`. **Top-p**, или nucleus sampling, сортирует вероятности, берёт минимальный префикс, накопивший хотя бы `p`, и нормализует его. Если вероятность лучшего кандидата 0,55, а второго 0,30, то при `p=0,8` нужны оба. Их новые вероятности — 0,55 / 0,85 и 0,30 / 0,85. Следующий выбор зависит от случайного числа.

Вероятность токена означает пригодность продолжения в модели, а не доказанность факта. **Hallucination** — правдоподобное, но неподтверждённое или ошибочное содержание. **Calibration** описывает, как оценка вероятности согласуется с наблюдаемой долей верных на группе случаев. Формулировка «я уверен» сама не создаёт калиброванной оценки. Смена модели, программного окружения, инструкций или обработки равенства может изменить результат. Даже если провайдер поддерживает настройку `temperature=0`, это само по себе не гарантирует универсальную воспроизводимость.

## Модель понимания

В backend можно доказать, что место в брони действительно свободно, прочитав согласованное состояние. Для текста модели проверь факты отдельно. Введи outcome: доставленный готовый текст, отказ, неполный результат или ошибка транспорта. Успешный HTTP и красивый текст не взаимозаменяемы с предметной корректностью.

## Что нужно знать на Junior

Фиксированный seed воспроизводит наш алгоритм на одинаковых параметрах и окружении. При оценке внешнего API явно сохраняй вход, модель, настройки и измеряй разброс на нескольких проверенных случаях. Поведение может зависеть от бюджета вывода и stop-условий — границ окончания генерации, а не только от temperature и top-p.

## Примеры кода

Вес 1 означает `exp(0)`. Разность двух logits равна `log(3)`, значит отношение весов при T=1 составит 3 к 1.
```python
from math import exp, log, isclose

gap = log(3)
def probability_of_best(temperature):
    small = exp(-gap / temperature)
    return 1 / (1 + small)

assert isclose(probability_of_best(1), 0.75)
assert isclose(probability_of_best(0.5), 0.90)
assert 0.5 < probability_of_best(100) < 0.51
print(round(probability_of_best(1), 2), round(probability_of_best(0.5), 2))
```
Вывод — `0.75 0.9`. При уменьшении температуры разность делится на 0,5 и вес меньшего кандидата становится 1/9. Пример описывает один шаг с двумя токенами. Вероятность ответа из нескольких токенов зависит от предыдущих выборов.

## Типичные ошибки

- Выбирать top-p до нормализации или исключать пересекающий порог токен.
- Вычислять exp для большого logit без вычитания максимума.
- Объявлять seed универсальным ключом повторения API.
- Принимать вероятный токен за доказанный факт.

## Хорошие ответы

Temperature влияет на выбор продолжения, а не на источник фактов. Top-p выбирает кандидатов по накопленной вероятности, число элементов зависит от входа. Калибровка сравнивает заявленные вероятности с наблюдаемой долей исходов.

## Критерии хорошего ответа

Вычисли веса с простыми числами, назови роль нормализации и отдели refusal от сетевой ошибки. Скажи, какую проверку корректности вынесешь за пределы модели.

## Задача

Реализуй `candidates(logits, temperature, top_p)` → список пар `(исходный_индекс, вероятность)` по убыванию, при равенстве — по исходному индексу. Для положительной температуры бери стабильный softmax, затем минимальный префикс, пересекающий порог или равный ему с погрешностью `1e-12`. При top_p=1 сохрани все элементы. Перенормируй. При T=0 верни единственного лучшего с весом 1. Вход непустой и конечный; отклони отрицательную или нечисловую температуру, бесконечность, NaN и top-p вне `(0, 1]`.

`sample(logits, temperature, top_p, rng)` использует `rng.random()` один раз при ненулевой температуре. Выбери первый накопленный вес строго больше значения из `[0, 1)`. При T=0 RNG не нужен. Например, для одинаковых logits, `p=1`, значения 0,49 и 0,50 выбирают индексы 0 и 1. Для авторской сверки есть точный порог, экстремальные числа и повторение с одним seed.
