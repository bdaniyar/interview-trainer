# Контекстное окно и бюджет токенов

После двадцатого сообщения запрос перестал помещаться, хотя новый вопрос состоит из одной строки. В серверном payload ещё есть история, документы и инструкция. Для ответа тоже нужно место.

## Учебные цели

- Разложить лимит по частям запроса.
- Выбрать историю, сохранив обязательную политику и пары событий.
- Отделить размер запроса от контроля прав и качества ответа.

## Теория

**Context window** — объём контекста, с которым модель может работать за один вызов. В модели учебного расчёта окно `W` включает вход и место для выхода. Из `W` вычитаем `R`, резерв токенов ответа, и `M`, запас на неточность оценки. Остаток `W - R - M` занимает вход. Реальные API могут иметь отдельные пределы входа и выхода или учитывать reasoning tokens, то есть служебные токены рассуждений, по собственным правилам. Поэтому перед выбором модели проверяй её документацию.

На входе лежат обязательные инструкции приложения, текущий вопрос, согласованный формат и необязательная история. **Truncation**, обрезка, оставляет часть истории по явной политике. **Overflow** возникает, если запрос превышает известный предел. Если обязательные данные не помещаются, верни понятную ошибку, переспроси или выбери другой согласованный лимит. Политика приложения не должна исчезать от переполнения.

Блок ответа инструмента связан с вызовом ID. Считай вызов и ответ вместе, включая порядок сообщений внутри. Склейка последних двадцати строк может выбросить половину блока. Вынеси проверку доступа к беседе перед подсчётом. **Prompt injection** — попытка передать модели инструкцию через недоверенный источник вроде найденного документа. Пометка документа как данных помогает выразить смысл, но сама по себе не даёт границы авторизации. Размер окна не гарантирует внимания ко всем фрагментам. Старые, противоречащие или посторонние сведения могут ухудшить ответ даже в пределах лимита.

## Модель понимания

При окне 120, резерве 30 и запасе 10 вход получает 80. Если политика стоит 16, вопрос 8, формат 6, то остаётся 50 на историю. Пара инструмента за 35 может поместиться, а один блок за 55 — нет, даже если его приоритет выше. После отбора восстанови исходный порядок сообщений, чтобы причины предшествовали последствиям.

## Что нужно знать на Junior

Храни метку модели и версию счётчика вместе с бюджетом. Учебные веса и приоритеты в задаче назначены вручную. Для production проверь на наборе разговоров, какие случаи страдают от обрезки. Удаление устаревшей истории допустимо по продуктовым правилам, а проверка прав и целостности выполняется всегда.

## Примеры кода

Сначала вычислим доступный остаток для необязательной истории.
```python
def history_budget(window, output, margin, required):
    available = window - output - margin - sum(required)
    if available < 0:
        raise ValueError("required input does not fit")
    return available

assert history_budget(120, 30, 10, [16, 8, 6]) == 50
assert history_budget(10, 2, 1, [7]) == 0
try:
    history_budget(9, 2, 1, [7])
except ValueError:
    print("обязательный вход не помещается")
else:
    raise AssertionError("overflow accepted")
```
Получаем остатки 50 и 0. Ноль допустим, если ничего добавлять не нужно. При уменьшении окна до 9 явный отказ отличает переполнение от пустой истории.

## Типичные ошибки

- Считать только новое сообщение.
- Добавлять весь текст другого диалога, если в окне есть место.
- Отделять результат инструмента от вызова.
- Путать запас для вывода с модельной гарантией качества.

## Хорошие ответы

Суммируй инструкцию, вопрос, формат и историю и оставь согласованный резерв. Обязательное переполнение — явный отказ или смена плана. Документ не получает прав выполнять действия, даже если присутствует в длинном контексте.

## Критерии хорошего ответа

Приведи точную сумму. Покажи случай, где отрезание последней строки ломает пару событий. Объясни, почему передача текста модели не может выдать разрешение.

## Задача

Реализуй `select_context(blocks, conversation_id, window, reserve, margin=0)`. Блок — неизменяемый `Block(conversation_id, messages, tokens, required, priority)` из fixtures. `conversation_id=None` у общей политики. Данные другой беседы исключи. Счётчик дан на целый блок. Сохрани обязательные блоки, пока сумма входит в `window - reserve - margin`. Если не входит, подними `ValueError`. Отклони отрицательные параметры и отрицательный вес выбранной беседы. Если сумма резерва и запаса превышает окно, тоже ошибка.

Необязательные блоки перебирай по убыванию приоритета, при равенстве сначала более поздний. Пропускай блок, который не входит, и пробуй следующий. Возвращай выбранные `Block` в исходном порядке. Например, при окне 10, резерве 2 и обязательном блоке 3 остаётся 5; атомарный вызов-ответ весом 6 не добавляем. В Run есть этот сценарий. Проверь также точную границу, пустую историю и две беседы.
