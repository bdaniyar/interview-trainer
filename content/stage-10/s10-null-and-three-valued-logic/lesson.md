# NULL: неизвестные значения и трёхзначная логика

## Учебные цели

После урока ты сможешь:

- отличить `NULL` от нуля, пустой строки и текста `'NULL'`;
- объяснить, почему сравнение `= NULL` не находит неизвестные значения;
- использовать `IS NULL`, `IS NOT NULL` и `COALESCE`;
- предсказать, какие строки с неизвестными значениями пропустит `WHERE`;
- решить задачу о необязательном поле пользователя в SQL Lab.

## Теория

### Что это

`NULL` означает отсутствие известного значения. Например, у пользователя ещё не указана страна. Это не название страны и не специальная пустая строка: значения пока нет.

В `shop-v1.users` поле `country` допускает `NULL`. В публичном наборе у ID 1 и 2 страна `KZ`, у ID 3 — `NULL`, у ID 4 — `GE`. Поле `manager_id` тоже необязательное: у пользователя 1 руководитель не указан.

| Значение | Смысл |
| --- | --- |
| `NULL` | Нет известного значения |
| `0` | Известное число ноль |
| `''` | Известная строка длины ноль |
| `'NULL'` | Известный текст из четырёх букв |

Если API получил пустую строку, она не превращается в SQL NULL сама собой. Правила очистки и проверки ввода задаёт приложение.

### Как работает

Обычное сравнение с `NULL` не может установить равенство или неравенство. Результат такого сравнения неизвестен:

```sql
SELECT 5 = NULL AS equal_unknown,
       5 <> NULL AS different_unknown,
       NULL = NULL AS both_unknown;
```

Все три значения результата — SQL NULL, а не `true` или `false`. Даже два неизвестных значения нельзя считать равными: мы не знаем, какие значения отсутствуют.

### TRUE, FALSE и UNKNOWN

В SQL есть три логических результата: `TRUE`, `FALSE` и `UNKNOWN`. Неизвестный boolean-результат представлен значением NULL. Посмотри пример:

```sql
SELECT id, country, country = 'KZ' AS from_kz
FROM users;
```

У ID 1 и 2 выражение `from_kz` равно true, у ID 4 — false, у ID 3 — NULL. Важно, что **WHERE пропускает только TRUE**. FALSE и UNKNOWN не проходят.

Поэтому фильтр `WHERE country <> 'KZ'` пропустит пользователя 4, но не пользователя 3. «Страна неизвестна» не доказывает, что она отличается от KZ.

### Логические связки с UNKNOWN

| Выражение | Результат |
| --- | --- |
| `TRUE AND UNKNOWN` | UNKNOWN |
| `FALSE AND UNKNOWN` | FALSE |
| `TRUE OR UNKNOWN` | TRUE |
| `FALSE OR UNKNOWN` | UNKNOWN |
| `NOT UNKNOWN` | UNKNOWN |

Для `AND` достаточно ложной части, чтобы всё условие стало ложным. Для `OR` достаточно истинной части. Простое добавление `NOT` не превращает неизвестное сравнение в истинное.

### IS NULL и IS NOT NULL

Для проверки отсутствия значения используют отдельные условия: `IS NULL` и `IS NOT NULL`. Они возвращают true или false, а не UNKNOWN.

```sql
SELECT id, manager_id
FROM users
WHERE manager_id IS NULL;
```

В публичном наборе вернётся пользователь 1. Проверяется отсутствие руководителя, а не равенство руководителя какому-то неизвестному ID.

```sql
SELECT id, country
FROM users
WHERE country IS NOT NULL;
```

Этот запрос покажет пользователей 1, 2 и 4. Если бы у строки `country` была равна `''`, она тоже прошла бы такой фильтр: пустая строка является известным значением.

### COALESCE: значение для отображения

`COALESCE` возвращает первый аргумент, который не равен NULL:

```sql
SELECT id, COALESCE(country, 'не указана') AS country_label
FROM users;
```

Для пользователя 3 заголовок `country_label` содержит `не указана`, для остальных — исходную страну. Исходное поле `users.country` не изменяется.

`COALESCE('', 'не указана')` вернёт пустую строку: она не NULL. Поэтому подстановка значения для отображения не заменяет правила обработки пустого пользовательского ввода. В фильтрах не стоит заменять NULL на произвольную строку: эта строка может оказаться реальным значением данных.

### Важный нюанс / ограничение

`WHERE country = NULL` не является поиском неизвестной страны. Такое сравнение даёт UNKNOWN для каждой строки, поэтому фильтр не пропускает ни одну строку. Ошибки синтаксиса при этом может не быть: успешный Run с пустым результатом ещё не означает верное решение.

В нашей схеме `active` объявлено `NOT NULL`, а `country` — нет. Какие значения возможны, проверяй в Explorer по nullable-свойству столбца, а не по одному видимому набору строк.

### Где используется в backend

Профиль пользователя часто содержит необязательные поля. SQL NULL позволяет отличить «страна не указана» от указанного значения. При построении API нужно отдельно решить: как искать такие профили, как отображать отсутствие поля и допустима ли пустая строка на входе. Эти решения не стоит смешивать в одном сравнении.

## Модель понимания

Задай два вопроса: «Есть ли известное значение?» и «Если есть, чему оно равно?». На первый отвечают `IS NULL`/`IS NOT NULL`, на второй — обычные сравнения. Фильтр `WHERE` оставляет только доказанно истинные условия.

## Что нужно знать на Junior

### Обязательно

- NULL не равен нулю, пустой строке или тексту `'NULL'`.
- Обычные сравнения с NULL дают UNKNOWN.
- `WHERE` пропускает только TRUE.
- Проверки отсутствия значения — `IS NULL` и `IS NOT NULL`.
- `COALESCE` выбирает первое не-NULL значение и не меняет таблицу.

### Полезно

Проверять запрос не только на одной неизвестной стране, но и на нескольких, на наборе без NULL и на строках с `''`.

### Можно не учить глубоко

Особенности NULL в индексах и сложных агрегатах разберём отдельно. Здесь важны обычные сравнения и фильтрация.

## Примеры кода

Если нужны пользователи из другой страны **вместе с** пользователями без указанной страны, две ситуации надо перечислить явно:

```sql
SELECT id, country
FROM users
WHERE country <> 'KZ' OR country IS NULL;
```

На исходных данных это ID 3 и 4. Если убрать вторую часть, останется только ID 4. Порядок строк без сортировки не гарантирован.

## Типичные ошибки

- Написать `= NULL` или `<> NULL` и ожидать обычного сравнения.
- Использовать `country = ''` для поиска отсутствующей страны.
- Считать текст `'NULL'` специальным SQL-значением.
- Ожидать, что `NOT (country = 'KZ')` включит неизвестную страну.
- Подменить отсутствие значения условной строкой и случайно смешать её с настоящими данными.
- Считать, что один подходящий ID в публичной базе будет подходить во всех наборах.

## Практика

### Основная задача: неизвестная страна

В SQL Lab выведи `id` и `email` пользователей, для которых `country` неизвестна (SQL NULL). В результате должны быть только `id`, затем `email`. Порядок строк несущественен.

Сначала посмотри схему и данные `users`. Напиши запрос самостоятельно, выполни **Run**, затем **Check**. Проверка требует всех подходящих строк и отличает NULL от пустой строки и обычного текста. Решение не должно зависеть от видимых ID.

<details>

```sql
SELECT id, email
FROM users
WHERE country IS NULL;
```

На публичных данных подходит ID 3. Проверяется именно отсутствие страны; в дополнительных наборах ID и количество таких пользователей другие. Условие `country = NULL` не эквивалентно этому запросу.

2. Кто пройдёт `WHERE NOT (country = 'KZ')` на исходных данных? Попадёт ли туда ID 3?

Я различаю отсутствие значения и известное пустое значение. Например, пустая страна проходит IS NOT NULL, а отсутствующая — нет. ## Шпаргалка

- NULL — нет известного значения.
- `= NULL` и `<> NULL` дают UNKNOWN.
- `IS NULL` — значения нет, `IS NOT NULL` — значение есть.
- WHERE сохраняет только TRUE.
- `COALESCE` возвращает первое не-NULL значение; `''` уже является значением.
