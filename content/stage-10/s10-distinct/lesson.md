# DISTINCT: уникальные строки результата

## Учебные цели

После урока ты сможешь:

- убрать повторяющиеся строки результата через DISTINCT;
- объяснить DISTINCT по одному и нескольким столбцам;
- различать SQL NULL и пустую строку при удалении повторов;
- отдельно задать порядок уникальных значений;
- понять, когда повторы ожидаемы, а когда скрывают ошибку запроса.

## Теория

### Что это

`DISTINCT` оставляет одну копию каждой одинаковой **строки результата**. Он не удаляет записи из таблицы и не делает исходные данные уникальными.

В `shop-v1.products` две книги принадлежат категории books. Посмотри обычную проекцию:

```sql
SELECT category
FROM products
ORDER BY id;
```

Публичный результат — books, hardware, books: по одной строке на товар. Если API нужен список категорий, повторы не нужны:

```sql
SELECT DISTINCT category
FROM products
ORDER BY category;
```

Теперь это books и hardware, по одному разу. DISTINCT убрал повторы, ORDER BY отдельно задал порядок. DISTINCT сам по себе не обещает сортировку.

### Как работает

Сначала определяются поля результата, затем среди получившихся строк убираются одинаковые. Поэтому добавление поля может изменить то, какие строки считаются повторяющимися.

### DISTINCT по нескольким столбцам

Сравнивается вся выбранная комбинация полей:

```sql
SELECT DISTINCT country, active
FROM users
ORDER BY country ASC NULLS LAST, active DESC;
```

В публичном наборе получим GE/true, KZ/true и NULL/false. Два пользователя KZ имеют одинаковый active, поэтому их пары совпадают. Если бы в KZ был ещё и неактивный пользователь, пара KZ/false осталась бы отдельной строкой.

`DISTINCT country, active` не означает «уникальная страна, а active возьми любой». Уникальна вся пара. По этой же причине добавление уникального `id` обычно делает DISTINCT бесполезным для удаления повторов: строки уже различаются по ID.

### NULL и пустая строка

При удалении повторов DISTINCT считает несколько NULL в одном и том же месте совпадающими. Это специальное правило удаления повторов; обычное выражение `NULL = NULL` по-прежнему даёт UNKNOWN.

Небольшой самостоятельный пример со значениями, без изменения таблиц:

```sql
SELECT DISTINCT value
FROM (VALUES (NULL::text), (''), (''), ('NULL'), (NULL::text)) AS example(value)
ORDER BY value ASC NULLS LAST;
```

Получим три строки: пустую строку, текст NULL и SQL NULL. Два отсутствующих значения схлопнулись в одно; две пустые строки — тоже в одну. Но пустая строка и SQL NULL не стали одним значением.

Если нужны только известные значения, исключи NULL через WHERE. Например, список указанных руководителей:

```sql
SELECT DISTINCT manager_id
FROM users
WHERE manager_id IS NOT NULL
ORDER BY manager_id;
```

В публичном наборе это ID 1 и 2. Фильтр исключает отсутствие значения, DISTINCT убирает повторяющиеся ссылки на одного руководителя, ORDER BY задаёт последовательность.

### Сортировка уникальных результатов

Для списка значений явно добавляй ORDER BY. Без него PostgreSQL может использовать разные способы удаления повторов, и наблюдаемый порядок может измениться.

У обычного `SELECT DISTINCT` выражения ORDER BY должны присутствовать в списке SELECT. Если нужны уникальные категории, нельзя просто сортировать их по цене конкретного товара: у одной категории несколько цен. Сначала надо определить, какую цену считать ценой категории; это уже другая задача.

Текстовый порядок зависит от collation базы. В SQL Lab используется PostgreSQL с locale C. Для наших коротких кодов стран из латинских заглавных букв порядок однозначен; пустая строка идёт раньше непустых. Не стоит переносить это объяснение на алфавиты и локали всех приложений без проверки их collation.

### DISTINCT и GROUP BY

Для простого списка категорий можно сгруппировать строки по выбранному полю:

```sql
SELECT category
FROM products
GROUP BY category
ORDER BY category;
```

Здесь результат такой же: books, hardware. Но цель конструкций различается. DISTINCT убирает повторяющиеся строки проекции; GROUP BY формирует группы, по которым затем можно вычислять количество, сумму и другие показатели. Группировку подробно разберём в следующем этапе. Не добавляй её или DISTINCT по привычке.

### Важный нюанс / ограничение

Повторы не всегда являются ошибкой. Если у пользователя два заказа, соединение пользователя с заказами закономерно даёт две строки. Краткий пример JOIN для понимания результата; сам JOIN разберём отдельно:

```sql
SELECT u.id, u.email
FROM users AS u
JOIN orders AS o ON o.user_id = u.id
ORDER BY u.id, o.id;
```

В публичном наборе ID 1 и 2 появятся по два раза, ID 4 — один раз. Это по одной строке на заказ, хотя мы вывели только поля пользователя.

Если нужны именно пользователи, у которых есть заказы, можно получить уникальные строки пользователей:

```sql
SELECT DISTINCT u.id, u.email
FROM users AS u
JOIN orders AS o ON o.user_id = u.id
ORDER BY u.id;
```

Останутся ID 1, 2 и 4. Такой DISTINCT соответствует цели запроса. Но если условие JOIN ошибочно соединяет чужие строки, DISTINCT не исправит связь. Он может скрыть заметные повторы, оставив неправильный состав результата. Сначала выясни, чему должна соответствовать одна строка ответа, и проверь условие соединения.

### Где используется в backend

DISTINCT полезен для списка доступных категорий, фильтров поиска или уникальных пользователей из соединения. Для истории заказов повторы статуса или user_id, напротив, могут быть нормальны: каждая строка обозначает отдельный заказ. Удаление повторов без понимания этого смысла способно потерять нужные данные.

## Модель понимания

Сначала представь строку ответа целиком. Только после этого решай, какие полные строки являются одинаковыми. Затем отдельно задай порядок оставшихся строк. Исходная таблица при этом не меняется.

## Что нужно знать на Junior

### Обязательно

- DISTINCT относится ко всем выбранным столбцам вместе.
- Он убирает повторы результата, а не записи таблицы.
- При DISTINCT несколько одинаково расположенных NULL считаются повтором.
- Пустая строка остаётся отдельным известным значением.
- Для порядка нужен ORDER BY.

### Полезно

Отличать ожидаемую связь «один пользователь — несколько заказов» от неправильного JOIN. Понимать базовую разницу DISTINCT и GROUP BY.

### Можно не учить глубоко

DISTINCT ON и внутренние алгоритмы удаления повторов пока не нужны. Они не заменяют ясного условия задачи.

## Примеры кода

Один уникальный статус на строку:

```sql
SELECT DISTINCT status
FROM orders
ORDER BY status;
```

В публичном наборе получим cancelled, new и paid. Пять заказов превратились в три значения статуса. Это подходящий результат для фильтра статусов, но не список самих заказов.

## Типичные ошибки

- Забыть DISTINCT и вернуть одну страну по нескольку раз.
- Ожидать, что DISTINCT автоматически исключит NULL.
- Смешать пустую строку с SQL NULL.
- Добавить ID и удивиться, что одинаковые категории больше не схлопываются.
- Рассчитывать на сортировку без ORDER BY.
- Замаскировать ошибочное соединение вместо проверки его условия.
- Добавить DISTINCT в API, где каждая строка должна обозначать отдельный заказ.

## Практика

### Основная задача: уникальные страны

Выведи уникальные значения `country` из `users`. Исключи SQL NULL и отсортируй страны по возрастанию. В результате должен быть только столбец `country`. Если встречается пустая строка, она остаётся: это известное значение, а не NULL.

Посмотри данные в Explorer, напиши запрос и нажми **Run**, затем **Check**. Проверка учитывает повторы, неизвестные значения и позиции строк, в том числе на других наборах стран. Здесь проверяется список значений, а не пользователи по одному.

<details>
<summary>Показать решение для самопроверки</summary>

```sql
SELECT DISTINCT country
FROM users
WHERE country IS NOT NULL
ORDER BY country;
```

На публичных данных результат — GE, затем KZ. Условие исключает только SQL NULL. Оно не исключает пустую строку, если та присутствует в другом наборе.

### Дополнительная практика без отдельного Check

Выведи уникальные пары `category`, `price` из `products`, отсортированные по категории и цене. Сколько строк останется и почему две книги не станут одной строкой?

<details>
<summary>Показать ответ к дополнительной практике</summary>

```sql
SELECT DISTINCT category, price
FROM products
ORDER BY category, price;
```

Останутся три пары: books/30, books/40, hardware/90. У книг разные цены, поэтому полные строки результата различаются.

## Вопросы с собеседований

1. К чему относится DISTINCT, если выбрано несколько столбцов?
2. Почему DISTINCT может оставить одну строку с NULL, хотя NULL = NULL не даёт TRUE?
3. Гарантирует ли DISTINCT сортировку?
4. Почему DISTINCT не исправляет неправильный JOIN?

## Хорошие ответы

<details>
<summary>Показать ответы для собеседования</summary>

### Короткий ответ

DISTINCT убирает одинаковые строки результата по всей выбранной комбинации полей. NULL имеет специальное правило для удаления повторов. Порядок задаёт отдельный ORDER BY.

### Ответ уровня Junior

Сначала я определяю смысл одной строки ответа. Повторы пользователей при соединении с заказами могут быть ожидаемы. Если нужен список пользователей без повторов, DISTINCT подходит; если нужна строка на каждый заказ, он может потерять информацию. Ошибочное условие JOIN всё равно надо исправить.

### Follow-up

Для простой проекции GROUP BY может дать тот же набор уникальных значений. Когда требуются показатели по группам, используется группировка с агрегатами. Одна конструкция не является универсальной заменой другой.

</details>

## Критерии хорошего ответа

- Уникальность относится ко всей строке результата.
- NULL и пустая строка различаются.
- Удаление повторов не перепутано с сортировкой.
- Объяснено, почему повторы могут быть правильным свойством результата.

## Шпаргалка

- DISTINCT сравнивает всю строку результата.
- Несколько NULL могут схлопнуться в один, но NULL не становится пустой строкой.
- WHERE исключает ненужные значения; ORDER BY задаёт порядок.
- Дополнительное поле меняет понятие повтора.
- Сначала проверь смысл строк и JOIN, затем решай, нужен ли DISTINCT.
