# Set operations

## Учебные цели

После урока вы сможете объяснить механизм Set operations, предсказать строки на пустых и граничных входах, написать запрос и проверить его контракт.

## Теория

### Что это

Операции над множествами соединяют результаты вертикально. JOIN добавляет столбцы через пары строк, а UNION/INTERSECT/EXCEPT сравнивают строки одинаковой формы. Так backend может собрать единый список адресатов из разных источников или найти расхождения между двумя выгрузками.

### Как работает

UNION возвращает строки из обоих результатов и удаляет повторы. UNION ALL сохраняет все копии. INTERSECT оставляет общие строки, EXCEPT — строки левого результата, которых нет справа. Без ALL сравниваются множества целых строк; с ALL учитываются количества копий. Например, две копии x слева и одна справа дают одну копию x для EXCEPT ALL.

Число столбцов должно совпадать; соответствующие типы должны быть совместимы. Имена итоговых столбцов берутся из левого запроса. Для set semantics повторные NULL считаются одним значением, хотя NULL=NULL в обычном условии даёт UNKNOWN. INTERSECT имеет больший приоритет, чем UNION и EXCEPT; скобки позволяют явно задать смысл.

### Важный нюанс / ограничение

Внешний ORDER BY сортирует весь составной результат, а не каждый источник отдельно. ORDER BY/LIMIT внутри отдельной ветки требуют скобок, когда они должны относиться именно к ней. UNION ALL не обещает физический порядок «сначала все левые, затем правые». Страны — значения, а не пользователи: если хотя бы один paid-покупатель живёт в стране, эта страна исключается целиком, даже если другой активный пользователь той же страны ничего не покупал.

## Модель понимания

Совпадают форма и совместимые типы. Без ALL — множества, с ALL — кратности. EXCEPT направлен. Скобки задают приоритет, внешний ORDER BY задаёт вывод.

## Что нужно знать на Junior

### Обязательно

При повторных полных строках. UNION удаляет повторы, ALL сохраняет их кратности. Выбирать нужно по контракту, а не по привычке.

В правилах set operations повторные NULL рассматриваются как неразличимые значения строки. Это отличается от трёхзначного обычного сравнения через =.

## Примеры кода

Все примеры ниже выполняются в PostgreSQL 17 на неизменном shop-v1 либо явно заданных синтетических VALUES. SQL NULL обозначает отсутствие значения; строка `NULL` была бы другим значением.

### Пример 1

Три различных значения. Повторы a из обоих источников схлопываются.

```sql
SELECT * FROM (VALUES ('a'),('a'),('b')) a(v) UNION SELECT * FROM (VALUES ('a'),('c')) b(v) ORDER BY v;
```

Ожидаемый результат; типы: `v: text`.

| `v` |
| --- |
| a |
| b |
| c |

### Пример 2

ALL сохраняет три копии a. Здесь порядок задан явно.

```sql
SELECT * FROM (VALUES ('a'),('a'),('b')) a(v) UNION ALL SELECT * FROM (VALUES ('a'),('c')) b(v) ORDER BY v;
```

Ожидаемый результат; типы: `v: text`.

| `v` |
| --- |
| a |
| a |
| a |
| b |
| c |

### Пример 3

Общие значения — b и NULL. Множественная операция не использует обычное равенство NULL=NULL.

```sql
SELECT * FROM (VALUES ('a'),('b'),(NULL::text)) a(v) INTERSECT SELECT * FROM (VALUES ('b'),(NULL::text)) b(v) ORDER BY v NULLS LAST;
```

Ожидаемый результат; типы: `v: text`.

| `v` |
| --- |
| b |
| SQL NULL |

### Пример 4

Вычитается одна копия a. EXCEPT без ALL оставил бы только b.

```sql
SELECT * FROM (VALUES ('a'),('a'),('b')) a(v) EXCEPT ALL SELECT * FROM (VALUES ('a')) b(v) ORDER BY v;
```

Ожидаемый результат; типы: `v: text`.

| `v` |
| --- |
| a |
| b |

## Типичные ошибки

JOIN не заменяет UNION. UNION ALL добавляет лишние копии в задаче на уникальные страны. NOT IN может ошибиться из-за NULL. EXCEPT в обратную сторону ищет другой набор. Сортировка одной ветки не определяет итоговый порядок.

## Практика

Данные множеств: `A={a,a,b}`, `B={a,c}`, `C={b,c}`; повторы входят в исходные отношения. Для тех же VALUES предскажите INTERSECT ALL и EXCEPT без ALL. Затем сравните (A UNION B) INTERSECT C с A UNION (B INTERSECT C). Зафиксируйте скобки и внешний порядок. В новой основной задаче не перепутайте отсутствие paid у пользователя с отсутствием paid-покупателей во всей стране.

Сначала запишите ожидаемые столбцы, типы и строки вручную; затем используйте Run. Сравнивайте также пустой вход и повторные значения. Дополнительная практика не выдаёт статус основной задачи.

## Задача

**sql.set.50 — Страны активных пользователей без paid-покупателей**

Верните уникальные страны активных пользователей, в которых нет ни одного пользователя с paid-заказом. NULL рассматривается как одно значение множества. Столбец country; по возрастанию, NULL в конце.

Исходные таблицы смотрите в Explorer. Run выполняет запрос на публичных данных, Check проверяет отдельные наборы. Нужны все требуемые строки и только указанные столбцы. Принимаются эквивалентные SELECT независимо от выбранного синтаксиса. SQL XP отключён; черновик сохраняется в браузере.

<details>
<summary>Показать решение для самопроверки</summary>

```sql
SELECT country FROM users WHERE active EXCEPT SELECT u.country FROM users u JOIN orders o ON o.user_id=u.id WHERE o.status='paid' ORDER BY country NULLS LAST;
```

Сравните множества стран, устраните повторы и учитывайте NULL как одно значение EXCEPT.

</details>
