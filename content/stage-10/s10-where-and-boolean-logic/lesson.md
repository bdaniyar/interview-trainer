# WHERE: фильтрация строк и логические условия

## Учебные цели

После урока ты сможешь:

- отделить выбор столбцов от отбора строк;
- написать условие с операторами сравнения;
- объединить условия через `AND`, `OR` и `NOT`;
- объяснить роль скобок и приоритет операторов;
- отфильтровать пользователей по boolean-полю и проверить решение в SQL Lab.

## Теория

### Что это

`SELECT` определяет, **какие столбцы** попадут в результат. `WHERE` определяет, **какие строки** попадут в результат. Таблица при этом не изменяется.

В общей базе `shop-v1` у `users` есть `id`, `email`, `country`, `active`, `manager_id` и `created_at`. Например, список пользователей из Казахстана:

```sql
SELECT id, email
FROM users
WHERE country = 'KZ';
```

На исходных данных это пользователи с ID 1 и 2. `country` участвует в условии, хотя его нет в списке `SELECT`. Условие фильтрации не обязано быть столбцом ответа.

### Как работает

Для этих простых запросов полезна такая модель:

1. `FROM users` — берём строки пользователей.
2. `WHERE ...` — оставляем строки, для которых условие истинно.
3. `SELECT ...` — выбираем поля оставшихся строк.

Это логическое объяснение результата. PostgreSQL сам выбирает физический способ выполнения.

### Сравнения

| Оператор | Смысл | Пример условия |
| --- | --- | --- |
| `=` | равно | `country = 'KZ'` |
| `<>` или `!=` | не равно | `status <> 'cancelled'` |
| `>` и `<` | больше и меньше | `total > 100` |
| `>=` и `<=` | включая границу | `price <= 40` |

Строковые значения пишутся в одинарных кавычках: `'paid'`. Двойные кавычки нужны для имён SQL-объектов, а не строковых значений. Равенство записывают через `=`, не Python-оператор `==`.

```sql
SELECT id, total
FROM orders
WHERE total >= 100;
```

На исходных данных проходят заказы 10 и 12: их суммы 100 и 200. Заказ с суммой ровно 100 тоже проходит, поскольку используется `>=`.

### AND, OR и NOT

`AND` требует, чтобы выполнялись оба условия:

```sql
SELECT id, total
FROM orders
WHERE status = 'paid' AND total >= 100;
```

Это оплаченные заказы с суммой не меньше 100. На исходных данных проходят 10 и 12. Оплаченный заказ 13 с суммой 50 не проходит второе условие.

`OR` требует хотя бы одного истинного условия. `NOT` меняет истинное условие на ложное и наоборот. Приоритет: сначала `NOT`, затем `AND`, затем `OR`. Скобки явно задают нужную группировку:

```sql
SELECT id, status, total
FROM orders
WHERE (status = 'paid' OR status = 'new') AND total >= 100;
```

Здесь порог суммы относится к обеим категориям. Без скобок запись `status = 'paid' OR status = 'new' AND total >= 100` пропустила бы **любой** оплаченный заказ, в том числе заказ 13 с суммой 50.

Не сокращай `status = 'paid' OR status = 'new'` до `status = 'paid' OR 'new'`: обе части `OR` должны быть boolean-условиями.

### Boolean-поля PostgreSQL

`active` имеет тип `boolean`: значение `true` или `false`. В нашей схеме также задано `NOT NULL`, поэтому неизвестного значения в этом поле нет.

PostgreSQL принимает boolean-выражение прямо в `WHERE`. Условия `WHERE active`, `WHERE active = true` и `WHERE active IS TRUE` оставляют строки с истинным `active`. `NOT active` отбирает неактивных:

```sql
SELECT id, active
FROM users
WHERE NOT active;
```

В исходном наборе это пользователь 3 со значением `false`. Число `1` не стоит использовать вместо boolean-условия: PostgreSQL не рассматривает произвольное число как истину.

### LIKE: простой поиск по шаблону

`LIKE` сравнивает текст с шаблоном. `%` означает любую последовательность символов, в том числе пустую, `_` — один символ.

```sql
SELECT id, name
FROM products
WHERE name LIKE '%Book';
```

В исходном наборе подходят `Python Book` и `SQL Book`. `%Book` означает «заканчивается на Book», а `%Book%` — «содержит Book». Для текстовых полей этой учебной базы `LIKE` чувствителен к регистру; `ILIKE` позволяет искать без учёта регистра.

### Важный нюанс / ограничение

`WHERE` сохраняет только строки, где всё условие равно `TRUE`. Если поле допускает `NULL`, обычное сравнение может дать неизвестный результат. Поэтому `country <> 'KZ'` не означает «все остальные пользователи, включая неизвестную страну». Подробно разберём это в следующем уроке.

Приоритет операторов задаёт группировку, но не гарантирует порядок вычисления частей условия. Не используй `AND` как способ обязательно выполнить опасное выражение вторым.

### Где используется в backend

Список заказов в API часто ограничен статусом и минимальной суммой. Сначала сформулируй условие словами: «оплачен **и** сумма не меньше 100» или «оплачен **или** новый». Затем перенеси связки в SQL и явно поставь скобки.

## Модель понимания

Для каждой строки вычисляется одно итоговое условие. Строка либо проходит фильтр, либо нет. После фильтра `SELECT` формирует нужные поля. Ни `WHERE`, ни `AS` не удаляют и не меняют исходные данные.

## Что нужно знать на Junior

### Обязательно

- `SELECT` выбирает поля, `WHERE` отбирает строки.
- Сравнения возвращают boolean-результат.
- `NOT` имеет приоритет над `AND`, а `AND` — над `OR`.
- Скобки помогают точно выразить условие.
- Boolean-поле можно использовать непосредственно как условие.

### Полезно

Проверять границы `>`/`>=`, а также разницу `%текст`, `текст%` и `%текст%` в `LIKE`.

### Можно не учить глубоко

Планы выполнения и индексы пока не нужны для этой задачи. Сначала добейся правильного набора строк.

## Примеры кода

Попробуй фильтр товаров в диапазоне цены:

```sql
SELECT name, price
FROM products
WHERE price >= 30 AND price <= 40;
```

Он возвращает две книги с ценами 30 и 40, включая обе границы. Сравни его с вариантом `price > 30 AND price < 40`: на исходных данных тот не вернёт строк. Без `ORDER BY` порядок строк результата не гарантирован.

## Типичные ошибки

- Указать только нужные поля, забыв фильтр строк.
- Перепутать `AND` и `OR` или пропустить скобки.
- Написать `WHERE active = 'active'`, смешав имя поля и его значение.
- Забыть, что `>` исключает граничное значение.
- Вернуть один подходящий ID вручную вместо отбора всех подходящих строк.
- Добавить повторяющиеся строки, например через лишний `UNION ALL`.

## Практика

### Основная задача: активные пользователи

В SQL Lab выведи `id` и `email` пользователей, у которых `active = true`. Результат должен содержать только `id`, затем `email`. Порядок строк несущественен.

Посмотри `users` во вкладке «База данных», напиши запрос, нажми **Run** для просмотра результата и **Check** для проверки. Нужны все подходящие строки, без лишних строк и повторов. Check использует другие наборы данных, поэтому подстановка видимых ID не заменяет условие.

<details>

```sql
SELECT id, email
FROM users
WHERE active IS TRUE;
```

`WHERE active = true` и `WHERE active` тоже подходят для этой схемы. В публичном наборе проходят ID 1, 2 и 4. Check проверяет результат и на других данных, включая полностью активный и полностью неактивный наборы.

## Вопросы с собеседований

1. Чем фильтрация строк отличается от выбора столбцов?
2. Почему `A OR B AND C` отличается от `(A OR B) AND C`?
3. Можно ли использовать boolean-столбец прямо в `WHERE`?

## Хорошие ответы

<details>
<summary>Показать ответы для собеседования</summary>

### Короткий ответ

`WHERE` оставляет строки с истинным условием. `SELECT` выбирает поля этих строк. `AND` связывает обязательные условия, `OR` — альтернативы, `NOT` отрицает условие.

### Ответ уровня Junior

Сначала я формулирую критерий отбора, затем проверяю его на подходящей, неподходящей и граничной строках. В смешанном условии ставлю скобки: без них `AND` связывается раньше `OR`. Boolean-поле можно использовать как условие; в нашей таблице `active` не допускает NULL.

### Follow-up

`A OR B AND C` читается как `A OR (B AND C)`. Если порог `C` должен применяться и к `A`, и к `B`, нужны скобки `(A OR B) AND C`.

</details>

## Критерии хорошего ответа

- Различаются поля и строки результата.
- Объяснены смысл связок и роль скобок.
- Условие проверено на конкретных строках и границах.
- Успешное выполнение запроса не принято за доказательство правильности.

## Задача

Получи Passed для задачи «Активные пользователи». Неудачная повторная проверка не стирает прежний успех. Reset восстанавливает базу, сохраняя SQL-черновик и завершение задачи. SQL Check пока не начисляет XP.

## Шпаргалка

- Поля — `SELECT`, строки — `WHERE`.
- Равенство — `=`, неравенство — `<>`.
- Приоритет: `NOT`, `AND`, `OR`; скобки делают смысл явным.
- `LIKE`: `%` — последовательность символов, `_` — один символ.
- Run показывает результат; Check проверяет условие на нескольких наборах.
