# Subqueries

## Учебные цели

После урока вы сможете объяснить механизм Subqueries, предсказать строки на пустых и граничных входах, написать запрос и проверить его контракт.

## Теория

### Что это

Подзапрос — запрос внутри другого запроса. Он позволяет сначала получить факт, а затем использовать его как значение, условие или таблицу. Например, каталог показывает товары дороже самого дешёвого товара; приложение не обязано сначала скачивать цену в Python и отправлять второй запрос.

### Как работает

Скалярный подзапрос занимает место одного значения и обязан вернуть один столбец и не больше одной строки. Ноль строк превращается в SQL NULL; две строки вызывают cardinality violation 21000. Агрегат без GROUP BY обычно возвращает одну строку даже на пустом входе: COUNT даёт 0, AVG даёт NULL. Поэтому «результат пуст» и «единственная строка содержит NULL» различаются.

В WHERE подзапрос может задавать порог или множество для IN. Подзапрос в FROM возвращает отношение: у него может быть много строк и столбцов, ему дают понятное имя. WHERE оставляет только TRUE; сравнение с неизвестным порогом не проходит. Повторные значения внутри IN не умножают внешние строки. Скалярный контекст, наоборот, не допускает несколько одинаковых строк: равенство значений не устраняет ошибку количества строк.

### Важный нюанс / ограничение

Подзапрос не обещает отдельное физическое выполнение до внешнего запроса. Оптимизатор может преобразовать выражение. Если важна стоимость, исследуют реальный план и статистику, а не объявляют любой вложенный SELECT медленным. В Lab разрешены только SELECT; EXPLAIN здесь не открыт. Основная задача использует NOT NULL total, поэтому NULL-порог появляется при пустой orders, а не из выдуманной nullable суммы.

## Модель понимания

Сначала определите контекст: значение, множество или таблица. Для scalar проверьте 0/1/2 строки. Для AVG на пустом входе ожидайте NULL. Уточните строгую границу и область агрегации.

## Что нужно знать на Junior

### Обязательно

Скалярный используется как одно значение: один столбец, максимум одна строка, пустой результат даёт NULL. Табличный в FROM даёт отношение произвольной допустимой формы.

Ограничение относится к количеству строк, а не к числу различных значений. Если нужен один агрегат, его следует посчитать явно; случайный LIMIT изменяет контракт.

## Примеры кода

Все примеры ниже выполняются в PostgreSQL 17 на неизменном shop-v1 либо явно заданных синтетических VALUES. SQL NULL обозначает отсутствие значения; строка `NULL` была бы другим значением.

### Пример 1

Минимум равен 30. Keyboard стоит 90, SQL Book — 40; оба строго выше. Товар за 30 исключается.

```sql
SELECT id,name FROM products WHERE price > (SELECT MIN(price) FROM products) ORDER BY id;
```

Ожидаемый результат; типы: `id: int8`, `name: text`.

| `id` | `name` |
| --- | --- |
| 101 | Keyboard |
| 102 | SQL Book |

### Пример 2

Во внутреннем результате ноль строк. Внешний SELECT всё равно возвращает одну строку с NULL.

```sql
SELECT (SELECT id FROM users WHERE id < 0) AS absent;
```

Ожидаемый результат; типы: `absent: int8`.

| `absent` |
| --- |
| SQL NULL |

### Пример 3

Внутренняя таблица содержит две группы. Внешний запрос сортирует уже готовые группы.

```sql
SELECT category,n FROM (SELECT category,COUNT(*) AS n FROM products GROUP BY category) AS counts ORDER BY category;
```

Ожидаемый результат; типы: `category: text`, `n: int8`.

| `category` | `n` |
| --- | --- |
| books | 2 |
| hardware | 1 |

### Пример 4

Намеренно ошибочный пример: четыре строки не помещаются в скалярный результат. Ожидается SQLSTATE 21000.

```sql
SELECT (SELECT id FROM users) AS one_id;
```

## Типичные ошибки

LIMIT 1 без порядка маскирует неверную постановку скалярной задачи. Подмена AVG на MAX меняет порог. Удаление внешнего WHERE возвращает все строки. Сравнение x = NULL никогда не проверяет отсутствие значения; нужен IS NULL.

Затем отдельно выведите среднюю цену всех товаров через подзапрос в FROM. Объясните, почему одна категория без дорогих товаров не является ошибкой.

Сначала запишите ожидаемые столбцы, типы и строки вручную; затем используйте Run. Сравнивайте также пустой вход и повторные значения. Дополнительная практика не выдаёт статус основной задачи.

## Задача

**sql.subquery.27 — Заказы выше среднего**

Заказы со строго большей, чем средняя по всем orders, суммой. Верните id,total; порядок строк несущественен.

Исходные таблицы смотрите в Explorer. Run выполняет запрос на публичных данных, Check проверяет отдельные наборы. Нужны все требуемые строки и только указанные столбцы. Принимаются эквивалентные SELECT независимо от выбранного синтаксиса. SQL XP отключён; черновик сохраняется в браузере.
