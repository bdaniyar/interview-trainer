# `ROW_NUMBER`, `RANK`, `DENSE_RANK`

## Учебные цели

После урока вы сможете объяснить механизм `ROW_NUMBER`, `RANK`, `DENSE_RANK`, предсказать строки на пустых и граничных входах, написать запрос и проверить его контракт.

## Теория

### Что это

Номер строки, место в рейтинге и номер группы одинаковых результатов — разные понятия. Для списка заказов нужен уникальный порядковый номер, а для спортивной таблицы равные результаты могут делить одно место. Выбор функции является частью бизнес-контракта.

### Как работает

ROW_NUMBER выдаёт 1,2,3... внутри раздела. Если ORDER BY не определяет полный порядок, связь номера с конкретной строкой среди равных ключей не определена. RANK выдаёт одинаковое место peers и оставляет пропуск после них: 1,1,3. DENSE_RANK нумерует peer-группы без пропуска: 1,1,2.

Peers определяются всем списком оконного ORDER BY. Если добавить уникальный id к рейтингу по баллам, равные баллы перестанут быть peers — и смысл RANK изменится. Для основной задачи наоборот требуется именно нумерация всех заказов: created_at DESC,id DESC однозначно выбирает более новый timestamp, а при равенстве больший id.

### Важный нюанс / ограничение

Top-1 по ROW_NUMBER и все первые места по RANK — разные выборки. Внешний фильтр rn<=2 выдаёт максимум две строки на раздел, rank<=2 может выдать больше из-за ties. Все три функции возвращают bigint. Номера не являются постоянными идентификаторами: новый заказ меняет нумерацию при следующем запросе.

## Модель понимания

Номер строки: ROW_NUMBER. Место с пропусками: RANK. Номер peer-группы: DENSE_RANK. Полный порядок нужен для нумерации, но может разрушить желаемые равные места.

## Что нужно знать на Junior

### Обязательно

Обе функции дают одно место peers. RANK пропускает места после группы равных строк, DENSE_RANK считает группы подряд.

Иначе строки с равными ключами могут получить номера в любом порядке. Уникальный id завершает порядок, когда контракт требует однозначной нумерации.

## Примеры кода

Все примеры ниже выполняются в PostgreSQL 17 на неизменном shop-v1 либо явно заданных синтетических VALUES. SQL NULL обозначает отсутствие значения; строка `NULL` была бы другим значением.

### Пример 1

У 1 и 2 одинаковые баллы: они делят rank=1. Следующий rank=3, но dense_rank=2. Для rn id определяет, кто первый.

```sql
SELECT id,score,ROW_NUMBER() OVER(ORDER BY score DESC,id) AS rn,RANK() OVER(ORDER BY score DESC) AS rnk,DENSE_RANK() OVER(ORDER BY score DESC) AS dense FROM (VALUES (1,90),(2,90),(3,80),(4,70)) s(id,score) ORDER BY id;
```

Ожидаемый результат; типы: `id: int4`, `score: int4`, `rn: int8`, `rnk: int8`, `dense: int8`.

| `id` | `score` | `rn` | `rnk` | `dense` |
| --- | --- | --- | --- | --- |
| 1 | 90 | 1 | 1 | 1 |
| 2 | 90 | 2 | 1 | 1 |
| 3 | 80 | 3 | 3 | 2 |
| 4 | 70 | 4 | 4 | 3 |

### Пример 2

Нумерация начинает отсчёт заново у hardware. В books дороже SQL Book, поэтому он первый.

```sql
SELECT id,category,ROW_NUMBER() OVER(PARTITION BY category ORDER BY price DESC,id DESC) AS rn FROM products ORDER BY category,rn;
```

Ожидаемый результат; типы: `id: int8`, `category: text`, `rn: int8`.

| `id` | `category` | `rn` |
| --- | --- | --- |
| 102 | books | 1 |
| 100 | books | 2 |
| 101 | hardware | 1 |

## Типичные ошибки

Оконный ORDER BY без id не разрешает ties нумерации. Глобальный ROW_NUMBER не начинает отсчёт у нового пользователя. RANK не является произвольной заменой ROW_NUMBER. Сортировка created_at ASC нумерует от старых заказов.

## Практика

Данные: `products` из второго примера; для равных цен добавьте синтетические строки id=7,8 с ценой 90 в одну категорию. Выведите два самых дорогих товара каждой категории через внешний фильтр по ROW_NUMBER. Затем на синтетических равных ценах замените его RANK и объясните изменение числа строк. Не добавляйте id в рейтинг, если хотите сохранить равные места.

Сначала запишите ожидаемые столбцы, типы и строки вручную; затем используйте Run. Сравнивайте также пустой вход и повторные значения. Дополнительная практика не выдаёт статус основной задачи.

## Задача

**sql.window.33 — ROW_NUMBER orders**

Верните id,user_id,row_number для всех заказов. Нумерация с 1 отдельно по user_id, created_at DESC,id DESC. Итог по user_id,row_number.

Исходные таблицы смотрите в Explorer. Run выполняет запрос на публичных данных, Check проверяет отдельные наборы. Нужны все требуемые строки и только указанные столбцы. Принимаются эквивалентные SELECT независимо от выбранного синтаксиса. SQL XP отключён; черновик сохраняется в браузере.

<details>
<summary>Показать решение для самопроверки</summary>

```sql
SELECT id,user_id,ROW_NUMBER() OVER(PARTITION BY user_id ORDER BY created_at DESC,id DESC) AS row_number FROM orders ORDER BY user_id,row_number;
```

Проверьте PARTITION BY, обе сортировки DESC, последовательность без пропусков и итоговый порядок.

</details>
