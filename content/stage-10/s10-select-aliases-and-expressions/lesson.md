# SELECT: столбцы и псевдонимы

## Учебные цели

После урока ты сможешь:

- выбрать конкретные столбцы из таблицы;
- задать имя столбца результата через `AS`;
- отличить результат запроса от хранимой таблицы;
- объяснить, почему без сортировки нельзя полагаться на порядок строк.

## Теория

### Что это

`SELECT` получает данные и формирует результат запроса. После `SELECT` перечисляют нужные столбцы, после `FROM` — таблицу, из которой берутся строки.

Например, в учебной таблице `products` есть `id`, `name`, `category` и `price`. Для списка названий и цен достаточно двух столбцов:

```sql
SELECT name, price
FROM products;
```

В результате будут только `name` и `price`. Остальные столбцы останутся в таблице, но не попадут в этот результат.

### Как работает

Для простого запроса мысленно сделай два шага:

1. `FROM products` — возьми строки таблицы товаров.
2. `SELECT name, price` — для каждой строки выведи название и цену.

Порядок столбцов в списке `SELECT` задаёт порядок столбцов результата. `SELECT price, name` вернёт цену первой, название вторым.

### Псевдоним через AS

Псевдоним задаёт имя **столбца результата**:

```sql
SELECT name AS product_name, price
FROM products;
```

Первый столбец результата называется `product_name`. Исходный столбец таблицы по-прежнему называется `name`. `AS` не выполняет переименование в схеме и не изменяет хранимые данные.

### Важный нюанс / ограничение

Порядок столбцов и порядок строк — разные вещи. Столбцы следуют списку `SELECT`. Порядок **строк** без `ORDER BY` не гарантирован: он может поменяться при другом плане выполнения или изменении данных. Сортировку подробно разберём отдельно.

Если условие не требует порядка строк, правильные решения могут вернуть одни и те же строки в разной последовательности.

### Где используется в backend

API обычно нужны конкретные поля, а не вся таблица. Явный список столбцов помогает вернуть нужные данные, не передавать лишнее и дать результату понятные имена для ответа API.

## Модель понимания

Представь таблицу как набор строк с именованными столбцами. Запрос создаёт отдельный результат:

- `FROM` выбирает источник;
- список `SELECT` выбирает поля результата и их порядок;
- `AS` меняет заголовок в результате;
- исходная таблица сохраняет свои столбцы и значения.

Открой «База данных» в SQL Lab. После запроса с псевдонимом схема таблицы останется прежней. Это можно проверить через Refresh.

## Что нужно знать на Junior

### Обязательно

- Синтаксис `SELECT столбцы FROM таблица`.
- Явное перечисление нужных столбцов.
- Псевдоним через `AS`.
- Разница между схемой таблицы и заголовками результата.
- Отсутствие гарантированного порядка строк без `ORDER BY`.

### Полезно

`SELECT *` выбирает все столбцы. Для задания с точным списком полей он обычно не подходит: в ответ попадут лишние столбцы.

### Можно не учить глубоко

В этом упражнении не нужны фильтрация, объединение таблиц, индексы и планы выполнения. Их разберём в следующих уроках.

## Примеры кода

Выбор двух столбцов:

```sql
SELECT name, price
FROM products;
```

Понятное имя для результата:

```sql
SELECT name AS product_name, price
FROM products;
```

Вычисляемое поле тоже можно назвать:

```sql
SELECT name, price * 2 AS double_price
FROM products;
```

Этот запрос показывает удвоенную цену. Значения `products.price` в базе не меняются.

## Типичные ошибки

- Забыть `AS`, хотя условие требует определённое имя столбца результата.
- Поменять местами столбцы, когда условие задаёт их порядок.
- Использовать `SELECT *` и вернуть лишние поля.
- Вернуть только часть строк или добавить ненужные повторы.
- Записать значения из видимой таблицы вручную вместо запроса к данным.
- Считать, что псевдоним переименовал столбец в таблице.

## Практика

### Выбор столбцов и псевдоним

Выведи `id` и `email` **всех пользователей** из `users`. Назови столбец `id` псевдонимом `user_id`. Результат должен содержать только столбцы `user_id` и `email` в этом порядке.

Порядок строк несущественен. Никакая фильтрация в этом задании не требуется.

1. На вкладке «База данных» посмотри столбцы и строки `users`.
2. Напиши запрос в `query.sql`.
3. Нажми **Run**, чтобы посмотреть результат или ошибку PostgreSQL.
4. Нажми **Check**, чтобы проверить решение на публичном и дополнительных тестовых наборах.

Run не определяет правильность решения. Check сравнивает имена и порядок столбцов, значения и полный набор строк. Количество одинаковых строк тоже учитывается. Жёстко записанные значения публичного примера не пройдут дополнительные наборы.

## Вопросы с собеседований

1. Что выбирают `SELECT` и `FROM` в простом запросе?
2. Меняет ли `AS` имя столбца в таблице?
3. Чем отличаются порядок столбцов и порядок строк?
4. Почему API часто полезнее явный список полей, чем `SELECT *`?

## Хорошие ответы

### Короткий ответ

`SELECT` задаёт столбцы результата, `FROM` — источник строк. `AS` даёт столбцу результата псевдоним и не изменяет схему. Столбцы следуют списку `SELECT`, а порядок строк без сортировки не гарантирован.

### Ответ уровня Junior

Я сначала определяю нужные поля и таблицу-источник, затем явно перечисляю поля в нужном порядке. Если контракт ответа требует другого имени, использую псевдоним. После выполнения проверяю заголовки и строки результата. Я не рассчитываю на порядок строк без явной сортировки и не принимаю успешное выполнение за доказательство правильности решения.

### Follow-up

Если у таблицы появится новый столбец, запрос с явным списком продолжит возвращать прежний набор полей. Результат `SELECT *` может измениться.

## Критерии хорошего ответа

- Названы источник строк и список полей результата.
- Псевдоним не перепутан с переименованием в схеме.
- Различаются порядок столбцов и порядок строк.
- Понятна разница между выполнением Run и проверкой Check.

## Задача

Выполни задание из раздела «Практика» и добейся Passed во всех проверках. Исправлять и проверять запрос можно несколько раз. Успешное решение сохраняется отдельно от Python-заданий; последующая неудачная попытка не стирает этот факт.

## Шпаргалка

- `SELECT` — какие столбцы получить.
- `FROM` — откуда взять строки.
- `AS` — как назвать столбец результата.
- Порядок столбцов задаётся списком `SELECT`.
- Для гарантированного порядка строк нужна явная сортировка.
- Run показывает результат, Check проверяет условие на нескольких наборах.
