# CASE

## Учебные цели

После урока вы сможете объяснить механизм CASE, предсказать строки на пустых и граничных входах, написать запрос и проверить его контракт.

## Теория

### Что это

CASE вычисляет значение по условиям прямо в SQL. Он удобен, когда API должен вернуть метку, диапазон цены или несколько счётчиков по категориям, не скачивая все исходные строки в Python. CASE не управляет транзакцией и не является циклом.

### Как работает

Simple CASE сравнивает одно выражение с вариантами WHEN. Searched CASE проверяет отдельные булевы условия по порядку и выбирает первую TRUE-ветку. FALSE и UNKNOWN не выбирают ветку. ELSE задаёт запасной результат; без ELSE при отсутствии совпадений возвращается NULL.

Все результирующие ветки должны приводиться к совместимому типу. Нельзя считать CASE контейнером, который в одной строке содержит text, а в другой несвязанный integer. Для условной агрегации CASE обычно находится внутри SUM: каждая исходная строка даёт 1 или 0, затем считается сумма. CASE вокруг SUM выбирает значение уже для готовой группы и решает другую задачу.

### Важный нюанс / ограничение

CASE обычно вычисляет только нужную ветку, но это не абсолютная защита от ошибок планирования. Константное ошибочное выражение может быть вычислено оптимизатором раньше. Ветвление не разрешает запрещённую функцию или запись: policy проверяет весь AST. В orders.status есть NOT NULL, но набор возможных текстовых статусов не ограничен перечислением, поэтому ELSE обязателен в задании.

## Модель понимания

Первая TRUE-ветка побеждает. Не забудьте ELSE, порядок границ, совместимость типов и отдельную проверку IS NULL.

## Что нужно знать на Junior

### Обязательно

Simple сравнивает одно выражение с вариантами; searched проверяет самостоятельные булевы условия и выбирает первое истинное.

При отсутствии TRUE-ветки возвращает NULL. Результирующие ветки всё равно должны иметь совместимые типы.

## Примеры кода

Все примеры ниже выполняются в PostgreSQL 17 на неизменном shop-v1 либо явно заданных синтетических VALUES. SQL NULL обозначает отсутствие значения; строка `NULL` была бы другим значением.

### Пример 1

Проверки идут сверху вниз: 90 попадает в high, 30 и 40 в medium.

```sql
SELECT id,CASE WHEN price>=50 THEN 'high' WHEN price>=30 THEN 'medium' ELSE 'low' END AS band FROM products ORDER BY id;
```

Ожидаемый результат; типы: `id: int8`, `band: text`.

| `id` | `band` |
| --- | --- |
| 100 | medium |
| 101 | high |
| 102 | medium |

### Пример 2

Simple CASE не делает NULL равным NULL; searched CASE использует отдельный IS NULL.

```sql
SELECT CASE NULL::text WHEN NULL THEN 'equal' ELSE 'unknown' END AS simple, CASE WHEN NULL::text IS NULL THEN 'missing' END AS searched;
```

Ожидаемый результат; типы: `simple: text`, `searched: text`.

| `simple` | `searched` |
| --- | --- |
| unknown | missing |

### Пример 3

Каждая строка даёт по одному индикатору. Сумма indicators считает категории без изменения числа групп.

```sql
SELECT SUM(CASE WHEN category='books' THEN 1 ELSE 0 END) AS books, SUM(CASE WHEN category='hardware' THEN 1 ELSE 0 END) AS hardware FROM products;
```

Ожидаемый результат; типы: `books: int8`, `hardware: int8`.

| `books` | `hardware` |
| --- | --- |
| 2 | 1 |

## Типичные ошибки

Нет ELSE — неизвестные статусы превращаются в NULL. Условие price>=30 перед price>=50 перехватывает дорогие товары. CASE status WHEN NULL не проверяет отсутствие статуса. SUM(total) вместо количества индикаторов меняет единицу измерения.

## Практика

Данные: `products.price` равны 30,90,40; границы новой категории выберите 40 и 50. Добавьте четвёртую ценовую категорию и проверьте пересечение условий на точной границе 40. Затем посчитайте количество дорогих товаров по каждой категории через GROUP BY и CASE внутри SUM.

Сначала запишите ожидаемые столбцы, типы и строки вручную; затем используйте Run. Сравнивайте также пустой вход и повторные значения. Дополнительная практика не выдаёт статус основной задачи.
