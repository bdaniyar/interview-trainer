# Streaming и события потока

Ответ чата уже начал появляться. После двух фрагментов сеть прерывается. Для пользователя важно знать, сохранится ли такой ответ как завершённый. Для приложения важно освободить ресурс, даже если следующий event больше никто не запрашивает.

## Учебные цели

- Различить delta, terminal, преждевременный EOF и сетевую ошибку.
- Обеспечить закрытие upstream при отмене и ранней остановке потребителя.
- Проверить Unicode и порядок typed events.

## Теория

Сервис потоково отдаёт данные частями. **SSE**, Server-Sent Events, — текстовый формат кадров: строки `event:` и `data:`, пустая строка завершает кадр. Сетевой chunk может содержать полкадра или несколько кадров, поэтому следует читать поток через parser, а не превращать каждый TCP-фрагмент в JSON. SDK выдаёт разобранные **typed events**, то есть события с определённым типом и полями. Responses, например, документирует `response.output_text.delta` и `response.completed`. Прикладной протокол может дать стабильные `delta` и `terminal` независимо от формата провайдера.

**Delta** — фрагмент, а не готовый ответ. Пустую delta можно пропустить. Строки Unicode передаются уже после корректной расшифровки bytes. **Terminal** — один окончательный исход: completed, incomplete, refusal или failed. Если HTTP 200 пришёл и чтение закончилось без terminal, нужен неполный исход. Midstream failure оставляет ранее полученные части, но ответ не становится окончательным. Если потребитель ушёл, ему уже не доставить terminal.

**Disconnect** — прекращение получения запроса клиентом. При закрытии потребителя нужно закрыть свой async generator и upstream. `contextlib.aclosing` оборачивает генератор так, чтобы ранний выход явно вызывал `aclose`. **Backpressure** означает, что приложение учитывает скорость получателя. В pull-схеме `async for` ждёт обработки предыдущего фрагмента. Если отдельный worker складывает данные в очередь, ограничь размер очереди. Иначе медленный клиент удерживает растущий буфер.

## Модель понимания

Стрим хранит состояние по одному запросу. После первой delta нельзя безопасно прозрачно повторить весь запрос: пользователю может прийти повтор или несовместимая строка. Сервис фиксирует terminal и перестаёт просить дальнейшие события. Приложение обрабатывает данные модели как недоверенные. Например, интерфейс выводит текст, не выполняя HTML или команду из delta.

## Что нужно знать на Junior

Проверяй два уровня. Генератор тестируй на порядок, cleanup и незавершённый выход. HTTP-тест проверяет заголовок и кадры. Клиент в памяти может собрать весь ответ до возврата, поэтому timing и реальный disconnect требуют отдельного теста ASGI send или сети.

## Примеры кода

Обработаем первую строку, затем закроем upstream. `finally` даёт наблюдаемый след.
```python
import asyncio
from contextlib import aclosing

async def read_first(items):
    events = []
    async def source():
        try:
            for item in items:
                yield item
        finally:
            events.append("closed")
    async with aclosing(source()) as stream:
        async for item in stream:
            if item:
                return item, events
    return None, events

assert asyncio.run(read_first(["", "ёж", "ещё"])) == ("ёж", ["closed"])
assert asyncio.run(read_first([])) == (None, ["closed"])
assert asyncio.run(read_first([""])) == (None, ["closed"])
print("upstream закрыт")
```
Вывод подтверждает завершение проверок. Если consumer прочёл «ёж», третью строку не запрашивали. Пример моделирует pull и явное закрытие, без TCP, SSE-parser и повторов.

## Типичные ошибки

- Завершать ответ на первом HTTP 200 или первом chunk.
- Повторять stream после уже показанного текста.
- Терять символ в разрезанном UTF-8 байтовом потоке.
- Оставлять upstream открытым из-за break.

## Хорошие ответы

По потоковой границе проходят типизированные части; окончательное состояние связано с terminal. EOF не доказывает факт его отправки. Ограниченная очередь или pull-consumer подчиняют производителя скорости доставки.

## Критерии хорошего ответа

Назови порядок событий, владельца ресурса и условие завершения. Покажи, что тест раннего закрытия ждёт наблюдаемого cleanup, а не просто закончился без ошибки.

## Задача

Реализуй `normalize_events(source)` как async generator. Вход — закрываемый async iterator `WireEvent` из contracts. `text_delta` с непустым текстом даёт `AppEvent("delta", текст)`. `metadata` и пустые delta пропускаются. `done` даёт completed и usage, `incomplete` даёт incomplete и usage, `failure` и `StreamFailed` дают failed без сырого текста. Неподтверждённый EOF даёт incomplete. Например, delta «привет» и done с расходом 3 дают delta и completed с usage=3. Начни cleanup сразу после первого terminal, не дочитывай последующие события. При вызове `aclose` или отмене закрой upstream и продолжи отмену.

Run показывает открытый пример. Check проверяет несовпадающие фрагменты, типы терминала, EOF, Unicode и закрытие.
