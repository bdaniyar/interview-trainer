# Жизненный цикл async-клиента и отмена

Если клиент создаётся для каждого запроса, соединения почти не переиспользуются. Если общими становятся ещё и пользовательские данные, одновременные запросы смешиваются. Нужны два разных срока жизни.

## Учебные цели

- Открыть и закрыть один async-клиент на приложение.
- Остановить ожидание по сроку и пропустить внешнюю отмену.
- Доказать, что к моменту вызова закрыта транзакция чтения.

## Теория

**Lifespan** — время работы приложения от инициализации до остановки. Клиент с пулом HTTP-соединений можно открыть перед `yield` lifespan и закрыть после. В FastAPI зависимости получают этот ресурс с уровня приложения. Каждый запрос передаёт свой контекст аргументом. В текущем упражнении `open_service` — самостоятельный async context manager с тем же смыслом, который FastAPI может использовать внутри lifespan.

**Connect timeout** ограничивает подключение, **read timeout** — ожидание данных от сервера, **write timeout** — запись части запроса, а **pool timeout** — ожидание свободного соединения. Общий **deadline** объединяет всё ожидание, даже если отдельные чтения происходят часто и никогда не превышают свой read timeout. В Python `asyncio.timeout` выставляет срок, на выходе преобразует собственную отмену в TimeoutError и даёт внешнему CancelledError пройти. За очистку отвечает `finally`.

Загрузка контекста и опциональная запись результата — операции базы данных. Выход из `async with repository.read(actor)` заканчивает транзакцию. Снаружи остаётся только снапшот, простое значение. Если ответ записывается после ожидания, важно заново проверить версию записи и права. Так отказ сети или отмена не удерживают соединение на весь вызов модели. Отдельная задача не должна делить изменяемое состояние AsyncSession с другими задачами.

## Модель понимания

Клиент живёт в рамке приложения. Транзакция внутри запроса длится до получения снапшота. Внешнее ожидание начинается после закрытия транзакции. Отмена закрывает операцию провайдера сразу, а общий клиент остаётся пригодным для следующего запроса. При shutdown cleanup закрывает клиент ровно один раз.

## Что нужно знать на Junior

Тест с Event может зафиксировать «вызов начался» и «ресурс освобождён». Из такого теста видно, что внешняя отмена пришла именно в ожидание, и что транзакция не открыта. Контроль таймаута не требует ждать реальную секунду. Проверяй ограниченный код со сроком 0 и зависимостью, которая действительно приостанавливается.

## Примеры кода

Рассмотрим выход из операции чтения и независимый отсчёт для следующего шага.
```python
import asyncio
from contextlib import asynccontextmanager

async def probe(deadline, stall):
    events = []
    @asynccontextmanager
    async def read():
        events.append("begin")
        try:
            yield "доступный контекст"
        finally:
            events.append("end")

    async with read() as context:
        assert context
    try:
        async with asyncio.timeout(deadline):
            events.append("external")
            if stall:
                await asyncio.Event().wait()
    except TimeoutError:
        events.append("timeout")
    return events

assert asyncio.run(probe(1, False)) == ["begin", "end", "external"]
assert asyncio.run(probe(0, True)) == ["begin", "end", "external", "timeout"]
assert asyncio.run(probe(0, False))[-1] == "external"
print("чтение заканчивается раньше внешнего ожидания")
```
Поставленный срок действует через кооперативное ожидание. Блок без await может закончиться до доставки отмены. Асинхронность не превращает тяжёлую CPU-работу в прерываемый вызов.

## Типичные ошибки

- Создавать клиент в каждом обработчике.
- Превратить CancelledError в успешный результат или retry.
- Держать транзакцию до конца сетевого вызова.
- Использовать sleep как доказательство порядка двух событий.

## Хорошие ответы

Lifespan владеет клиентом. Spy провайдера может проверить, что контекст чтения уже закрыт. Таймаут сообщает об истечении нашего срока, внешняя отмена сообщает, что вызывающий код прекращает ожидание.

Результат `async with` имеет async-метод `ask(actor, question)`. Внутри `repository.read(actor)` доступна неизменяемая строка context. Скопируй её как значение и покинь async context, затем вызови `client.generate(context, question)` с общим timeout. Возвращай `Outcome("completed", text)` или `Outcome("timeout")`. Например, контекст «правила» и вопрос «срок» дают текст fake «правила:срок». Любая внешняя отмена и неожиданные ошибки пропускаются. Срок ограничивает вызов клиента, а очистка ресурса одного вызова принадлежит клиенту.

Run использует две последовательные операции одного клиента. Check координируется через Event, проверяет одно закрытие, отмену, timeout, ошибку setup и отсутствие открытой транзакции на длительном ожидании.
