# Usage, цена и бюджет

Два запроса печатают одинаковую длину ответа, но имеют разный объём истории и кэша. Чтобы прикинуть стоимость, нужно знать модель, тариф и категории расхода, а не только число запросов.

## Учебные цели

- Вычислить цену по input, output и cached usage.
- Сохранить неизвестную стоимость как unknown.
- Суммировать попытки и проверить границу бюджета.

## Теория

**Usage** — параметры расхода, которые сообщает провайдер. В нашей схеме total input включает **cached input**, входные токены с отдельной ставкой за повторное использование. Поэтому обычный вход равен `input - cached`. У выхода своя ставка. Одни API не передают все категории, а у моделей отличаются способы учёта. Прочитай схему перед расчётом.

Если тариф измеряется за `U` токенов, стоимость — `((I-C)×Pi + C×Pc + O×Po) / U`. Здесь I — весь вход, C — кэшированная часть, O — выход, P — ставки соответствующих типов. Проверка `0 ≤ C ≤ I` защищает от отрицательного некэшированного расхода. Для учебного тарифного объекта ставки задаются `Decimal` из строк. Это позволяет складывать десятичные ставки без лишней двоичной ошибки. Округлять каждый промежуточный токен не нужно. Правило округления счёта задаёт биллинг.

**Estimated cost** — оценка по известным токенам или прогнозу запроса и тарифу. **Actual cost** — списание, подтверждённое поставщиком. Может быть неизвестная цена, отсутствующее значение usage или попытка без ответа. Тогда ноль выдаёт ложную уверенность. На весь запрос суммируй расход всех известных попыток. Если хотя бы одна неизвестна, итоговая фактическая сумма неизвестна. Можно показывать отдельно известный минимум с явной подписью. У модели есть собственные limits, capabilities и измеренное качество. Выбор модели сравнивает задачу, ограничения входа/выхода, latency и стоимость по датированному каталогу.

## Модель понимания

У синтетического тарифа цена за 1000 токенов: 0,40 за input, 0,10 за cached, 0,80 за output. Для 120 входных, из них 20 cached, и 10 выходных числитель равен 40 + 2 + 8 = 50. Цена — 0,05. Вычисление сообщает оценку даже при известном usage, потому что реальные комиссии и округление счёта могут отличаться.

## Что нужно знать на Junior

Запиши model, revision, дату и quantity unit рядом с оценкой. Для предзапросного бюджета резервируй предельное потребление на известную стратегию попыток. После запроса сравни расчёт с измеренным usage. При неизвестной цене приложение может остановить платный сценарий, но ни шаблон, ни модель не должны самостоятельно менять предел.

## Примеры кода

Сравним два синтетических запроса по одной ставке за 100 единиц.
```python
from decimal import Decimal

def projection(quantity, rate):
    return Decimal(quantity) * Decimal(rate) / 100

assert projection(30, "0.23") == Decimal("0.069")
assert projection(0, "0.23") == 0
assert projection(1, "0.10") * 3 == Decimal("0.003")
print(projection(30, "0.23"))
```
Вывод — 0,069. Ставка из строки имеет ровно два разряда. Пример считает одну категорию, а задача добавляет кэш, выход и несколько попыток.

## Типичные ошибки

- Считать тариф за миллион токенов как цену за тысячу.
- Добавлять кэшированные токены поверх общего входа.
- Замещать missing usage нулём.
- Игнорировать второй вызов и переносить старый тариф на другую модель.

## Хорошие ответы

Нужны модель, датированный тариф, объёмы и единицы. Неполные сведения обозначаются явно. Бюджет попыток защищает от неожиданного суммарного расхода и ожидания.

## Критерии хорошего ответа

Покажи формулу с единицами и учти кэш как часть входа. Назови, что будет с неизвестной попыткой, и отдели учебные цены от реальных.

## Задача

Реализуй `estimate(price, attempts, budget) -> Estimate`. `Price` и `Usage` зафиксированы в contracts. Ставки — конечные неотрицательные Decimal, `unit` — положительный целый. Budget — конечный неотрицательный Decimal. Каждый известный count — неотрицательный int, cached не превосходит input. Некорректные числа вызывают `ValueError`. Отсутствие цены или любой из величин usage для попытки даёт `Estimate("unknown", None, revision)`. У неизвестной цены revision отсутствует. Пустой список означает ноль отправок при известном тарифе. Для валидных данных сложи точные десятичные цены и верни `within` при `total <= budget`, иначе `over`.

Например, цена 0,8 за 100 единиц и 25 выходных токенов стоят 0,2. Run проверяет синтетический одинарный вызов. Check использует другие единицы, нулевой риск, повторные attempts и повреждённые входы.

## Шпаргалка
