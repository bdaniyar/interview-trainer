## Теория

### Что это

Монолит — приложение, которое выпускается и разворачивается как одна единица. Внутри могут быть хорошо разделённые модули; наличие одной БД или одного процесса само по себе не описывает качество архитектуры.

### Как работает

В booking monolith один HTTP endpoint вызывает BookingService, тот резервирует inventory и через LocalNotificationAdapter записывает notification в той же PostgreSQL-транзакции. Исключение до COMMIT откатывает обе части. Нет сетевого вызова между модулями, поэтому эта граница может быть локальной и атомарной.

Один deployable можно запустить в нескольких instances за load balancer, если состояние запросов хранится устойчиво и нет process-local источника истины. Масштабирование целого приложения проще операционно, но нельзя независимо выпустить только notification module или дать ему иной runtime без изменения границы.

Общий процесс и release связывают отказ и deployment. Однако раннее разделение на сервисы добавляет сеть, контракты, outbox и частичные ошибки. Для маленького workflow полезно сначала держать понятные module API и измерять конкретный bottleneck.

### Важный нюанс / ограничение

Монолит не обязан быть big ball of mud и не запрещает horizontal scaling. В этом проекте он сохраняет booking и notification одной локальной транзакцией.

## Модель понимания

Проследите один booking от HTTP до durable state. Подпишите владельца данных и каждый COMMIT. На сетевой границе отдельно отметьте timeout, возможный повтор и наблюдаемое состояние receiver.

## Что нужно знать на Junior

### Обязательно

Один deployable может содержать несколько бизнес-модулей и иметь несколько replicas. Общая транзакция возможна, когда операции используют одно соединение с БД. Общий процесс упрощает локальные вызовы, но связывает отказ и выпуск модулей.

## Типичные ошибки

Считать любую зависимость модулей поводом выделить сервис — добавить сеть до появления необходимости. Назвать два отдельных COMMIT одной транзакцией — потерять атомарность. Хранить единственный результат запроса в памяти replica — осложнить безопасный горизонтальный запуск.

## Шпаргалка

Deployable — единица выпуска, модуль — граница ответственности, transaction — граница атомарности. Эти понятия не совпадают автоматически. В local adapter booking и notification используют одно соединение; исключение откатывает обе записи.
