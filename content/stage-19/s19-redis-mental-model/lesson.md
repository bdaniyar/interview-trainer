# Redis mental model

## Учебные цели

Объяснить Redis как отдельный сервер структур данных; различать хранение в RAM, persistence и роль основной БД.

## Теория

### Что это

Redis — отдельный сервер, который хранит ключи и структуры данных преимущественно в оперативной памяти. Приложение отправляет ему команды по сети. Это не обычный dict внутри Python-процесса: к одному Redis могут обращаться несколько экземпляров backend.

### Зачем нужно

Часто запрашиваемый результат можно временно сохранить по ключу и читать без повторного тяжёлого запроса к основной БД. Redis также применяют для счётчиков и временного состояния; у каждого сценария свои требования к потере данных.

### Как работает

Команда SET связывает ключ со строковым значением, GET читает его. Структуры данных обрабатываются командами на сервере. Это уменьшает число действий, которые приложение выполняет отдельно, но не устраняет сетевую задержку, лимит памяти и необходимость обработки отказов.

Persistence — сохранение данных на диск для восстановления после перезапуска. Здесь optional означает, что этот механизм можно включить или отключить; это не Python-аннотация Optional.

- RDB записывает снимок набора данных в определённые моменты. При восстановлении из снимка можно потерять изменения после него.
- AOF записывает операции изменения в журнал. Политика fsync определяет частоту принудительной синхронизации с диском и компромисс между производительностью и возможной потерей последних записей. При everysec в неблагоприятном случае можно потерять примерно последнюю секунду изменений.
- Без RDB и AOF данные существуют в памяти; после потери процесса нельзя рассчитывать на восстановление из локальной persistence. Репликация и persistence решают разные задачи и не заменяют резервное копирование.

### Важный нюанс / ограничение

Redis может быть основным хранилищем в специально спроектированной системе, но добавление его как кэша не переносит туда источник истины. Для кэша профилей основная БД остаётся источником данных. Нельзя обещать сохранность платежей, просто сказав «Redis быстрый»: нужны требования к durability, настройка persistence, резервное копирование и сценарий восстановления.

## Примеры кода

Команды для redis-cli в тестовой базе; ключи начинаются с tutorial:.

```redis
SET tutorial:profile:7 "Aida"
GET tutorial:profile:7
GET tutorial:missing
```

Ожидаемые ответы по порядку:

```text
OK
"Aida"
(nil)
```

### Разбор выполнения

SET сохраняет строку под конкретным ключом. GET того же ключа возвращает Aida. Для отсутствующего ключа Redis возвращает nil: значение не найдено. Это не пустая строка. Эти команды сами по себе не говорят, восстановится ли запись после restart: это зависит от настройки persistence.

## Типичные ошибки

Ошибка: утверждать «данные в RAM, значит Redis вообще не умеет сохранять их на диск». Исправление: различать рабочее размещение данных и RDB/AOF. Противоположная ошибка — считать, что один включённый persistence-режим гарантирует нулевую потерю при любом сбое: нужно учитывать fsync, снимки и восстановление.

### Вопрос 2

GET вернул nil. Может ли backend восстановить кэш профиля из основной БД? Объясни, почему это допустимо для кэша, но не универсально для всех Redis-данных.

<details><summary>Показать ответ</summary>

Для кэша профиля это допустимо, если основная БД хранит исходные данные: отсутствие ключа ведёт к повторному чтению и заполнению кэша. Для единственной записи важного состояния такого источника восстановления может не быть.

</details>

### Вопрос 3

Почему два экземпляра backend видят общий Redis, но не общий Python dict?

<details><summary>Показать ответ</summary>

Оба backend обращаются по сети к одному серверу Redis. Обычный dict находится в памяти конкретного Python-процесса и сам по себе не разделяется с другим процессом.

</details>

## Вопросы с собеседований

### Основной вопрос

Как Redis хранит данные и что означает optional persistence?

### Дополнительный вопрос

Чем RDB отличается от AOF?

## Хорошие ответы

### Короткий ответ

Redis — отдельный сервер структур данных, который обслуживает операции преимущественно из оперативной памяти.

### Нормальный ответ уровня Junior

Redis — отдельный сервер структур данных, который обслуживает операции преимущественно из оперативной памяти. При этом можно настроить сохранение на диск: RDB делает снимки, AOF записывает изменения. Допустимая потеря зависит от режима и частоты синхронизации. Если Redis используется как кэш, источником истины обычно остаётся основная БД, из которой можно восстановить отсутствующее значение.

### Углубление / дополнительный вопрос

RDB хранит снимок состояния, поэтому изменения после снимка могут отсутствовать при восстановлении. AOF хранит журнал операций изменения; частота fsync определяет компромисс производительности и окна возможной потери. Наличие любого режима требует проверки восстановления и не отменяет резервное копирование.

## Критерии хорошего ответа

Обязательные понятия:

- Redis — сетевой сервер структур данных в RAM.
- RDB сохраняет снимки, AOF — журнал изменений.
- Политика persistence определяет окно возможной потери.
- Для кэша источник истины остаётся в основной БД.

Ошибочные утверждения кандидата:

- «Optional persistence в Redis означает Python-тип T | None.»
- «Redis никогда не пишет данные на диск.»

Ошибки при написании кода разбираются отдельно в разделе «Типичные ошибки».

## Задача

### Выбрать требования к хранению

Для двух случаев запиши допустимость потери и способ восстановления: (а) кэш отображаемого имени, (б) единственная запись о полученном платеже. Для кэша опиши восстановление из основной БД. Для платежа назови, почему «хранить в памяти без persistence» не удовлетворяет требованию сохранности.

<details><summary>Показать ответ</summary>

Для кэша имя можно восстановить из основной БД. Единственная запись о платеже требует заранее определённой сохранности и восстановления; память без persistence этого не обеспечивает. RDB — снимок, AOF — журнал изменений, fsync влияет на окно потери. Отсутствующий ключ и пустая строка — разные состояния.

</details>

В этом уроке нет автоматической coding-задачи.
