# Диагностика backend-основ на AI-сценарии

Ты открываешь историю в сервисе учебных материалов и задаёшь вопрос по ней. Даже с медленным внешним ответом API должен сначала решить, имеет ли этот пользователь право читать беседу. Ни одна из этих проверок не требует реальной модели. Урок проверяет точность backend-навыков на искусственных данных.

## Учебные цели

- Проверить DTO, внедрение зависимости, доступ к объекту и асинхронное ожидание.
- Различить ошибки 422, 404 и 504 и показать, какой шаг прерывается.
- Доказать тестом, что чужой запрос не дошёл к провайдеру и отмена освобождает ресурсы.

## Теория

**DTO** (Data Transfer Object) описывает данные на границе. Pydantic проверяет, что вход содержит строку вопроса и идентификатор беседы. Объект DTO ещё ничего не говорит о владельце. **Dependency injection** передаёт обработчику готовый объект или функцию из внешней конфигурации. В тесте вместо реального клиента это объект с предсказуемым поведением. Подмена нужна, чтобы увидеть сам факт обращения и проверить порядок.

Авторизация по объекту сравнивает удостоверенного пользователя с владельцем конкретного объекта. Представь идентификатор 17 из URL. Значение может существовать, но быть чужим. Оба случая возвращают 404, если продукт скрывает существование чужих объектов. В этом упражнении actor приходит из доверенной зависимости, одинаковой для всех запросов одного тестового приложения. В реальном сервисе зависимость проверяла бы сессию или токен. Тело запроса не задаёт actor.

**Timeout** ограничивает длительность обещанного клиенту ожидания. `asyncio.timeout` отменяет блок при превышении срока, затем поднимает `TimeoutError` за пределами блока. Внешняя отмена задачи передаётся как `CancelledError`. Освобождение тестового счётчика или соединения удобно делать в `finally`. В проекте с PostgreSQL прочитай владельца в короткой операции и завершай транзакцию до долгого ожидания. Пока модель отвечает, соединение пригодится другим запросам.

## Модель понимания

Запрос проходит четыре двери: форма → владелец → ожидание → ответ. Раздели наблюдения. При 422 функция работы с беседой не получила валидный DTO. При 404 счётчик провайдера равен нулю. При 504 провайдер был вызван, но бюджет ожидания исчерпан. Так тест может объяснить причину, даже если все три результата одинаково неприятны пользователю.

## Что нужно знать на Junior

В тесте FastAPI TestClient даёт HTTP-смысл ошибок без порта и сети. Он создаёт контекст приложения, если использовать `with`. Для отмены самого приложения внутри event loop подойдёт `httpx.ASGITransport`, прямой тест корутины или Event, который отмечает момент входа в зависимость. `sleep(1)` ради синхронизации в тесте иногда проходит раньше нужного момента и тратит время.

Если трудно прочитать fixture, повтори [тестирование FastAPI](/?lesson=s14-testing-fastapi) и [timeout и cancellation](/?lesson=s08-timeouts). Для ошибок авторизации найди в Backend треке темы dependency injection и object-level authorization. Возвращайся к диагностике с одним новым тестом, который ты можешь объяснить без подсказки.

## Примеры кода

Корутина выполняет подготовку ответа. Вход в блок измерим, освобождение ресурса видно по счётчику. Локальная модель заменена синхронизируемым ожиданием.

```python
import asyncio

async def probe(wait: bool, budget: float) -> str:
    active = [True]
    async def operation():
        try:
            if wait:
                await asyncio.Event().wait()
            return "готово"
        finally:
            active.pop()
    try:
        async with asyncio.timeout(budget):
            return await operation()
    except TimeoutError:
        return "504: время истекло"
    finally:
        assert not active

async def demo():
    assert await probe(False, 1) == "готово"
    assert await probe(True, 0) == "504: время истекло"
    task = asyncio.create_task(probe(True, 60))
    await asyncio.sleep(0)  # Передаём управление задаче до её первого ожидания.
    task.cancel()
    try:
        await task
    except asyncio.CancelledError:
        print("отмена дошла до вызывающего кода")
    else:
        raise AssertionError("cancellation was swallowed")

asyncio.run(demo())
```

Бюджет 0 срабатывает на первом ожидании и не требует секундного сна. Вывод подтверждает, что внешняя отмена не скрыта. Этот пример не измеряет поведение удалённого HTTP-сервиса. После timeout он мог уже начать работу.

## Типичные ошибки

- Сначала звать модель, потом проверять owner. Даже если HTTP вернёт 404, внешняя сторона уже получила данные.
- Хранить историю текущей беседы в одном изменяемом списке модуля. Параллельные запросы изменяют одну коллекцию.
- Возвращать «готово» из широко обработанного исключения. Клиент не различит отсутствие результата и успешную генерацию.
- Полагаться на время сна теста. Сигнал `Event` даёт наблюдаемую точку отмены.

## Хорошие ответы

DTO не знает, какая запись принадлежит удостоверенному пользователю. Timeout задаётся локальной политикой и возвращает 504 при истечении срока. Отмена вызывающей задачи распространяется после cleanup. Долгоживущий клиент хранит конфигурацию и управляет соединениями. Содержание вопроса и история относятся к конкретному запросу.

## Критерии хорошего ответа

Покажи отдельные тесты на порядок авторизации, ограничение ожидания и освобождение ресурса. Объясни, почему счётчик провайдера и тип исключения различают сценарии. Если один из тестов пока не получается, выбери конкретную тему в Backend и вернись с отдельной проверкой.

## Задача

Реализуй `create_app(actor, owners, provider, timeout)` в `main.py`. Это фабрика ASGI-приложения. `owners` сопоставляет положительный `conversation_id` с actor. `provider.generate(question, conversation_id)` — async-метод, возвращает строку. В request DTO запрети дополнительные поля, убери внешние пробелы, разреши от 1 до 240 символов и положительный ID. В response DTO верни `conversation_id` и `text`. Например, для владельца «ana» и вопроса «Статус?» пример даёт `{"conversation_id": 17, "text": "Ответ на Статус?"}`.

Внедри provider с `Depends`. Проверь владельца раньше generate, поставь локальный timeout, преобразуй только его в 504. Внешняя отмена должна дойти до вызывающего кода. Сам провайдер владеет своими ресурсами и освобождает их. Режим Run запускает ASGI TestClient с публичным примером. В авторских проверках есть отказ ввода, запрет вызова, параллельность, timeout и внешняя отмена. Это диагностика для самопроверки.

Для копии запроса с чужим ID проверяй 404 и отсутствие обращения к провайдеру. При задержке используй бюджет. При внешней отмене освободи ресурс, затем продолжи распространение отмены.
