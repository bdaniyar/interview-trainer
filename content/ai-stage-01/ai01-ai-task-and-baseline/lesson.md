# Как поставить проверяемую AI-задачу

Помощник бронирований отвечает быстро и уверенно. В журнале 200, а гость получил имя другого клиента. Сформулируем такую проверку, в которой красивый ответ не затмит нарушение доступа.

## Учебные цели

- Задать границы задачи и базовый способ её решать.
- Разделить HTTP, фактическую точность, основание и права.
- Собрать рубрику и посчитать проверяемые свойства ответа.

## Теория

У задачи есть наблюдаемый вход, разрешённые данные, выход и критерий для отказа. Для номера или даты брони подойдёт чтение из собственной базы с шаблоном. Для пересказа длинной политики можно сравнить шаблон, поиск и генерацию на одних входах. **Baseline** — исходный способ решения, относительно которого измеряют изменение. Простой baseline выявляет, приносит ли модель пользу сверх обычного backend.

**Детерминированная** функция выдаёт одинаковый результат на одинаковом входе и состоянии. У вероятностной генерации один смысл может получить несколько корректных формулировок. Сравнивать байты полезно для кода статуса, а пересказ оценивай по фактам. **Галлюцинация** в этом уроке — выдуманное или ошибочное утверждение. **Grounded**, то есть обоснованный ответ, имеет проверяемую опору в разрешённой записи. Даже корректная дата без ссылки на доступную запись может провалить требование обоснования.

Представь три счётчика. Точность проверяет, что 12 мая совпадает с фактом. Опора проверяет, что прочитанная карточка подтверждает дату. Доступ проверяет владельца и разрешение. Сведения другого владельца проваливают всю проверку независимо от первых двух счётчиков. Право на чтение вычисляй до вызова модели и проверяй при выдаче результата. HTTP 200 сообщает о доставке, а не о корректности текста.

## Модель понимания

Зафиксируй snapshot разрешённых карточек и нескольких соседних пользователей. Для неоднозначного ID успехом может быть уточняющий вопрос. Сравни baseline и LLM на том же наборе, показывая отдельные ошибки. Фраза «не нашёл подтверждения» может быть корректной при отсутствии записи, даже если ожидаемый текст меняется.

## Что нужно знать на Junior

Критерий приёмки проверяют на каждом failure case. Если метрика среднего качества растёт, а один ответ выдаёт чужую бронь, версия не проходит gate доступа. Субъективную ясность и обоснованность разметки обсуждает человек.

## Примеры кода

```python
def mismatches(asserted, known):
    return sorted(name for name, value in asserted.items() if known.get(name) != value)

print(mismatches({"nights": 2, "floor": 4}, {"nights": 2, "floor": 3}))
assert mismatches({"nights": 2}, {"nights": 2}) == []
assert mismatches({"currency": "EUR"}, {}) == ["currency"]
```

Вывод `['floor']`. Пример сравнивает уже выделенные факты. Он не определяет факты из свободного текста и не проверяет владельца.

## Типичные ошибки

- Принимать хорошую формулировку за доказательство.
- Смешивать нарушение доступа с обычными ошибками поля.
- Менять эталон после того, как увидел ответ новой версии.

## Вопросы с собеседований

1. Зачем baseline при оценке LLM?
2. Может ли точный ответ получить отказ?

## Хорошие ответы

**Зачем baseline при оценке LLM?**

Возьми шаблон или поиск и один и тот же набор случаев. Сравни качество, доступ и стоимость отдельно. Она блокирует выпуск даже при улучшении точности.

**Может ли точный ответ получить отказ?**

Совпадение утверждений с БД не доказывает правомерность чтения. В приложении до передачи и выдачи данных.

## Критерии хорошего ответа

Укажи запись, подтверждающую факт, кто может её читать и что считать корректным уточнением. Для спорных случаев запиши причину своего решения.

## Задача

Открой восемь синтетических ответов в `fixtures.py` и вручную оцени точность, опору и владельца. Запиши в коротком README область применения, baseline и один спорный пример. Затем реализуй `score(factual, grounded, authorized, ambiguous=False)`, получающий четыре явных bool и возвращающий `pass`, `clarify` или `fail`. Например, ложный authorized всегда даёт fail. При известном нарушении фактов или основания возвращай fail, а при всех трёх истинах и ambiguous — clarify. Иначе pass. Отклоняй небулевы значения. Run сверяет один открытый вариант, дополнительные авторские проверки исполняются отдельно. Твой README оценивается по рубрике.
