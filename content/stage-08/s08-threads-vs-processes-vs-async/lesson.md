# Threads vs processes vs async

## Учебные цели

Выбрать механизм под нагрузку и ограничить число одновременных запросов через Semaphore.

## Теория

### Что это

Async, threads и processes — разные способы организовать работу. Выбор начинается с того, что занимает время: ожидание I/O, синхронная библиотека или вычисление. Долговечность фонового задания — отдельное требование.

### Зачем нужно

Тысяча одновременно начатых HTTP-запросов может перегрузить удалённый сервис, даже если loop остаётся свободен. Конкурентность требует ограничения ресурсов, а не только запуска gather.

### Как работает

| Работа | Подход | Причина |
| --- | --- | --- |
| Много сетевых ожиданий с async API | Async-клиент и Task | Ожидания уступают loop |
| Синхронная I/O-библиотека | Ограниченный thread pool | Блокировка вынесена из loop |
| Тяжёлые чистые Python-вычисления | Process pool или worker | Отдельные процессы могут использовать разные ядра |
| Задание обязано пережить restart сервера | Очередь и worker с хранением состояния | Task в памяти процесса не даёт долговечности |

Для ограничения async-запросов используется `asyncio.Semaphore(limit)`: счётчик свободных мест. `async with semaphore` ожидает место перед телом и возвращает его при выходе, включая выход по ошибке. Если limit=2, не более двух участников одновременно находятся в защищённом участке. Семафор должен быть общий для всей группы.

### Важный нюанс / ограничение

Semaphore ограничивает активный участок, но gather всё ещё создаёт работу для всего входного списка. Для огромного потока данных нужна очередь ограниченного размера и фиксированное число обработчиков; здесь вход небольшой. Семафор не задаёт число запросов в секунду и не делает блокирующую функцию асинхронной.

## Модель понимания

Механизм выбирается по характеру ожиданий и вычислений.

## Что нужно знать на Junior

### Обязательно

- Механизм выбирается по характеру ожиданий и вычислений.
- Один общий Semaphore ограничивает активные участки группы.
- Порядок результата gather сохраняется и с Semaphore.
- Долговечность задания требует отдельного хранения и обработки.

## Примеры кода

```python
import asyncio

async def main():
    gate = asyncio.Semaphore(1)
    active = 0
    peak = 0

    async def send(label):
        nonlocal active, peak
        async with gate:
            active += 1
            peak = max(peak, active)
            try:
                await asyncio.sleep(0)
                return label.upper()
            finally:
                active -= 1

    result = await asyncio.gather(send("a"), send("b"))
    print(result, peak)

asyncio.run(main())
```

### Разбор выполнения

Первый участник получает единственное место, второй ждёт. Даже когда первый уступил на sleep(0), место всё ещё занято. После его выхода второй входит. Печатается ['A', 'B'] 1. С лимитом 2 оба смогут войти до завершения первого и peak станет 2.

## Типичные ошибки

Неправильно создавать новый Semaphore(2) внутри каждого send: у каждого вызова получится собственный счётчик, общей границы не будет. Исправление: один объект на группу. Для тяжёлого расчёта нельзя выбирать async только из-за большого числа запросов: блокировка CPU останется.

## Хорошие ответы

### Короткий ответ

Для множества сетевых ожиданий с async API подходит asyncio.

### Нормальный ответ уровня Junior

Для множества сетевых ожиданий с async API подходит asyncio. Синхронный I/O можно выполнять в ограниченном пуле потоков. Для тяжёлого чистого Python-кода в обычной CPython с GIL подходят отдельные процессы, с учётом передачи данных и затрат запуска. Если задание должно пережить перезапуск, нужна система очереди и worker. Количество одновременных операций в любом случае ограничивают по ресурсам.

### Углубление / дополнительный вопрос

Semaphore считает одновременно занятые места. Если запросы очень короткие, за секунду через два места могут пройти сотни операций. Для ограничения частоты нужен отдельный алгоритм rate limiting.

## Задача

### Ограничить число активных вызовов

Реализуй `async def map_limited(function, values, limit)`. function — async-функция одного аргумента. Выполни её для каждого значения, допуская не более limit одновременных вызовов, и верни результаты в порядке values.

Пример: функция удвоения, `[3, 1, 2]`, limit=2 дают `[6, 2, 4]`, а пик активных вызовов не превышает 2. Пустой вход при положительном limit даёт `[]`. При limit <= 0 подними ValueError, включая пустой вход. Ошибки function передавай наружу. Общий Semaphore, async with и gather уже объяснены выше.
