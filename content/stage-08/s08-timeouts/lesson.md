# Timeouts

## Учебные цели

Ограничить длительность ожидания через asyncio.timeout и отличать истечение срока от ошибки операции.

## Теория

### Что это

Timeout — ограничение времени ожидания. `asyncio.timeout(seconds)` задаёт срок для блока async-кода. Если блок не успел закончиться, текущая задача получает запрос отмены, а снаружи контекстного менеджера возникает `TimeoutError`.

### Зачем нужно

Без ограничения один зависший внешний сервис может удерживать обработчик запроса слишком долго. Срок позволяет вернуть понятную ошибку или выбрать запасной сценарий.

### Как работает

`async with` — вход и выход из контекста, которые могут содержать await. Здесь контекст устанавливает таймер. При нормальном завершении таймер снимается. При истечении срока происходит отмена ожидаемой работы; её finally выполняет очистку. Менеджер преобразует вызванный им CancelledError в TimeoutError на выходе. Подробности отмены — в следующем уроке.

Перехватывай TimeoutError вокруг всего `async with`, если хочешь обработать истечение срока. Внутри блока преобразования ещё не произошло.

### Важный нюанс / ограничение

Это кооперативное ограничение, а не принудительная остановка потока. Если код блокирует loop или подавляет отмену, завершение может задержаться. Значение 0 или отрицательный срок означает истечение на ближайшем шаге loop; не используй такие сроки для проверки скорости. Для клиента HTTP дополнительно настраивают его сетевые таймауты.

## Модель понимания

Срок ограничивает блок ожидания, а не скорость вычисления.

## Что нужно знать на Junior

### Обязательно

- Срок ограничивает блок ожидания, а не скорость вычисления.
- TimeoutError обрабатывается снаружи async with.
- Очистка finally выполняется во время отмены.

## Примеры кода

```python
import asyncio

async def slow_read(log):
    try:
        await asyncio.sleep(10)
        return "ready"
    finally:
        log.append("closed")

async def main():
    log = []
    try:
        async with asyncio.timeout(0.01):
            await slow_read(log)
    except TimeoutError:
        print("deadline")
    print(log)

asyncio.run(main())
```

### Разбор выполнения

После истечения срока slow_read выходит через finally, добавляя closed. Снаружи контекста печатается deadline, затем ['closed']. Нормальный return "ready" не достигается. Здесь нет требования закончить ровно за 0.01 секунды.

## Типичные ошибки

Неправильно ловить TimeoutError только внутри async with: менеджер создаёт его при выходе. Исправление — try вокруг контекста. Ещё одна ошибка: использовать timeout как защиту от time.sleep внутри loop; заблокированный loop не сможет вовремя обработать свой таймер.

## Практика

1. Замени задержку slow_read на 0, а срок на 1. Будет ли deadline? Ответ: нет, но finally всё равно добавит closed.
2. В slow_read вместо sleep подними ValueError. Какое исключение получит вызывающий код? Ответ: ValueError, а не TimeoutError.
3. Объясни, почему срок 100 мс не гарантирует ответ сервера строго через 100 мс.

## Вопросы с собеседований

### Основной вопрос

Как работает asyncio.timeout и где ловить TimeoutError?

### Дополнительный вопрос

Будет ли ValueError операции превращён в TimeoutError?

## Хорошие ответы

### Короткий ответ

Asyncio.timeout ограничивает блок ожидания.

### Нормальный ответ уровня Junior

Asyncio.timeout ограничивает блок ожидания. Когда срок истекает, он отменяет текущую задачу и на выходе из контекста преобразует свою отмену в TimeoutError. Поэтому обработчик TimeoutError ставится вокруг async with. Ожидаемая coroutine получает возможность выполнить finally. Это кооперативный механизм: он не способен вовремя сработать, пока синхронный код блокирует loop.

### Углубление / дополнительный вопрос

Нет. Контекст преобразует свою отмену из-за срока. Независимая ошибка операции передаётся как была; внешнюю отмену также нельзя считать обычным истечением срока.

## Критерии хорошего ответа

Обязательные понятия:

- Срок ограничивает блок ожидания, а не скорость вычисления.
- TimeoutError обрабатывается снаружи async with.
- Очистка finally выполняется во время отмены.

Ошибочные утверждения кандидата:

- «Timeout принудительно прерывает любой синхронный вызов точно в заданную миллисекунду.»

Ошибки при написании кода разбираются отдельно в разделе «Типичные ошибки».

## Задача

### Ожидание со сроком

Реализуй `async def await_with_timeout(awaitable, seconds)`. В Python 3.11+ используй контекст asyncio.timeout и верни результат ожидаемого объекта. TimeoutError, отмену извне и ошибки самой операции не подавляй.

Пример: ожидание `asyncio.sleep(0, result="ok")` со сроком 1 возвращает `"ok"`. Незавершённое ожидание при сроке 0 завершается TimeoutError. Если операция поднимает ValueError, передай его без подмены; finally ожидаемой coroutine должен выполниться при отмене.

## Шпаргалка

- Срок ограничивает блок ожидания, а не скорость вычисления.
- TimeoutError обрабатывается снаружи async with.
- Очистка finally выполняется во время отмены.
