# Sync, concurrency and parallelism

## Учебные цели

Различать последовательное выполнение, конкурентное ожидание и параллельные вычисления; читать временную схему без знания asyncio.

## Теория

### Что это

Sequential execution — последовательное выполнение: следующую операцию начинаем после завершения предыдущей. Concurrency — конкурентность: несколько операций уже начаты и продвигаются по очереди, пока другие ждут. Parallelism — параллелизм: несколько исполнителей действительно работают одновременно.

### Зачем нужно

Сервис ждёт цену от поставщика A две секунды, от B — три. Если запросы независимы, их ожидания можно перекрыть. Если запрос B требует результат A, начать его заранее нельзя.

### Как работает

Представь одного повара и два таймера. Повар запускает чайник, а пока вода греется, ставит хлеб в тостер. Он один, но два ожидания уже идут. Два повара, одновременно нарезающие овощи, — пример параллелизма.

```text
Время, с:        0     1     2     3     4     5
Последовательно A: [ожидание]
                B:             [   ожидание   ]
Конкурентно     A: [ожидание]
                B: [   ожидание   ]
```

В идеальной модели без накладных расходов последовательное время равно 2 + 3 = 5, конкурентное — max(2, 3) = 3 секунды. Это расчёт ожиданий, а не обещание точного времени в реальной сети.

I/O-bound — работа, в которой преобладает ожидание сети, диска или БД. CPU-bound — работа, где время уходит на вычисления процессора. Перекрыть ожидания не означает ускорить один цикл вычислений.

### Важный нюанс / ограничение

Конкурентность меняет возможный порядок завершения. Данные, от которых зависит следующий шаг, всё равно нужно дождаться. API для запуска конкурентных операций изучим после coroutine, event loop и Task.

## Модель понимания

Последовательные независимые ожидания складываются; конкурентные могут перекрываться.

## Что нужно знать на Junior

### Обязательно

- Последовательные независимые ожидания складываются; конкурентные могут перекрываться.
- Конкурентность возможна с одним исполнителем; параллелизм требует одновременного исполнения.
- Зависимость результатов ограничивает конкурентный запуск.

## Примеры кода

```python
waits = [2, 3]
sequential = 0
for delay in waits:
    sequential += delay
print(sequential)
print(max(waits))
```

### Разбор выполнения

Печатается 5, затем 3. Цикл складывает длительности двух независимых ожиданий. max выбирает момент завершения более долгого ожидания, если оба начались в момент 0. Никакие реальные запросы этот код не запускает.

## Типичные ошибки

Ошибка: считать, что конкурентное время всегда равно сумме, делённой на число задач. Для ожиданий 1 и 9 это дало бы 5, хотя второе ожидание закончится только на секунде 9. Исправление: нарисовать общую шкалу и найти самое позднее завершение.

## Практика

1. Для ожиданий 1, 4 и 2 секунды найди последовательное и идеальное конкурентное время. Ответ для самопроверки: 7 и 4.
2. B требует токен, полученный от A. Можно ли начать B в момент 0? Объясни зависимость.
3. Два чистых Python-цикла выполняются по очереди на одном исполнителе. Почему смена порядка не делает их параллельными?

## Вопросы с собеседований

### Основной вопрос

Чем конкурентность отличается от параллелизма?

### Дополнительный вопрос

Можно ли перекрыть любые две операции?

## Хорошие ответы

### Короткий ответ

При последовательном выполнении следующая операция начинается после предыдущей.

### Нормальный ответ уровня Junior

При последовательном выполнении следующая операция начинается после предыдущей. При конкурентном несколько операций находятся в работе и могут перекрывать ожидания, даже если исполнитель один. При параллельном несколько исполнителей работают одновременно. Например, два независимых сетевых ожидания по 2 и 3 секунды в идеале занимают около 3 секунд вместе. Это не ускоряет само вычисление на CPU.

### Углубление / дополнительный вопрос

Нет. Если вторая операция использует результат первой, эта зависимость задаёт порядок. Перекрывать можно независимые ожидания; накладные расходы и ограничения ресурсов учитываются отдельно.

## Критерии хорошего ответа

Обязательные понятия:

- Последовательные независимые ожидания складываются; конкурентные могут перекрываться.
- Конкурентность возможна с одним исполнителем; параллелизм требует одновременного исполнения.
- Зависимость результатов ограничивает конкурентный запуск.

Ошибочные утверждения кандидата:

- «Конкурентность всегда означает выполнение Python-кода на нескольких ядрах.»

Ошибки при написании кода разбираются отдельно в разделе «Типичные ошибки».

## Задача

### Сравнить время независимых ожиданий

В `main.py` реализуй `compare_waits(delays) -> tuple[int, int]`. На входе список неотрицательных целых секунд; верни `(последовательное_время, идеальное_конкурентное_время)`. Здесь мы моделируем ожидания, ничего не запускаем.

Пример: `compare_waits([2, 3]) == (5, 3)`. Пустой список даёт `(0, 0)`, `[0, 4, 4]` — `(8, 4)`. Отрицательная длительность вызывает `ValueError`. Входной список менять нельзя.

Достаточно обычного цикла, сложения и сравнения. Если в редакторе осталось прежнее задание, сохрани его код и добавь compare_waits ниже в том же main.py. Ранее написанные решения тоже продолжают проверяться; используемый в них API разбирается в 8.9.
