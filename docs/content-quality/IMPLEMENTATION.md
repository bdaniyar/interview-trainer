# Переработка качества обучения: фактическое покрытие

Работа выполнена в локальном checkout `bdaniyar/interview-trainer`, исходная ревизия `00c4dcf`. Публикация в GitHub не выполнялась.

## Архитектура и источник материалов

`curriculum.json` хранит taxonomy и implementation_slug; опубликованные metadata могут находиться в старых папках `async-python/` и `concurrency/`. `backend/app/content.py` читает эти папки напрямую. Slug определяет progress и сохранённые файлы; интервью использует `slug:index`. Поэтому переносов папок, переименований и перестановок вопросов нет. `course.json` — производный snapshot, он обновлён.

Полный bundle (`lesson.md`, `interview.json`, metadata, starter, solution, tests) теперь является источником авторского контента. После проверки metadata получает `content_source: curated`, `quality_revision`, `reviewed_on`. Отдельный `curation-policy.json` перечисляет только исторический долг: 279 ещё не переработанных опубликованных уроков. Новая публикация Stage 8+ без reviewed bundle не проходит validator. Список долга нельзя пополнять ради обхода проверки.

`populate_curriculum`, `personalize_examples`, `add_coding_tasks` и использующий его `add_backend_tasks` сохраняют существующие bundles по умолчанию. Защита находится и в функции записи coding task, а не только в цикле main. Явный `populate_curriculum --rewrite-legacy` касается только старых этапов 0–7; для текущей работы он не применялся. Также защищены инъекции add_practice_banks и запись enrich_curriculum; старый seed_content (включая --force) отключён, когда уже существует curriculum.json. Старый catalog задач Stage 8 удалён, чтобы не существовало второй устаревающей копии. `compact_dossier`, `fallback_dossier`, `dossier_for` запрещены для Stage 8+. Прямые вызовы Markdown/interview renderer читают reviewed bundle по стабильному ID либо завершаются ошибкой. Подстрочный подбор объяснений удалён; исторические объяснения до Stage 8 используют только точное совпадение.

Чтобы изменить reviewed-урок, редактируй весь комплект непосредственно в его опубликованной папке. Проверь предпосылки, результаты примеров, контракт задания и рубрики; увеличь quality_revision. После нового содержательного аудита legacy-урока пометь его curated и убери его ID из legacy_debt. Сохраняй ID, slug, порядок интервью, task_id и XP. Генераторы не являются средством перегенерации авторского текста.

## Завершённые группы

- Stage 8: все 12 уроков, включая находящиеся в `content/async-python`. Написаны объяснения механизма, воспроизводимые примеры, разбор вывода, конкретные практические вопросы, инструкции coding tasks и интервью. Последовательность: временные модели → coroutine → await → loop → Task → gather → timeout → cancellation → blocking I/O → resource lifecycle → async iteration → выбор исполнителя и лимит конкурентности.
- Stage 9: все три опубликованных урока 9.1–9.3 (`threads`, `processes`, `thread-pool`). Объяснены shared memory, составные гонки, общий lock, start/join, изоляция процессов, сериализация, spawn/__main__, Future и ограничения пула. Два planned-урока не публиковались.
- Stage 19: полностью переработан только 19.1 Redis mental model: сервер структур данных, RAM, RDB/AOF/fsync, возможная потеря данных и источник истины.

В 12 других уроках исправлены только неверные абзацы, возникшие из-за substring routing: 10.16, 12.6, 13.5, 13.10, 16.7, 18.4, 19.2, 22.9, 23.7, 29.2, 32.11, 32.22. Они не помечены curated: остальная теория, примеры, практика и interview ещё требуют переработки. В каждом абзаце добавлен источник и точная граница проверки.

## Задания и сохранённые решения

8.1 теперь предлагает `compare_waits(delays)`: обычная модель суммы и максимума с пустым входом, нулевыми/повторными ожиданиями и отрицательным значением. Task ID и XP сохранены. Hidden tests поддерживают прежнюю `run_blocking_calls` только у сохранённых файлов без compare_waits. Если новая функция присутствует, обязательны все новые проверки; ошибки не вызывают отката к старым тестам. Для старого редактора текст объясняет, как дописать новую функцию без удаления прежнего кода.

8.3 сохраняет `load_profile(client, user_id)`, но допускает решение последовательными await. Старый конкурентный вариант остаётся корректным. Проверяются новое объединённое значение, отсутствие мутации, роли, ID и ошибки клиента.

Инструкции всех 12 coding tasks Stage 8 согласованы со starter/solution/tests. Для 8.2–8.12 добавлены значимые проверки ошибок, очистки, пустых входов, исчерпания итератора, наличия общей границы конкурентности и сохранения порядка. Проверки конкурентности наблюдают состояние и сигналы, а не ускорение на конкретной машине. Учебные примеры используют другие имена и сценарии, а не выдают готовую функцию задания.

## Интервью

Для 16 reviewed-уроков переписаны оба вопроса, ответы Junior, follow-up и критерии. Сохранены позиции массива, level, tags, sets и priority. Неверные утверждения кандидата отделены от ошибок реализации и обязательных понятий.

У остальных 279 опубликованных уроков Stage 8+ выполнена только структурная миграция rubric: описания типичных ошибок перенесены в coding_mistakes, замечание о полноте ответа — в assessment_notes. Поля common_wrong_answers и red_flags оставлены пустыми до отдельного содержательного аудита; правильное описание ошибки больше не объявляется неправильным ответом. Поля expected answer и вопроса не переписывались массовыми шаблонами. Миграция идемпотентна. Старые Markdown-разделы этих уроков ещё могут содержать неудачные формулировки — это часть открытого долга.

## Проверки

- `python3 tools/validate_content.py --run-solutions --audit-dir docs/content-quality`: 406 записей taxonomy, 359 опубликованных уроков, 63 solution-комплекта проходят hidden tests.
- `python3 -m pytest`: backend, runner и content regression checks проходят. Изменение testpaths включает новые content checks в обычный запуск.
- Regression checks дважды запускают девять авторских скриптов в временной копии и сравнивают все байты content, включая Stage 1–7, metadata, интервью и задачи.
- Baseline до изменений фиксирует persistence keys, XP, позиции интервью и SHA-256 всех файлов Stage 1–7. Fixtures прежних решений 8.1/8.3 проходят текущие hidden tests. Проверки работают без доступа к истории Git.
- Все 15 основных Python-примеров reviewed-уроков запускаются отдельными скриптами; stdout совпадает с текстовым разбором, включая ProcessPoolExecutor под spawn. Сетевые демонстрации только компилируются: внешние HTTP-запросы не выполнялись.
- `python3 tools/export_course_snapshot.py`: обновлены metadata snapshot, ранние уроки не менялись.
- Frontend: lint, `npx tsc --noEmit --incremental false`, build проходят. Попутно исправлена обработка unknown JSON error payload и добавлены отсутствовавшие типы react-syntax-highlighter. Build сообщает существующее предупреждение о размере chunks.
- В браузере локального приложения проверен урок 8.1: новый текст Learn, временная схема, пример, инструкция задания, переключение Review и скрытие теории. Monaco показывает ранее сохранённый файл пользователя; его содержимое не заменялось. Save, Check, отметка теории и завершение интервью в пользовательской сессии не нажимались.
- Технические объяснения содержательно сверены с первичными источниками, указанными в самих уроках: Python 3.12, HTTPX, Redis, PostgreSQL, SQLAlchemy, pytest, Git, HTTP RFC и документация NGINX.

`--strict-quality` намеренно завершается ошибкой на оставшихся 279 уроках. Обычный validator проверяет всю старую структуру и делает новые editorial-проверки обязательными для curated-контента; исторический долг выводит явно и перечисляет в AUDIT.md/audit.json. Автоматические правила находят известные шаблоны, placeholders, дубли, нарушения Markdown, отсутствие конкретной практики/контракта задания, противоречия rubric и известные подмены тем. Они не доказывают смысловую корректность.
