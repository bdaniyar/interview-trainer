# Локальный SDK пример с явным opt-in

`live_example.py` запускается отдельным процессом и переиспользует проверенный `tools_roundtrip.py`. Создайте отдельное окружение Python 3.12 из `tools/ai_sdk_verify/requirements.txt` с `pip install --require-hashes`. Запускайте скрипт этим Python из каталога P3. Для примера достаточно SDK lock. Перед запуском проверьте версию модели, её максимальный контекст и действующие цены у провайдера.

```sh
python live_example.py --send-one-case --case lookup \
  --model "$BOOKING_DEMO_MODEL" --context-tokens "$BOOKING_DEMO_CONTEXT" \
  --input-usd-per-million "$BOOKING_DEMO_INPUT_RATE" \
  --output-usd-per-million "$BOOKING_DEMO_OUTPUT_RATE" --max-usd "$BOOKING_DEMO_BUDGET"
```

Ключ задаётся через `OPENAI_API_KEY` в локальном процессе. Запуск допускает один замороженный синтетический запрос `list` или `lookup`. SDK делает до двух HTTP-запросов без автоматических повторов, с максимумом 256 выходных токенов на запрос и общим дедлайном 12 секунд. Скрипт до сети оценивает верхнюю границу стоимости двух полных входных контекстов и двух выходов по указанным ставкам. Задайте достаточное для выбранной модели значение контекста и используйте лимит отдельного проекта у провайдера как внешнюю границу расходов. Локальный расчёт не является данными биллинга.

Оба разрешённых tool используют сервис P3 с фиксированным synthetic principal. В вывод попадают только режим, имя сценария, состояние, число вызовов и признак наличия финального текста. Не включайте отладочные HTTP-логи и не переносите ключ в Monaco, Runner или браузер. Live результаты храните отдельно от `data/evaluation.json`. Пример дополнительно проверен на локальный отказ без opt-in. Платные запросы в рамках R2 не выполнялись.
