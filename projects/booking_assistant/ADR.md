# Границы провайдера, доступа и истории

**Статус:** принято для P3, 2026-11-24.

## Провайдер

Ассистент зависит от `Provider.reply(Context, exchanges) -> Reply`. Адаптер переводит внешний формат в контракт и сообщает об известной недоступности как `ProviderUnavailable`. Правила обработки ID и бюджетов остаются в приложении. Scripted provider позволяет тестировать те же ветки без ключа и сети. FastAPI открывает и закрывает provider context через lifespan.

## Доступ к данным

Identity dependency выбирает principal из учебных fixtures. Tool registry принимает только известные имена и точные типы аргументов. Сервис авторизации использует отдельный индекс, проверяет пару tenant и subject, scope и отзыв разрешения, затем читает разрешённый payload. Отсутствие в индексе и запрет дают одну категорию. `propose_cancel` возвращает предложение после собственной проверки scope и не читает payload. В рабочем приложении PostgreSQL проверка и чтение должны разделять согласованную версию policy или выполняться через авторизованный запрос, чтобы учесть изменение права между операциями.

## История и конкуренция

Клиент предъявляет ID, приложение проверяет principal. Асинхронный claim устанавливается до первого await, освобождается в finally и относится к одному диалогу. В одном event loop этого достаточно для единственного активного turn на ID. Другие диалоги исполняются параллельно. История хранит только завершённые turns с полными tool exchanges и исходными call ID. Context budget выбирает целый хронологический суффикс и резервирует вывод перед вызовом провайдера. Для нескольких процессов потребуется общее хранилище и транзакционная координация на границе записи. Сетевой inference внутри DB-транзакции не удерживается.
