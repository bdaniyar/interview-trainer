# P1 · LLM Chat API

Учебный FastAPI-проект после AI3. Он отдаёт реальные HTTP-ответы и SSE поверх локального scripted provider. Используй Python 3.12 и зависимости из lock-файла. Для запуска и тестов модели, GPU и ключи не нужны.

```sh
cd projects/chat_api
uv venv --python 3.12
uv pip sync --python .venv/bin/python --require-hashes requirements.txt
.venv/bin/python -m pytest -q tests
.venv/bin/python -m uvicorn main:app --host 127.0.0.1 --port 8765
```

Первичную установку выполни через индекс пакетов или заранее наполненный кэш. С готовым кэшем добавь `--offline` к `uv pip sync`. Все тесты выполняются внутри процесса и блокируют сетевые подключения. Для ручного запуска нужны только локальные порты.

```sh
curl http://127.0.0.1:8765/chat \
  -H 'Content-Type: application/json' \
  -d '{"question":"Где конспект?"}'
curl -N http://127.0.0.1:8765/chat/stream \
  -H 'Content-Type: application/json' \
  -d '{"question":"Где конспект?"}'
```

В первом ответе `status=completed`, свой `request_id`, учебный текст, usage и версия синтетического расчёта. Пустой вопрос даёт 422 и безопасный статус `invalid_request`. Поток выдаёт кадры `delta`, затем один `terminal`, в котором проверяется статус результата. HTTP 200 говорит о начале потока.

## Устройство

- `contracts.py` хранит входной DTO, схему usage, типы генерации и событий, протокол провайдера.
- `providers.py` содержит локальный fake без общего request state. Подставь другой через `create_app(make_provider=...)`. FastAPI lifespan владеет клиентом, отдельные запросы владеют prompt и request ID.
- `main.py` задаёт HTTP-контракт, общий timeout, безопасное отображение ошибок, одну повторную попытку при точно известном отказе до обработки, SSE и расчёт цены. Если отдался хотя бы один фрагмент, поток заканчивается своим terminal исходом или отключением, без ярлыка успеха по HTTP.
- `tests/` проверяет FastAPI через TestClient и ASGITransport. Прямой ASGI-тест имитирует разрыв во время send и наблюдает cleanup. Сокеты запрещены отдельно. Синтетическая версия цены `synthetic-v1` оценивает сообщённый расход успешной попытки. Отсутствующий cached usage означает отсутствие полной оценки; реальная цена, планирование покупок и биллинг остаются за пределами P1.

| Проверь | Что наблюдать |
| --- | --- |
| Правильный и пустой запрос | Текст, уникальный ID, 422 до провайдера |
| Завершение без текста, refusal, incomplete | Тип исхода и пустой публичный текст |
| Недоступность и timeout | 503 или 504 и отсутствие сырых ошибок |
| 429/503 до обработки | Один bounded retry, обязательный Retry-After, остановка по deadline |
| Два разных одновременных запроса | Разные ID и совпадение каждого текста со своим вопросом |
| Stream, EOF и разрыв | Типизированный terminal или закрытие upstream, когда клиент ушёл |
| Usage | Кэш как подмножество input и versioned Decimal estimate |

Для самостоятельной проверки измени лимит вопроса на 300 символов, добавь кейсы границы 300/301 и выполни тесты. Или измени один fixture на неверный refusal и убедись, что тест падает до исправления.

Опциональный отдельный запуск реального SDK описан в [LIVE_PROVIDER.md](LIVE_PROVIDER.md). Стандартные команды проекта его не используют.
