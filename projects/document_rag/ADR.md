# ADR · каталог, evidence и telemetry

**Решение 2026-11-24.** Храним версии, ACL, embedding space и признаки поиска в одном PG17. P5 использует параметры SQL и scoped metadata, затем читает только payload выбранных записей. Модель и внешние документы не выбирают actor, scope, фильтры, SQL или адрес хранилища. Текст документа считается данными. Подставные claims отклоняются при проверке принадлежности и поддержки.

## Согласованность и защита

- Подготовка чанков и embeddings выполняется до открытия SQL-транзакции. Запись блокирует документ, вставляет целый набор чанков и атомарно меняет active pointer. Более ранний commit остаётся доступен при сбое. Revoke и delete сериализуются с загрузкой. Replay не дублирует активные rows.
- Retrieval использует tenant, scope, owner/grant, space, active version и tombstone. Payload отделён от проекции metadata. Scoped lookup в materialized CTE проверяет допустимость ключей, затем присоединяется к таблице текста. После rerank приложение перед контекстом проверяет и читает его заново.
- Перед выдачей все supplied keys сравниваются с одной свежей SQL-выборкой. Смена версии, tombstone, revoke и revoke→grant выявляются по epoch. Тест останавливает генератор, параллельно выполняет commit и убеждается в `stale_evidence` без claims. Гарантия относится к snapshot финальной проверки. Мутация после этого snapshot может произойти до получения ответа. Текст, уже переданный генератору до отзыва, невозможно забрать обратно. Здесь генератор локальный. Кэша результатов или embeddings в P5 нет, повторный ask читает актуальные данные. Tombstone ограничивает выдачу, физическая очистка истории остаётся задачей политики хранения.
- Фабрика FastAPI получает synthetic principal из серверной таблицы. Все интеграции используют отдельную БД без связи с learner SQLite. Runtime-роль доверена приложению и ограничена DML. В модели угроз доступ к её локальной строке подключения относится к администратору демо. Per-user RLS, подлинная аутентификация и внешнее сетевое размещение потребуют отдельного проектирования.
- OTel SDK с локальным ring exporter хранит последние 512 завершённых spans. Атрибуты ограничены по числу и длине. Полные вопросы, документы, векторы, приватные actor ID, credentials и исключения не отправляются. Жёсткие ошибки ставят `ERROR` и фиксированный outcome. [Пример реальных spans](data/redacted-trace.json).

## Таксономия

| Статус | HTTP и смысл |
| --- | --- |
| `answered`, `conflict`, `insufficient_evidence` | 200, с ответом только при проверенных claims. |
| `stale_evidence`, `version_conflict` | 409, изменился snapshot evidence или занят номер версии. |
| `invalid_input`, `context_budget` | 422, некорректный контракт или неподходящий бюджет. |
| `insufficient_scope` / `document_unavailable` | 403 за scope, 404 для чужого или отсутствующего ID. |
| `unsupported`, `invalid_answer`, `generation_error` | 502, неподдержанный claim, неверная форма или ошибка генерации. |
| `retrieval_error`, `storage_unavailable` | 503, безопасная категория ошибок при чтении или записи. |
| `deadline` | 504, предел ask/search. Отменённая корутина не возвращает цитаты. Уже начатый PostgreSQL read в worker thread ограничен отдельным statement timeout. |

UTF-8 context budget резервирует вывод, exact token counts зависят от реальной модели. Scripted проверка support подходит для ограниченного формата `Fact: topic = value`. Автор с правом ingest может внести ошибочный факт. Сервис проверяет его происхождение и совместимость с evidence, а достоверность самого документа зависит от владельца корпуса. Для произвольных документов потребовалась бы отдельная оценка смысла. Реальный model adapter, платный SDK эксперимент, Collector и удалённая платформа tracing в поставку не входят.
