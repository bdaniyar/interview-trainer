# Практика 11.14. Исчерпание пула и восстановление

Задание `py.pool.11.14.lifecycle-v1` проверяется локальным `check.sh`.

Два запроса FastAPI используют одну Engine с `pool_size=1` и
`max_overflow=0`. Приложение выдаёт сессию на запрос, но стартовый обработчик
оставляет соединение занятым. Исправьте жизненный цикл сессии в копии
`starter.py`. Сохраните фабрику `make_app(sessions, after_write)` и контракт
`POST /values/{number}`. Вызов `after_write(number)` делает момент ожидания
воспроизводимым.

1. Запустите `./check.sh`. Посмотрите, где проверка обнаруживает удержанное
   соединение.
2. Скопируйте `starter.py` в `answer.py`. Исправьте завершение транзакции при
   успехе и при `?fail=true`. Запустите `./check.sh answer.py`.
3. Объясните, почему увеличение размера пула лишь отложило бы ошибку.
   Сравните с `solution.py` после самостоятельной попытки.

При удерживаемом соединении второй HTTP-запрос должен получить 503. Первый
запрос записывает число и возвращает соединение. Ошибка 409 откатывает
вставку, после неё ещё один запрос проходит. Проверка опрашивает настоящий
PostgreSQL и сверяет занятые соединения SQLAlchemy. Параметры пула задаёт
тест.

Скрипт создаёт отдельный краткоживущий Compose-проект. PostgreSQL и Uvicorn
работают во внутренней сети без открытых хост-портов. Проект использует
синтетическую БД и удаляет свои ресурсы после проверки. Результат выводится
локально.
